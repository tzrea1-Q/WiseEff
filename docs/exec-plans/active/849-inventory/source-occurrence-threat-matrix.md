## Implementation contract

1. Add one immutable occurrence relation with Organization, Project, config-set, kind, stable instance, immutable file ID, and format-specific locator. DTS uses its genuine logical node; JSON uses a genuine configuration-instance identity and strict RFC 6901 pointer, never a fabricated DTS node or a dotted path.
2. Existing DTS Binding IDs and history references survive unchanged. Derive backfill only from proven stored source/file/config-set evidence. Missing, contradictory or multi-owner evidence blocks the migration with an actionable report; do not guess a file or use synthetic placeholders.
3. Expand first, compare old and new DTS resolution including replacement projection, then switch uniqueness/queries to Project + occurrence + Definition. Preserve the legacy logical-node projection until the full matrix passes. A JSON-only nullable-column cluster on Binding is forbidden.
4. Backfill before extending identity immutability; then enforce immutable occurrence/Binding ownership before enabling new writes. Observation and match identities/FKs must enforce the same occurrence, not only equal Definition IDs. Applied migrations are immutable.
5. Add a distinctly named occurrence resolver with explicit least-privilege grants; keep the existing three-text-argument resolver as the DTS compatibility projection. It must fail closed on ambiguity, never choose a first row across files/config-sets.
6. File/config revision pins remain in ProjectValue and source revisions. A new source revision must not mint another Binding. A changed file/instance/config-set is another occurrence, not a mutable identity update.
7. Reuse the canonical Binding, ProjectValue, pending draft, review, audit and protected-reference owners. JSON parsing/locator/writeback belongs to parameter-files; DTS stays in parameter-topology. No legacy writer or new publication bypass.
8. JSON accepts strict JSON only. Duplicate decoded keys, unsupported syntax, invalid escapes, nonfinite/unsafe numeric conversion, ambiguous or missing locators, array append/noncanonical indices and stale revisions fail before publication. Preserve exact scalar kinds, decimals, arrays, literal dotted/slashed/tilde keys and unrelated semantics. Any serialization change must appear in the review diff.
9. Candidate creation and pending drafts never change the active file, current value or config pointer. Submit freezes exact source/value/definition pins; the independently authorized review/apply revalidates all pins and atomically commits value/source metadata/history/workflow/audit. Prepared object failures leave old state readable.
10. Export reads the exact pinned source revision, not whichever file version is now active. Reimport proves equivalent typed values and locators. Unknown input enters existing observation/review flow and cannot invent a Catalog identity.
