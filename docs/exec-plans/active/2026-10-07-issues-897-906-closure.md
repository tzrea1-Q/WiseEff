## Starting point

All ten Issues already have their core canonical flow on `main`: the legacy reads/writes named in each Issue's "exact code evidence" are replaced, and most closure criteria have real PostgreSQL, HTTP, or 1440×900 browser tests. A read-only gap audit of every closure criterion (2026-10-07) found the remaining work below. Evidence for closing each Issue goes in its closing comment and the PRs that land the work.

## Decisions (made by the coordinator)

| ID | Decision | Rationale |
| --- | --- | --- |
| D1 | Give the production API LOGIN a narrow, tested capability for the canonical source path (source-occurrence row lock, current-Binding lock, source-pin lock, occurrence/pin append) instead of relying on owner connections. No broad Catalog DML, no SET ROLE to the migration owner, no removed locks. | Formal API LOGIN currently gets 42501 on these locks/writes (measured in `canonicalDebugging.integration.test.ts`), so #898/#902/#905/#906 writes would fail in deployment. |
| D2 | #897 Overlay authoring stays a legacy driver-schema feature: the UI fails closed with a clear message when a canonical Definition is chosen, instead of submitting it as a legacy `parameterSpecId`. Historical registry load failures must not break the canonical module page. | No canonical Overlay owner exists; a mirrored legacy spec would create a second model. |
| D3 | #900 canonical risk stays `unavailable` (no legacy risk reuse). Import-batch metrics remain: they count records of the still-active import workflow, not parameter model data. | Risk has no canonical owner; showing unavailable is the honest state. |
| D4 | #901 legacy submission/request history must be scoped server-side (owner-only for the personal view, authorized projects for reviewers); the unscoped global prefetch is removed. | Static audit shows organization-wide legacy reads without actor/project filters. |
| D5 | #899 stale `?binding=` links keep the generic "unavailable or no access" message; no archive guessing. | Avoids leaking identities of other projects. |
| D6 | #902 initialization keeps one independent target config set per source group. | Matches "target and source are independent". |
| D7 | #903 Catalog Definitions are platform-shared (read scope `all`); "visibility" is satisfied by shared Definitions + organization-isolated references and projections. | No organization-private Definitions exist in the Catalog model. |
| D8 | #904 run snapshots include a bounded canonical value history; missing context fails closed with a clear reason and old reports stay intact. | The Issue explicitly requires change history in analysis. |
| D9 | #905 Agent action supports set for DTS and JSON (tool metadata must say so); delete stays unsupported. | Matches the server contract. |
| D10 | #906 canonical member addition and DTS member removal stay explicitly disabled in the UI; draft #1024 is out of scope. | The Issue allows unsupported actions to be disabled with an explanation. |
