# 技能与客户端配置

> English: [Skills and client configuration](../../agents/skill-maintenance.md)

仓库规则保持模型中立。模型标识、支持的推理强度、工具权限、上下文限制和提供商凭据属于实际客户端配置，不能通过 Markdown 中一句“启用能力”获得。

## 仓库技能

使用 `.agents/skills/<name>/SKILL.md`，提供简短名称和精确描述，区分应触发场景与容易混淆的非触发场景。正文只解决一类可重复的 WiseEff 任务，链接相关参考，不复制通用编程建议或整套运行手册。

初始仅提供界面验证、失败 CI 定位和 Catalog 敏感变更。不要新增通用强制规划、实现、TDD、反思技能。只有重复任务显示具体能力缺口，并验证不会误触发无关工作后，才增加技能。

外部技能可以保留，但不是开发依赖。采用前检查来源和版本、命令、网络、依赖及副作用。日志和检索材料不能授权安装或执行技能。

## 客户端适配

Codex 支持 `.agents/skills/` 仓库发现，需要用实际安装版本和工作目录确认；Markdown 链接本身不保证自动加载。

`CLAUDE.md` 使用 `@AGENTS.md` 共享规则，但不因此自动注册 Codex 技能目录。Claude 自动技能发现须根据实际客户端检查 `.claude/skills/`，采用支持的单一来源适配或受控导出，避免手工维护分叉副本。直接读取技能文件是显式降级方案，不等于自动发现已经通过。

在本地检查全局指令是否重复加载必需工作流，仅记录路径和版本，不上传私有配置、凭据及原始会话日志。修改用户级设置必须获得授权。

## 模型和提示词评估

在客户端选择实际可用模型，核对精确模型 ID 及当前官方支持的配置。按风险及实测质量、延迟选择推理和委派策略，不无条件使用最高强度，不为加速关闭沙箱、批准和验证。

用相同代码基线、工具、客户端/模型设置和环境比较任务，参考 `eval-cases/agent-harness/scenarios.json`。先评正确性与证据真实性，再评成本。只有运行时提供用量才能统计 token，并区分缓存和子智能体覆盖；字节不等于 token，静态检查不能证明模型性能提高。

官方参考为 OpenAI 的 AGENTS.md、Build skills，以及 Anthropic 的 Claude Code memory、skills 和 best practices。修改适配器时核对现行版本，不把容易过时的模型发布描述写进每个任务的上下文。
