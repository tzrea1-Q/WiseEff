# 开发工作流

> English: [Development workflow](../../agents/development-workflow.md)

本文件是普通开发的默认路径。既有明确采用封存流程的程序、独立评审要求和发布证据契约继续保留。`docs/developer/ui-quality-checklist.md` 中 PC 优先的视口策略取代旧的全仓三视口默认，不取消专门的发布验收。

## 根据风险选证据，不根据文件数增加仪式

| 变更 | 工作记录与验证 |
| --- | --- |
| 有界文档或机械修改 | 任务或 PR 摘要、相关静态和定向检查；不为纯文档制造失败测试。 |
| 行为、API 或界面修改 | 明确验收用例；验证公共接口及相关异常情况；进行聚焦评审。 |
| 授权、租户、迁移、并发、恢复或破坏性行为 | 明确不变量和对抗用例，进行独立评审，提供要求的真实环境证据。 |
| 显式要求封存、血缘、指纹或分阶段发布批准的项目 | 继续执行既有交付协议和已接受的运行配置。 |

相关的风险证据不能减少；但修改多个文件不应自动引入大型编排状态机。既有计划要求两个独立评审时，未经契约负责人明确修订仍保留两者。

## 实现闭环

明确目标、受影响接口、工作树所有权和验收条件。可逆选择优先说明假设后继续；改变实质范围或产生不可逆后果前取得必要决定。

从实现及相邻测试入手，只读取解决当前不确定性所需的设计章节。尽可能复现缺陷，并补充行为测试。红绿循环用于证明缺陷，不用于给文档、格式化或生成文件增加形式门槛。

编辑期间定向反馈；实现完整后检查差异和相邻集成接口，再执行候选版本门禁。未改变输入或没有新假设时，不反复运行大套件。历史结果可以帮助诊断，但源码或相关环境变化后不能宣称它仍是当前验收证据。

浏览器、数据库、外部服务或独立评审者不可用时，只阻塞其负责的证据。继续不受影响的安全工作，明确缺失项，不宣称就绪，不越过必需合入门禁。

## 计划与恢复

跨会话、多团队、架构变更、高风险发布或既有契约要求的任务保留持久计划。其他有界任务可使用简短摘要。现有计划继续保留文档影响矩阵、文档更新门、界面操作覆盖要求及中英文配对。

交接记录只需承载目标和范围、分支及基线/提交、拥有的路径和相关未提交修改、关键决定、精确命令及结果位置、阻塞项和下一步。原始日志留在本地；不重建长对话，不把逐单元 token 采样变成开发门禁。实测中缺失的用量记为未知。

## 委派与集成

委派独立调查、不相交实现或必需的评审，并给出目标、路径、契约、证据和停止边界。协调者负责集成和外部变更，不为凑满并发槽位或保持忙碌启动工作。

普通任务在获准交付且具备集成条件时建立一个 PR；发现问题后在同一个 PR 修复，不把关闭重开作为常规流程。已接受的封存项目仍执行其显式生命周期。不得绕过检查或冒充独立评审。

rebase 后验证受影响行为及必需标识符和生成物；TypeScript 变更复用 `npm run typecheck`，保留最终构建。不得重置其他工作树；只有获准时才同步指定的干净主分支工作树。

## 完成报告

报告行为变化、真实执行/失败/跳过、缺失外部证据和实际 PR/合并状态。本地或 Hosted 通过不自动等于发布、目标主机或生产通过。
