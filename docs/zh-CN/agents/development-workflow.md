# 开发工作流

> English: [Development workflow](../../agents/development-workflow.md)

本文件是 `AGENTS.md` 所述封存范围（Wayfinder #668 启动子单 #683–#735）以外全部开发的默认路径。该封存范围、独立评审要求和发布证据契约继续保留。`docs/developer/ui-quality-checklist.md` 中 PC 优先的视口策略取代旧的全仓三视口默认，不取消专门的发布验收。

## 根据风险选证据，不根据文件数增加仪式

| 变更 | 工作记录与验证 |
| --- | --- |
| 有界文档或机械修改 | 任务或 PR 摘要、相关静态和定向检查；不为纯文档制造失败测试。 |
| 行为、API 或界面修改 | 明确验收用例；验证公共接口及相关异常情况；进行聚焦评审。 |
| 授权、租户、迁移、并发、恢复或破坏性行为 | 明确不变量，在变更接口编写对抗测试；对 PR 差异做一次独立评审；不变量落在数据库时提供真实 PostgreSQL 测试。 |
| Wayfinder #668 启动子单，或正文明确要求封存、血缘、指纹或分阶段发布批准的 Issue | 继续执行既有交付协议和已接受的运行配置。 |

相关的风险证据不能减少；但修改多个文件不应自动引入大型编排状态机。既有计划要求两个独立评审时，未经契约负责人明确修订仍保留两者。

## 实现闭环

明确目标、受影响接口、工作树所有权和验收条件。可逆选择优先说明假设后继续；改变实质范围或产生不可逆后果前取得必要决定。

从实现及相邻测试入手，只读取解决当前不确定性所需的设计章节。尽可能复现缺陷，并补充行为测试。红绿循环用于证明缺陷，不用于给文档、格式化或生成文件增加形式门槛。

遵循[验证分层](../developer/verification-matrix.md#验证分层)：编辑内循环 → 交接前 → PR CI → 合入 → 夜间。运行 `npm run test:impact -- <changed-files>` 或 `npm run test:impact -- --base <integration-base>`，选择套件、静态门禁、quality 路由及跨路由 acceptance spec。检查两个回退标志，不为适应预算缩小回退范围。获准进行真实 API 浏览器检查时，为选择器命令分配隔离 `WISEEFF_RUNTIME_LANE` ID；quality 覆盖分区使用独立的 `WISEEFF_QUALITY_LANE` 设置。

编辑期间定向反馈；实现完整后检查差异和相邻集成接口，在[智能体验证预算](../developer/verification-matrix.md#智能体验证预算)内执行候选版本门禁。协调者承担昂贵门禁时，实现者顺序执行一次最终 related、变更文件 ESLint 和受影响项目 TypeScript 检查；选中的额外套件、静态门禁、构建及浏览器证据交给协调者。纯文档选择文档验证，不制造测试。未改变输入或没有新假设时，不反复运行大套件。历史结果可以帮助诊断，但源码或相关环境变化后不能宣称它仍是当前验收证据。

浏览器、数据库、外部服务或独立评审者不可用时，只阻塞其负责的证据。继续不受影响的安全工作，明确缺失项，不宣称就绪，不越过必需合入门禁。

## 计划与恢复

跨会话、多团队、架构变更、高风险发布或既有契约要求的任务保留持久计划。其他有界任务可使用简短摘要。现有计划继续保留文档影响矩阵、文档更新门、界面操作覆盖要求及中英文配对。

交接记录只需承载目标和范围、分支及基线/提交、拥有的路径和相关未提交修改、关键决定、精确命令及结果位置、阻塞项和下一步。原始日志留在本地；不重建长对话，不把逐单元 token 采样变成开发门禁。实测中缺失的用量记为未知。

## 委派与集成

委派独立调查、不相交实现或必需的评审，并给出目标、路径、契约、证据和停止边界。协调者负责集成和外部变更，不为凑满并发槽位或保持忙碌启动工作。

普通任务在获准交付且具备集成条件时建立一个 PR；发现问题后在同一个 PR 修复，不把关闭重开作为常规流程。已接受的封存项目仍执行其显式生命周期。不得绕过检查或冒充独立评审。

### 草稿 PR 的 CI 早期信号

在获准创建 PR 和推送后，尽早将同一个 PR 以草稿形式建立，让集成反馈进入实现过程。每次推送后，协调者读取该次推送精确 head 对应的 CI：立即检查失败任务及有界日志，在继续积累变更前修复集成失败，并在标记 PR 就绪前确认最终 `Merge bar` 结果。等待中、已取消或旧 head 的运行不能作为当前验收；草稿状态不豁免任何门禁。

CI 在 PR 打开、同步、重开以及添加或移除 `full-acceptance` 时运行。无关标签编辑跳过昂贵任务，并使用独立并发组，不能取消正在运行或等待中的 PR CI。其轻量结果名为 `Merge bar (ignored label)`，而非必需的 `Merge bar`，不会替代真实门禁结果。验收标签变更根据当前标签列表重新选择验收范围。`main` 推送、夜间运行和手动验收模式保持既有覆盖。

所有安装 Chromium 的任务按运行器操作系统、架构和已安装的 Playwright 版本恢复浏览器缓存；无论命中与否，仍安装 Chromium 及系统依赖。CI 卫生变更由协调者在 PR 中记录前后设置耗时：精确 head/运行/任务、缓存命中情况，以及依赖安装、缓存恢复、浏览器及系统依赖安装的耗时。比较同类任务，区分冷缓存和热缓存；无法获取的测量明确列为缺失，不声称节省。

rebase 后验证受影响行为及必需标识符和生成物；TypeScript 变更复用 `npm run typecheck`，保留最终构建。不得重置其他工作树；只有获准时才同步指定的干净主分支工作树。

## 完成报告

报告行为变化、真实执行/失败/跳过、缺失外部证据和实际 PR/合并状态。本地或 Hosted 通过不自动等于发布、目标主机或生产通过。
