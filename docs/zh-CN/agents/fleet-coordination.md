# 并行工作协调

> English: [Fleet coordination](../../agents/fleet-coordination.md)

只有多个会话或工作树会接触共享集成状态时才读取本文件。已接受的封存项目继续遵守交付协议。

## 所有权和主分支故障修复

修复无关主分支失败前，检查对应 Issue、开放 PR 和认领评论。协调者记录唯一的负责人、路径和停止边界；优先使用既有 Issue 评论，新增认领产物需要授权。实现子智能体不得创建认领 PR，从而消除旧规则中“提前建草稿 PR”与“最后才建 PR”的冲突。

不要多条工作线重复修复同一故障。证据不受影响时继续独立工作。通过定向复现或当前主分支比较分类无关失败，不反复执行整个测试套件。

## 共享编号与源码变化

集成前根据最新主分支检查迁移、ADR 和技术债编号；需要重编号时更新所有引用及中英文配对。不得为解决编号冲突修改已应用迁移。

rebase 无文本冲突不等于行为正确，必须运行受影响检查。TypeScript 变更复用原生类型检查，保留构建及环境门禁。保存原命令退出码，使用 `pipefail` 或结构化结果，不能把日志过滤器的成功当成测试成功。

基于其他未合并分支开发时记录其精确 tip。该分支被重写后根据旧基线重建堆叠，避免盲目 rebase 重放上游提交。保护其他会话的工作树及未提交修改。

## Catalog 隔离

Wayfinder #668 启动节点保留独立数据库和角色要求，使用验证矩阵中的 `catalog:lane:env`、`catalog:lane:accept` 原生命令。禁止用共享 compose 应用库或仅超级用户运行代替；零测试不能通过。

显式协调共享资源。并行开发和评审应互相独立，不能并发修改冲突迁移或共享验收数据库。合并权限始终属于协调者，并受用户授权边界约束。
