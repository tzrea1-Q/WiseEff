# ADR-0047：日志分析是共享 Agent 内核之上的技能平台

> English companion: [English decision record](../../adr/0047-log-analysis-is-a-skill-platform-over-a-shared-agent-kernel.md)

日期：2026-10-18

## 状态

提议中。产品负责人已于 2026-10-18 敲定三项待定输入（见"决策"）。实施由[分析技能平台计划](../exec-plans/active/2026-10-18-log-analysis-skill-platform.md)跟踪；本记录中的内容均尚未实现。

## 背景

已上线的日志分析系统（[2026-08-12 计划](../exec-plans/active/2026-08-12-agent-log-analysis-system.md)、ADR-0022）引擎可靠，但扩展模型薄弱：

- **领域逻辑写在代码里。** 预筛规则是充电领域专用的正则（`server/modules/logs/prefilter.ts:27`），规则 id 是封闭的 TypeScript 联合类型（`server/modules/logs/analyzer.ts:7`），Agent 指令对所有域都相同（`server/modules/logs/analyzer/agentLoop.ts:76`）。接入新业务模块需要改代码并发布。
- **日志业务域是薄的实时配置。** 只有名称、描述、格式画像、模型覆盖、Webhook 和知识链接。Worker 在分析时联表读取域的*当前*格式画像（`server/modules/logs/repository.ts:765`），报告只记录 `promptVersion` 和 `model`，因此编辑一个域会悄悄改变历史运行的复现结果。
- **工具集固定。** 五个工具（`server/modules/logs/analyzer/tools/toolCatalog.ts`），域无法声明新增工具。
- **每次分析只有一个文件。** 接收入口只接受文本文件、单文件 `.gz` 或单条目 `.zip`（`server/modules/logs/unpack.ts`），Worker 把全文载入内存。设备日志通常是多文件日志包。
- **结构化载荷无法解读。** 格式画像能读取时间戳、级别、多行合并和 `key=value` 标记，但无法从一行中取出十六进制寄存器值或协议帧并解码为具名字段。
- **质量检查只面向开发者。** 金标准案例是仓库里的 YAML 文件，通过命令行运行；管理员无法测试自己的配置。

产品目标（2026-10-18）是通用日志分析平台：管理员按业务模块构建分析能力——诊断流程、日志解析、Markdown 知识以及模块源码；WiseEff 提供接收、文件管理、信号提取和通用 Agent 工作流。

## 决策

1. **扩展单元是分析技能。** 分析技能是组织作用域、带版本的包，描述如何分析某个业务模块的日志：诊断流程（Markdown）、适用文件、解析与解码规则、信号规则、知识链接、可选源码快照、预算以及测试用例。它在原地演进日志业务域：现有日志业务域 id 直接成为技能 id，记录、知识链接、Webhook 与反馈的引用保持不变；API 继续接受 `logDomainId` 作为别名。
2. **技能发布不可变版本，运行钉住其中一个。** 编辑产生草稿；发布冻结一个版本。每次分析运行记录所用技能版本，Worker 只加载该版本，绝不读实时配置。重新分析默认使用当前已发布版本，也可指定版本。知识仍在知识库中：技能链接知识条目，运行记录实际检索到的知识修订。
3. **解析是声明式的抽取加解码，构件集合封闭。** 技能的解析规则选择文件，用命名分组模式从行中抽取字段，转换为类型化值，再用固定构件解码：寄存器位域、字节布局帧（字节序、偏移、按已解码字段 `switch`、计数重复、TLV）、查找表、比例/偏移/单位，以及固定的校验和集合。基于解码字段的信号规则取代硬编码的预筛规则。输出是锚定到文件与行的**解码事件**。管理员编写的模式在线性时间正则引擎上执行，并有单行和单次运行上限。
4. **解析脚本后续提供，遵循同一契约。** 仅限日志解析的脚本是计划中的后续阶段。它们产出同样的解码事件契约，在隔离沙箱中运行：无网络、文件系统、数据库或密钥，有 CPU、内存和时间上限，输出视为不可信数据。沙箱选型在实施前需要单独 ADR。
5. **源码通过源码快照和有界工具进入。** 源码快照是模块源码的不可变、带版本标签的上传，存于对象存储并在 PostgreSQL 中建立索引（与 ADR-0025 一致）：日志语句索引（格式串及其输出位置）加分块全文检索。Agent 只能通过有上限的工具访问源码，源码绝不整体载入提示词。源码与日志片段可以发送给已配置的 `LOG_ANALYSIS_*` 模型服务（产品负责人决定，2026-10-18）。
6. **非模块专属的一切归平台所有。** 日志包接收与解压、文件管理与逐文件行索引、通用信号（级别、时间戳、错误码、崩溃特征、行模板聚类、突发与间隔）、Agent 循环及其协议、接地、降级、预算、评测打分、权限、审计、Webhook 和 API。没有技能的运行只使用这些，即演进后的未分类域。
7. **内核仍是 ADR-0022 的有界循环，工具按运行组合。** 平台工具始终可用；依赖技能的工具（解码事件、源码检索）仅当所钉版本提供相应数据时出现。技能的诊断流程作为分隔的段落插入，不能覆盖平台协议：只读、严格 JSON、证据接地。证据引用日志行（文件与行号）或源码位置，每条引用都必须在工具结果中出现过。技能可下调预算，或在平台上限内上调。
8. **技能在产品内测试后再发布。** 解析测试（样例行 → 期望解码字段）是确定性的，每次保存都运行。分析用例（日志包加期望根因、关键证据和建议）用真实模型和现有质量评分运行，并与上一版本比较。结果在发布时展示；它们供管理员参考，不阻止发布。

### 通用信号实现（#1235）

错误突发要求同一文件滚动十秒内至少五条错误，既能发现重复故障，又不把每个孤立错误都当作突发。解析后的 error 级别，或独立且不区分大小写的 `ERROR`、`ERR`、`FATAL` 单词均计入，包括没有正式级别字段的内核 `error -71` 消息。无需技能即可用内核 `[秒.小数]` 启动时钟计算同文件突发、间隔与时间重置；切换时钟类型会清空窗口，启动时钟不作为跨文件绝对时间。崩溃信号保留稳定的 `crash` 类型，新增可选匹配 `signature`；同文件不同签名分别计数并保存锚点。中文报告翻译通用类型与标题，保留技术签名名称。

每次运行由平台提取崩溃特征、时间戳间隔或重启、错误突发及每文件首个错误，不依赖技能。行模板替换变化的数字、十六进制、标识符与路径，保留次数和首末 `file:line` 锚点。RE2 模式及信号、模板、证据集合的上限使提取适于流式输入。运行所属的报告摘要保存通用信号和所钉技能的信号命中；旧报告可以没有摘要。

worker 每行最多扫描前 6144 个 UTF-16 代码单元，每行检查截止时间，约每 8 ms 或 64 个检查点让出调度。可配置耗时默认五秒、最大十秒；信号提取与解码共享最多四分之一的剩余租约，从提取开始时计算。不完整摘要保存可选的 `truncated` 与 `reason`（`time_cap`、`line_cap` 或 `extraction_error`）；出错时返回空摘要并继续分析。其余租约留给压缩、存储与分析，不续租。

`get_signals`、`get_line_templates` 与 `get_timeline` 是始终可用的只读工具。信号及模板每页最多 20 条；时间线按 ISO 时间或文件行号定位，跨文件按时间戳排序，前后各最多返回 20 行。只有返回的行或锚点才建立接地，包括模板首末锚点；行在文件中存在并不足够。规则回退合并通用信号与所钉技能规则，降级标记和置信度上限不变。报告在既有内容旁新增「信号」标签。脚本行为评测覆盖三种工具、仅通过新工具获得的证据与未读行拒绝；PostgreSQL 上传到报告测试覆盖不选技能的多文件包。

## 备选方案

- **保留日志业务域为实时配置并增加字段**——否决：没有版本，报告就说不清是哪套流程、规则或解码器产生的，任何编辑都会改变所有重新分析的含义。
- **以管理员上传脚本作为首个解析机制**——前几个阶段否决：这会把管理员代码放进 Worker，与数据库凭据和其他组织的数据同处。声明式解码覆盖结构化行格式；沙箱确定后再提供脚本（决策 4）。
- **把源码作为知识库条目存储**——否决：知识条目是带编辑修订的文档；源码需要与固件构建匹配的版本标签、文件与行寻址以及日志语句索引。
- **外部代码或日志检索（OpenGrok、Sourcegraph、Elasticsearch）**——暂时否决：每个自托管实例都多一个有状态服务，违背 ADR-0025 以 PostgreSQL 为先的检索立场。若快照规模使 PostgreSQL 索引不可行再重新评估。
- **带文件系统与代码执行的通用 Agent 技能运行时**——否决：它需要本 ADR 推迟的代码执行沙箱，还会把建议性的批处理分析器变成通用执行器。导入导出借用其包*结构*（`SKILL.md` 流程加辅助文件），因为管理员已熟悉。
- **通用解码表达式语言（CEL、JSONata）**——推迟：封闭构件集合更易在编辑器中校验、测试和解释。等真实协议需要时再加有界表达式构件。

## 后果

诊断流程位于平台协议之后、任务之前。#1227 中，它是可选的 Markdown，上限 20,000 字符，从钉住版本读取，以 JSON 字符串传入带分隔符、低优先级的不可信段。行分隔符和分隔符字符转义，防止伪造协议标题或结束标签开启新分区。流程不能覆盖接地、工具结果证据、拒绝规则或只读工具约束。确定性规则回退忽略流程。循环提示词版本为 `2026-10-19.loop.procedure.signals.1` 和 `2026-10-19.loop.procedure.signals.related-parameter.1`；对应单发版本为 `2026-10-19.procedure.signals.1` 和 `2026-10-19.procedure.signals.related-parameter.1`。无流程时省略流程段，平台信号工具仍可用。行为评测验证提示词优先级及编造证据、写操作尝试被拒绝，PostgreSQL 集成通过捕获脚本模型收到的提示词验证草稿隔离和发布。

- 运行来源信息新增技能版本 id；证据新增可选文件路径和可选源码位置。两者对输出契约都是增量的，没有技能的单文件运行表现与现在一致。
- 硬编码的充电规则转为数据，作为种子技能。规则回退随后使用所钉技能的信号规则加通用信号，因此降级分析对任何技能都仍有意义。
- 物理表 `log_domains` 继续作为技能身份表；改名只是外观问题，推迟处理。"日志业务域"一词在 UI 和文档中退役，改为"分析技能"。
- 日志包提高接收上限，并需要逐文件行偏移索引，使工具无需把所有文件载入内存即可读取行范围。压缩包处理必须拒绝路径穿越、链接以及超过一层的嵌套压缩包。
- 现有格式画像对管理员输入使用 `new RegExp`（`server/modules/logs/parser.ts`），在大输入上有回溯风险；改用线性时间引擎同样适用于现有画像。
- 源码快照可能很大。索引是异步的，按文件类型和大小设上限；快照在索引完成前不可用于分析，此时 Agent 在没有源码工具的情况下运行，而不是失败。
- 把源码发送给模型服务是已接受的数据流。源码快照上线时 `docs/SECURITY.md` 必须写明。
- 自助集成需要机器凭据，而产品目前没有（用户以 OIDC 或本地账号的 bearer token 认证）。集成凭据是一种新的主体类型，上线前需单独 ADR。
- 产品内的编写以样例驱动、表单优先；版本的 YAML 形式是等价视图和打包格式，而非主要编辑器。
- 两条 LLM 路径仍并存（ADR-0022）。技能永远不获得写权限，小泽仍只读取已完成的结论。
