# 参数库：以定义为入口的阅读与项目配置对比

> English: [Design discussion](../../design-docs/2026-11-05-parameter-library-design.md)

日期：2026-11-05

状态：用户于 2026-11-05 定稿，并在规格和票据发布后，通过 `implement-spec` 明确授权完成开发，特别要求前端设计和实现质量。部署不在请求范围内。参见[执行计划](../exec-plans/active/2026-11-05-parameter-library.md)。

## 问题与目标

项目参数工作台从项目出发，方便查看和修改该项目的配置值。阅读者需要另一条路径：先找到参数定义，理解含义，再查看各项目如何配置并比较差异，而不必先找到一个已经使用该参数的项目。

参数库基于已有的规范参数定义、修订、Binding 和项目值提供阅读体验。即使没有项目使用，一项定义仍然是有价值、可阅读的参数库条目。

## 第一轮已确认决策

用户于 2026-11-05 接受以下三项推荐。

| 决策 | 已确认行为 |
| --- | --- |
| Q1. 参数库覆盖范围 | 包含平台已发布的全部参数定义，包括本组织尚未登记的主体、尚无项目使用的定义。默认查看当前有效定义，提供本组织登记状态和项目使用情况筛选。项目配置仍受阅读者的查看权限约束。 |
| Q2. 修改边界 | 参数库负责阅读、查询和对比。修改项目值时，准确跳转到已有工作台中的项目、配置集和参数实例；修改定义时进入现有 Catalog 治理。参数库不增加内联值编辑或另一套提交流程。 |
| Q3. 第一版对比范围 | 聚焦单个参数定义在多个项目、多个实例上的对比。多参数、多项目矩阵不纳入第一版。 |

## 领域术语

- **参数库**：以参数定义为入口的阅读界面，定义已写入[术语表](../../../CONTEXT.md)。
- **参数定义**：Catalog 主体拥有的稳定属性契约，不能只凭显示名称确定身份。
- **定义修订**：参数契约在某次修订时的不可变内容。最新发布的说明与某实例的值解释规则可能对应不同修订。
- **Binding（绑定）**：参数定义与项目中某个确切来源实例之间的现有关系。一个项目可以有同一定义的多个 Binding。
- **参数实例**：由确切 Binding 表示的一次参数使用，是面向阅读者的名称，不增加身份，也不等同于项目。
- **项目值**：Binding 下、由确切定义修订解释的配置值事实，区别于待提交草稿和设备调试结果。

参数定义、定义修订、Binding 和项目值沿用已有含义。本设计不增加另一套参数身份、脱离项目的配置值或定义存储。

领域模型已有三种主体类型，但 HTTP 类型筛选白名单仍只接受驱动与节点类型，需要补齐 `configuration-schema`。当前主体 DTO 的 `ownerSubjectId` 可能包含组织放置覆盖；若要构建全平台一致的驱动／子节点树，需要明确读取发布 Catalog 的归属。已确认的 Q6 只要求按主体类型分组。生命周期多选也需要统一契约：当前界面发送逗号分隔值，而 HTTP 解析器只接受单一生命周期。

现有产品及前端文档仍有“不提供第二个 Catalog 产品界面”的描述，但代码已存在只读路由。最终文档需说明：规范目录共享，阅读与治理采用不同呈现；这不意味着增加另一套定义存储或独立治理流程。保留历史验收契约。

## 阅读工作区设计

以下细节展开已确认方向，将随完整方案一起审阅，不代表当前界面已经具备。

### 参数库列表

- 明示登记和项目用量所属的当前授权组织。外壳中的项目选择不能静默缩小参数库；项目是明确、可移除的使用情况筛选。
- 在 `1440×900` 下使用现有 PC 布局规范：可折叠主体导航在左，主结果表在右；搜索、已选筛选、结果数、重置位于表格上方。
- 默认展示当前有效的已发布定义和主体，不因本组织登记生命周期隐藏它们。提供生命周期、主体类型／主体、登记状态、业务模块和项目使用情况筛选，标明组织专属筛选的范围。
- 复用已有不区分大小写的包含搜索，覆盖属性键、显示名、说明正文和主体别名／身份。不承诺相关度排序、模糊匹配，也不增加独立简介字段；列表短预览来自已有说明。
- 主列为：名称／属性键、主体／类型、说明预览、值类型／单位、已配置项目数、当前值实例数。异常生命周期和登记状态用简短标识表达，不加入治理操作；技术 ID 放在次级详情。
- 复用服务端分页，默认 50 条，可选 20／50／100，并保持确定性排序。先筛选后分页；使用数量和项目使用筛选由服务端负责，不把全组织项目值下载到浏览器聚合。

### 参数详情

页头显示可读名称、属性键、所属主体和生命周期，下方是三个已确认页签，默认进入“参数定义”。返回动作恢复列表搜索、筛选及位置。

| 区域 | 内容与行为 |
| --- | --- |
| 参数定义 | 说明正文优先，其后展示值类型、单位、有意义的 schema 约束和示例。示例明确标成示例，不当作项目推荐值；没有内容时明确未说明。 |
| 修订上下文 | 默认阅读当前发布定义，按需打开已有修订历史。实例值始终按自身固定修订解释，不能套用最新定义。历史定义内容不暗示项目用量也是历史快照。 |
| 来源与依据 | 技术身份、发布信息和完整 schema 收在次级查看区。安全复用现有 Markdown 能力，不承诺尚不支持的表格／图片，也不虚构缺失内容。 |
| 治理衔接 | 有权限的用户可进入已有定义治理。打开或阅读页面不创建登记、草稿或发布意图。 |

### 项目配置与对比

- 同时覆盖 DTS 和软件配置实例，保留项目、配置集、实例／来源位置、当前值、单位和值固定的定义修订，不只读取默认配置集。
- 按项目分组，保留每个 Binding。分页边界切开一个项目时标明该组续页；数量区分项目数与实例数。
- 项目／配置集／搜索筛选可见、可移除。当前行、数量与对比复用同一授权实例集合及规范来源可用性规则。未设置／占位不算已配置值；有类型的空字符串和布尔存在性，不能只因原始展示为空就被判缺失。
- 未选基准前中立展示配置值；明确选定基准后，即使目标筛选改变，也保留可见的基准身份。不能自动选第一个项目或实例。
- “对比”页签展示基准身份和值、其他实例列表，并提供选定目标的一对一详细 diff；可比性规则见 Q9。
- 实例动作在 `/parameters?project=...&binding=...` 基础上增加配置集选择。服务端确认目标 Binding 所属项目／配置集，校验传入的 configSet 提示，再先选中并加载该集合，打开 DTS／JSON 详情。切换项目／配置集前保留原有权限检查和未保存编辑保护。合法的非默认实例不能只因加载的是默认集就被误报为不可用。增加仅允许本地参数库路径的返回定位，恢复定义／页签／列表上下文；真正不可读或已移除的 Binding 明确提示不可用，不按名称替换目标。

### 加载、刷新与访问

各页签分别处理加载、失败／重试和空态。配置读取失败不清除可读的定义正文；无权限不能表现为零用量。筛选变更后取消或忽略过期响应，尤其不能在切换组织后展示上一组织结果。

当前查询代表标明时点的一次读取，不是历史快照。一次对比应一起解析基准和目标值，返回确切的 Binding、ProjectValue、DefinitionRevision 身份。刷新可以更新值，但按 Binding 保留选择，并提示已移除／不可用的选项。不能悄悄替换消失的基准，也不能把旧基准与新目标混合后伪装成同一批当前结果。

## 第三轮已确认决策

用户于 2026-11-05 接受 Q9–Q11。

| 决策 | 已确认行为 |
| --- | --- |
| Q9. 不同修订与值形状 | 双方值固定修订按已有分类规则具有相同语义内容时，比较有类型的值，并标明仅说明性修订不同。语义不同／未知时只并排展示，不计算数值差。复杂值不支持安全判断时提供表示／结构 diff，不声称语义相同。不自动换算单位或推导 schema 兼容关系。 |
| Q10. 没有当前配置的项目 | 默认列出存在当前已配置实例的项目，提供“显示无当前配置项目”。使用中立的“无当前配置”，不标为缺少必填参数；退役、不可用、仅保留历史等状态分别表达。没有当前行不证明项目必须配置它，也不证明从未使用。 |
| Q11. 带走查询结果 | 支持复制当前视图链接，以及明确选中的值。接收者重新鉴权并读取当前数据。暂不提供 Excel／PDF 导出、保存对比报告或共享收藏视图；链接不是冻结结果。 |

Q9 采用现有保守规则：单位、完整值 schema、matching 和生命周期都必须一致。它目前在发布模块的 `contentClassOf` 中实现，不是通用对比接口。服务端需读取完整固定修订；公开修订 DTO 缺少部分字段，不能由前端补默认值推导兼容。复用或最小提取已有纯规则，不增加兼容性引擎。schema 内部的说明变化也会被该规则保守视为语义变化，不能承诺所有文字修改都可直接比较。

能够证明可比的标量使用有类型的规范值比较；数值差要求单位相同且数值可以安全表示。数组／JSON 保留类型和顺序语义。复杂 DTS 表达式和跨项目引用中，文本相同不证明含义相同：提供原始／结构查看，并明确不输出无法支持的语义结论。

## 读取模型与计数契约

以下集合均属于服务端授权的一个组织和一个确切参数定义。除非用户明确筛选项目／配置集，否则覆盖全部配置集。配置集筛选只涉及该配置集所属项目，不能在无关项目中虚构缺失行。

| 集合／计数 | 含义 |
| --- | --- |
| 当前实例候选 B | 符合共享来源可用性规则，且具有可证明身份和适用 occurrence 依据的规范 current Binding。被替换、暂停和移除的 occurrence 不属于当前实例。已识别的身份占位只校验其实际拥有的依据，不能虚构值／source pin 或有效来源位置。完整性失败属于不可用，不能静默从集合中滤掉。 |
| 已配置实例 C | B 中具有当前存在、非身份占位 ProjectValue 及合法所属 source pin 的子集。有类型的空字符串、布尔存在性和合法 JSON null 仍是值。可证明的删除和已识别身份占位不是已配置；值记录悬空／缺失或必要 pin 缺失属于完整性失败，不是未设置的依据。 |
| 已配置项目数 | C 中去重后的项目 ID 数量，不是登记数量，也不是所有保留 Binding 所属项目数。 |
| 已配置实例数 | C 中去重后的 Binding ID 数量；关联多条 source pin 不能把数量乘大。 |
| 未设置实例 | 具有明确可识别占位／未设置状态，且对应依据合法的 Binding。显示“无当前值”，只展示可证明的身份／来源，不当作零或推断出来的 schema 默认值。不能把所有 B 中不属于 C 的记录都归为未设置。 |
| 无当前配置项目 | 当前项目／配置集范围内可读、但没有 C 实例的项目，不代表该项目必须配置这一参数。 |

默认展示至少有一个已配置实例的项目组，并保留这些项目中的其他当前未设置兄弟实例。“显示无当前配置项目”开启后，补充只有未设置实例的项目以及没有当前实例的项目。后者只生成一条项目状态行，不虚构 Binding。保留但当前不可用的记录不计入当前值。

沿用已有 missing-current-value 等类型化完整性失败。声称存在的当前值或必要 source pin 无法验证时，返回不可用／类型化错误，不能过滤掉记录后返回成功零结果。所选集合完整性无法确定时，不提供伪精确总数。已知删除／退役是有依据的生命周期状态，读取失败是另一种状态。实施核查需证明合法占位状态，不能绕过已配置值所需的更严格检查。

参数库主列表的数量对应列表上方明确显示的组织／项目使用范围。详情中的范围数量描述项目／配置集选择内、尚未应用行文本／差异筛选的完整集合；筛选结果数量描述分页前匹配的行。两者明确标注，避免把局部结果误认为组织总用量。文本搜索不能把“配置存在但不匹配”的项目改标为“无当前配置”。分页总行数包括明确的项目状态行，但已配置实例数不包括这些行。

同一响应中的数据行、总数和对比基准应在同一数据库读取事务的一致快照内计算，复用既有读取事务设施。不同分页请求属于当前读取，不构成持久快照；游标失效／过期时明确刷新或重新开始。定义修订历史和当前用量保留各自上下文。用量读取缺失代表不可用，不是零；`policyCount: null` 继续表示未知，不进入本功能配置计数。

现有 `usageSummary.projectCount` 按保留的 current-view Binding 统计，口径比 C 更宽。不能直接把该字段改名展示为“已配置项目”。在共享查询归属处增加明确的当前配置摘要，或通过明确版本化替换 DTO；迁移期间保留旧字段含义，新的参数库数量／筛选全部使用新摘要。ADR-0055 改变读取范围，不改变无关破坏性治理操作的计数口径。

## 服务端与客户端契约

以下端点是已接受行为的建议实现形式，具体 DTO 名称可遵循邻近代码惯例；它目前尚不存在。

### 扩展已有读取

- 保留 Catalog 列表、主体、定义和修订读取作为定义来源；补齐配置模型类型筛选和一致的生命周期选择。参数库默认不能沿用治理页面隐含的组织登记过滤。
- 通过规范 Binding 查询归属，批量取得一页定义的当前配置摘要。“有配置”和指定项目筛选必须先作用于完整集合，再分页并计算总数，不能只筛返回的一页。不得逐定义遍历项目发请求，也不向浏览器下载全组织值。
- 保留已有治理、来源和项目编辑命令。用户或 Agent 通过参数库导航都只读；产品人工批准仍留在原有工作台流程中。

### 增加一个以定义为入口的配置读取

`GET /api/v2/catalog/definitions/:definitionId/project-configurations`

| 项目 | 必需行为 |
| --- | --- |
| 范围 | 服务端确定认证组织和 `parameter:view`，校验定义身份及每个传入的项目／配置集／Binding ID。平台全局定义 ID 不扩大值的读取范围。 |
| 查询 | 可选项目／配置集筛选、实例／来源文本查询、includeUnconfigured、cursor、limit。可选 baselineBindingId 请求逐行对比；可选 targetBindingId 请求焦点对比，且必须带基准。 |
| 数据行 | 带种类标记的实例行包含确切 Binding／项目／配置集／来源身份、可读位置、值状态／预览、ProjectValue ID、值固定修订、生效修订、单位和生命周期依据；只有有证明的未设置状态允许明确缺省，占位行仅暴露实际依据。项目状态行只包含项目身份及“无当前配置”，不伪造 Binding／值。 |
| 摘要 | 上节定义的范围计数、筛选后行数、分页信息、读取时间。基准／目标详情与分页行分开返回，因此不在目标筛选内的基准仍可见，也不计入筛选结果数量。 |
| 比较 | 服务端验证相同定义身份及完整固定修订语义。明确返回相同、不同、语义不同、不支持、不可用及原因；数值差仅在已确认规则足以支持时提供。 |
| 数据量 | 分页行使用明确标记截断的预览。通过同一查询归属，按需取得明确选中的基准／目标或查看／复制值的完整内容；不能把截断预览冒充完整值复制。沿用现有输入输出限制。 |
| 失败 | 输入不合法／身份不匹配明确失败；未认证或无查看能力沿用现有鉴权处理。跨组织或不可访问身份沿用现有不泄露信息的响应规则。基准不可用时不能自动挑选替代项。 |

数量、新读取与已有项目起点对比适配器共享底层规范查询。保留旧端点公开形状，明确修复共享计数／读取范围分歧。不仅为这个阅读界面增加第二套当前值存储、后台同步服务、通用比较引擎或数据库迁移。实施核查若发现必须变更 schema，应另行说明理由，不能假定本设计已经接受。

当前行使用当前 Catalog 与来源可用性。打开历史定义修订只改变展示的定义内容，项目配置读取仍明确为当前。比较值所需的两份修订来自各自 ProjectValue 固定修订，即使 Binding 的生效修订或页面展示的最新 head 不同，也不能替代。

### 可定位状态与返回流程

复用 `/parameters/definitions` 及现有定义／列表定位参数，增加页签、基准／目标 Binding ID、实例筛选与 showUnconfigured。列表搜索／游标与实例搜索状态分别保留。不合法组合只清除不合法选择并解释原因；浏览器前进后退和刷新恢复定义、页签及对比身份。

工作台跳转需要扩展上下文解析和配置集加载，支持非默认配置集。客户端传入的项目／配置集／Binding 组合是待服务端校验归属的提示，不是授权。DTS 和软件配置都必须先加载目标集合再选 Binding，原有脏状态保护覆盖离开旧上下文的操作。

复制链接包含选定定义／视图和支持的身份／筛选状态，不包含值载荷、凭据或组织切换命令。接收者在自己的当前组织中重新鉴权、读取当前数据；文案说明数据可能已变化。项目工作台的返回定位须标准化并限制在本地参数库路径，拒绝外站、协议相对地址及嵌套任意重定向。返回仍遵守已有未保存编辑保护。

复制值由明确的行／详情动作触发，复制选中值的完整原始表示并保留实际格式，不复制示例值或规范化预览。成功／失败有反馈，失败保留选择；不会产生草稿，也不声称含来源专属引用的值可以直接跨项目使用。

## 状态与比较矩阵

| 条件 | 展示／可用动作 | 不能暗示 |
| --- | --- | --- |
| 已发布、未登记、未使用 | 定义可读，“未登记”标识，无当前配置 | 阅读必须先登记或选择项目 |
| 有效定义的 C 为零 | 无当前配置，可选展示无配置项目 | 从未使用、缺少必填项、值为零 |
| 同项目多个 Binding | 保留各配置集／来源行，明确选基准 | 一个项目只有一个值 |
| 同定义、同语义 | 类型化相同／不同；安全且同单位标量可给数值差 | 推荐值、设备实际状态、自动批准 |
| 仅说明性修订不同 | 正常比较并标明修订 | 修订 ID 不同就一定不能比较 |
| 语义不同／未知 | 原值、各自单位和修订并排，无数值差 | 自动换算或等价 |
| 不支持的复杂值／引用 | 明确标为原文／结构查看 | 文本相同证明跨项目含义相同 |
| 空字符串／布尔存在性／JSON null | 保留类型和存在状态，区别于不存在 | 展示空白就是没有值 |
| 可证明的占位与缺失值／pin | 占位显示“无当前值”且仅显示实际依据；悬空／损坏的当前数据返回不可用，不提供无依据总数 | 缺失记录或读取失败就是普通未设置值 |
| 定义／登记退役、来源暂停 | 解释已知不可用原因，保留原归属允许的定义历史／深链接 | 历史已删除或从未配置 |
| Binding 被删除／替换且仍保留 | 选中项不可用，仅在已有能力支持时提供确切历史链接 | 同名实例就是替代者 |
| 是否存在历史未知 | 无当前配置，不声称一定有保留历史 | 当前零数量证明历史有或没有使用 |
| 无权限／请求失败 | 明确拒绝／不可用或重试，保留可读定义 | 成功查询后没有结果 |
| 阅读期间基准消失 | 保留身份上下文，说明不可用并要求明确重新选择 | 自动回落首行 |
| 打开历史定义修订 | 历史修订标识，项目区标明“当前配置” | 当时的项目快照 |

## 验收矩阵

以下是未来实施验收要求，不是本次设计任务已经取得的结果。

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| LIB-01 | 未选项目直接进入参数库 | 主导航入口可见，展示有效的全局发布定义，未使用／未登记定义可发现。 |
| LIB-02 | 驱动、节点类型、配置模型搜索筛选 | 三类端到端可用；不在第一页的匹配可检索到；先计算全量筛选结果再分页。 |
| LIB-03 | 同组织非参与者／项目角色读者 | 合法数量、明细和对比一致；修改无权限项目值仍被拒绝。 |
| LIB-04 | 无 `parameter:view`、禁用或跨组织身份 | 摘要、游标、基准／目标、分享链接和缓存响应均不泄露配置数量／值。 |
| LIB-05 | 项目 A 两实例、B 一实例，另有其他配置集 | 保留全部 Binding 和配置集；不按名称／路径配对，不按项目去重值。 |
| LIB-06 | 同定义只有非语义内容不同 | 可比值仍可比较，显示不同修订；最新 head 不替换值固定修订的解释。 |
| LIB-07 | 单位／schema／matching／生命周期变化或缺少修订证据 | 并排原有上下文，无推断等价或数值差。 |
| LIB-08 | DTS 数字不同写法、类型化 JSON、布尔、空字符串、复杂引用 | 支持的规范值正确比较；不支持的形态明确限制；不使用部分字符串数值转换，也不误判为空。 |
| LIB-09 | 已保存草稿、待审修改、设备调试值 | 都不改变展示的当前 ProjectValue 和计数。 |
| LIB-10 | 零使用、可证明占位／未设置兄弟实例、缺失值／pin、显示无配置项目 | 项目／实例／行计数正确；不伪造 Binding／来源依据；损坏当前数据返回不可用而非未设置／零；行搜索不把不匹配误标为未配置。 |
| LIB-11 | 退役、来源暂停、替换和值删除 | 当前数量／清单／对比采用一致可用性；历史保留且说明真实。 |
| LIB-12 | 筛选／分页／刷新与并发修改 | 身份选择稳定，范围和结果计数真实，无关联重复计数、混合对比快照或旧组织响应。 |
| LIB-13 | 深链接、前进后退、刷新、项目编辑往返，包含非默认 DTS／JSON 配置集 | 校验 Binding／项目／集合归属，先加载正确集合再定位；恢复定义／页签／列表，保护未保存编辑，拒绝不匹配提示和非法返回地址。 |
| LIB-14 | 分享链接和复制完整多行值 | 接收者重新鉴权并读取当前数据；复制完整选中值或报告失败；链接不含值载荷。 |
| LIB-15 | `1440×900`、键盘、长说明／长值 | 列可读、焦点稳定，页签／树可操作，加载错误可感知，完整值按需展开且动作不被裁切。有实际布局风险才增加一个紧凑 PC 窗口。 |
| LIB-16 | 定义读取成功、项目读取失败 | 定义仍可阅读；局部重试恢复；失败／无权限不展示为零用量。 |

实施验证遵循仓库影响选择器和验证矩阵。权限／计数／查询变更需要真实 PostgreSQL 集成覆盖及独立审查。UI 在任务隔离的真实 API 环境以 `1440×900` 验证，明确包含 DTS 和软件配置样例；mock 不构成集成验收。保留所选构建和静态检查，记录确切通过／失败／跳过，不削弱历史 Catalog 证据要求。
