# ADR-0053：业务模块直接容纳主体，驱动拥有其子节点

> 英文：[English](../../adr/0053-business-modules-hold-subjects-and-drivers-own-child-nodes.md)

日期：2026-11-02

## 状态

[#1479](https://github.com/tzrea1-Q/WiseEff/issues/1479) 已确认。实施方案见[模块主体结构](../../exec-plans/completed/2026-11-02-issue-1479-module-subject-structure.md)，分 S1–S5 交付。本 ADR 修订 [ADR-0042](adr-0042-organizations-register-canonical-subjects-once.md)；ADR-0040 的身份、发布与同步器规则不变。

[ADR-0054](adr-0054-module-structure-transfer-is-explicit-organization-governance.md) 补充已接受的组织结构传输与停用登记归属编辑设计，实施待开始；本 ADR 的 Catalog 所有权和子节点生命周期不变量继续生效。

## 背景

ADR-0042 让主体登记放入与主体类型对应的模块（`driver-group`、`node-type`，配置规范放 `business`），数据库还限制一个模块只能放一条归属。用户因此要在业务分类下再建一个同名技术模块，“调整归属”看不到业务分类，模块树位置看起来像驱动与子节点的结构关系，实际却不是。Catalog 导入还丢弃了驱动 schema 的 `childNodes`，节点类型按名称全局唯一，另一驱动下同名子节点可能匹配到错误主体。

## 决定

1. **模块只表达业务分类。** 新归属与新模块只使用 `business` 或保留的 `unclassified` 根；`driver-group`、`node-type` 模块在迁移归档前只读保留。
2. **一个业务模块可容纳任意多个根主体**（驱动、独立节点类型、配置规范），也可有业务子模块。取消“一模块一归属”约束；每条登记仍恰有一条保留归属（ADR-0042 不变量不变）。
3. **Catalog 从属仍属于身份，组织内从属可显式覆盖。** 节点类型可有永久 Catalog 所属驱动（`catalog_subjects.owner_subject_id`），名称唯一性按该驱动划分。依据 [#1509 的补充澄清](https://github.com/tzrea1-Q/WiseEff/issues/1509)，管理员可通过保留登记上的可空所属驱动覆盖字段，**仅在当前组织**更换子节点所属驱动。其他组织及已发布 Catalog 身份不变。操作沿用版本条件与审计，核验目标驱动、组织登记、当前发布和识别名称冲突。调回 Catalog 所属驱动时清空覆盖。共享 Catalog 身份变更仍须建立新主体并按 ADR-0044 替换定义。
4. **子主体保留各自的登记与归属**，现有绑定的登记身份不变。子主体归属不指向模块，组织内展示在有效所属驱动的归属之下。有组织覆盖时使用覆盖，否则使用 Catalog 所属驱动。识别、生命周期级联、来源范围校验、结构导出与复制均遵循这一规则。调整归属保留定义、值、历史及来源字节，不会搬动 DTS 节点；后续来源编辑仍须遵循既有预览和审批流程。
5. **子主体登记跟随根主体，支持在组织内单独停用。** 登记驱动时同事务登记其有效子主体；停用驱动级联停用；恢复驱动只恢复被级联停用的子主体。依据 [#1509](https://github.com/tzrea1-Q/WiseEff/issues/1509) 的补充澄清，管理员可沿用驱动的版本条件、影响确认与审计流程，单独停用和恢复子主体。单独停用的子主体不会随驱动恢复；恢复子主体要求所属驱动在 Catalog 和当前组织中均有效。登记、归属、定义、绑定、值和历史均保留。子主体仍没有独立登记入口。
6. **匹配携带所属驱动上下文。** 节点自身 compatible 匹配驱动；否则匹配最近祖先驱动下同名的子主体；否则匹配无所属驱动的独立节点类型。有所属驱动的节点类型不能脱离该上下文被匹配。
7. **单一读模型接缝**推导每条登记的实际业务模块（直接或经所属驱动），供模块树、统计、定义库和项目工作台使用。
8. **名称不是身份。** 旧技术模块名称可作为根主体登记的组织显示别名保留，不替代主体、定义、绑定或值的身份。

## 影响

- 组织识别覆盖规则从以模块为键迁为以登记为键。
- 单条、批量与审核登记不再创建技术包装模块；#1447 的“创建同类型模块 / 选择空闲模块”选项被取代。
- 存量技术模块按组织执行可预检、幂等、有审计的迁移；对共享或无证据的子节点从属、名称不符的模块、所属驱动未登记等情况报告冲突而不猜测，旧模块归档而非删除。
- 从属证据不一致的子节点保持为独立节点类型并报告。

## 备选方案

- **只在界面隐藏包装层。** 否决：数据库约束、登记写入与匹配器仍按旧关系工作。
- **只保留驱动登记并改指子节点绑定。** 否决：会改写保留的绑定身份与审计历史。
- **按 release 版本化父子关系。** 否决：节点换父即语义变化，按新主体建模。
