# ADR-0048：集成凭据是机器主体，不是用户

> English companion: [English decision record](../../adr/0048-integration-credentials-are-a-machine-principal.md)

日期：2026-10-19

## 状态

已接受。扩展 ADR-0038。实施由 #1248 跟踪，隶属[分析技能平台计划](../exec-plans/active/2026-10-18-log-analysis-skill-platform.md)。

## 背景

目前向 WiseEff 推送设备日志的外部系统只能以个人身份认证，即使用用户的 bearer token。这个 token 携带该用户在整个产品中的角色与权限，人员离职后失效，并且每次上传都会被记为用户发起。分析技能平台（ADR-0047，规格 #1221 用户故事 74–76）需要自助集成：集成方从技能的「集成」分区复制技能标识和凭据，无需个人账号即可推送日志。

ADR-0038 将认证主体（`AuthContext`，始终是用户）与服务端构造的 initiator（`user`、`agent`、`system`）分开。二者都不适合机器调用方：
- `AuthContext` 要求用户；
- `system` 指服务端自有的作业，而非服务端之外持有的凭据；
- 把凭据伪装成用户会伪造审计溯源，这正是 ADR-0038 所禁止的。

## 决策

1. **集成凭据是独立的主体类型。** 它属于组织作用域，具有：
   - id；
   - 显示名；
   - 可选的单一技能绑定；
   - 固定范围：上传日志，以及读取自己创建的记录。

   它不是用户，不携带 `AuthContext`、角色或权限，也不会出现在用户列表、角色绑定或 `/me` 中。
2. **Bearer 格式与存储。** 密钥为至少 256 位的随机值，以 `Authorization: Bearer wie_<credentialId>_<secret>` 形式提交。
   - `wie_` 前缀把请求交给凭据解析器；其他 bearer 仍走现有的用户解析器。
   - 服务端只保存密钥哈希，并以恒定时间比较。
   - 明文只在签发或轮换时返回一次，不记日志、不进审计、不持久化，也无法再次取回。
3. **只允许白名单路由，默认拒绝。**
   - 集成主体只被显式白名单接受：日志上传端点（`POST /api/v1/log-files`、`POST /api/v1/logs`），以及读取该凭据自己创建的记录、报告和文件。
   - 其他所有路由仍要求用户 `AuthContext`，在任何处理器或领域读取之前就以 `401`/`403` 拒绝该凭据。
   - 绑定技能的凭据只能上传到该技能；技能选择冲突或未绑定时返回 `403`。
4. **记录保留创建它的凭据。** 由凭据创建的记录保存 `created_by_credential_id`，带组织复合外键，上传用户为空。拥有 `logs:view` 的组织用户仍可像查看其他组织记录一样查看这些记录。凭据永远不能读取其他凭据或用户的记录。
5. **新增溯源 initiator。** 可信调用联合类型新增 `integration`，携带凭据 id 与组织，只能由凭据解析器构造。审计记录 `actor_type = integration` 及凭据 id。human-required 策略拒绝 `integration`，与拒绝 `agent`、`system` 一致（ADR-0038）。
6. **生命周期受管理并审计。**
   - 拥有 `logs:admin-domains` 的用户在技能工作区的「集成」分区签发、轮换、吊销凭据。
   - 签发、轮换与吊销都是同一事务内的审计写（ADR-0027）。
   - 轮换立即替换密钥；吊销在下一个请求即生效。
   - 服务端记录 `last_used_at`，每分钟最多更新一次，以避免写放大。
   - 归档已绑定的技能会吊销其凭据。
   - 凭据上传与用户上传使用相同的大小、频率与分析上限。

## 备选方案

- **用户个人访问令牌。** 不采用。它继承个人的广泛权限，随人员离职失效，并把机器流量记为人工操作。
- **服务用户账号。** 不采用。虚假用户污染用户管理和角色绑定，并伪造 ADR-0038 溯源；其权限取决于被授予的角色，而不是固定范围。
- **OAuth 2.0 客户端凭据。** 暂不采用。它需要产品当前并不具备的授权服务器与令牌交换。日后可以用令牌交换替换凭据解析器，而不改变主体模型。
- **签名请求（每请求 HMAC）。** 第一版不采用。TLS 上的 bearer 密钥与现有 API 形态和集成方工具（`curl`）一致；请求签名可作为后续加固加入，不改变主体。

## 影响

- 认证层新增第二个解析器，并在路由边界引入主体联合类型。大多数路由不变，因为它们仍要求用户上下文，所以凭据的可达范围恰好就是白名单。
- 新表保存凭据，含组织外键、哈希、技能绑定、状态、`last_used_at` 与审计关联。记录新增可空的创建凭据列。租户隔离同时由查询与外键保证。
- 集成示例（`curl`）与集成指南从个人 token 改为集成凭据。
- 泄露的凭据只能向一个组织（可选限于一个技能）上传日志，并只能读取自己上传的内容。吊销立即生效，每次使用都可追溯到该凭据。
