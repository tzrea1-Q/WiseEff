# ADR-0054：模块结构传输属于显式组织治理

> English: [ADR-0054](../../adr/0054-module-structure-transfer-is-explicit-organization-governance.md)

日期：2026-11-03

## 状态

设计于 2026-11-03 接受：Q1–Q11 及整份[实施方案](../exec-plans/completed/2026-11-03-module-structure-transfer.md)已获用户确认。规格：[#1493](https://github.com/tzrea1-Q/WiseEff/issues/1493)；实现与验证：[PR #1505](https://github.com/tzrea1-Q/WiseEff/pull/1505)。本决策保留 ADR-0042/0053 的身份和所有权，将受控归属编辑扩展到停用登记，但不激活它们。部署与本次实现分开处理。

## 决策

带版本的模块结构包描述组织内业务分类和登记设置。同组织更新使用稳定身份及服务端保存的导出基准逐字段检测冲突。同部署跨组织复制生成或复用目标模块身份，复用共享 Catalog 主体身份，并要求确认匹配和冲突处理。复制保留源组织，不把源文件的模块删除指令应用到目标。

省略条目不代表删除或停用。删除模块必须显式声明，并在提交前处理子模块及受影响根归属；删除模块不意味着停用主体。传输不重写 Catalog 结构、项目值或保留历史。所属子节点继续遵循 owner 的归属和生命周期规则。

由 Governance 持有一个事务，统一执行已确认的模块、登记、别名、识别设置、审计和持久重试回执。公共 HTTP 层不能拼接各自已提交的 writer。停用登记可在受控路径下编辑或复制归属，始终保持停用，不能临时恢复；现有 Catalog、子节点和 Binding 约束继续生效。

### 组织识别类型纠正（2026-11-07）

用户明确了种子中的独立节点类型可能实际对应 compatible 驱动。因此，模块导入接受非空 compatible 覆盖作为当前组织内的节点到驱动纠正，预览明确列出类型变化，并保留人工确认、鉴权、原子事务、并发和审计约束。现有识别规则已经具有互斥的驱动/节点字段组合，无需修改 Catalog 身份或新增数据库结构。当前组织读取和匹配使用该组合的生效类型，目录编制能力仍依据规范类型；固定版本历史读取保留规范语义。

主体、登记、归属、参数定义、Binding 和参数值身份保留。导出/复制携带纠正后的识别类型，恢复继承则恢复规范类型。所属子节点、配置规范、全局 Catalog 身份及驱动所有权能力不在此纠正范围内。导出后识别规则发生变化时，丢弃旧节点识别前必须明确处理冲突。验证覆盖非空历史身份保留、精确匹配、组织隔离、预览无写入、重复/重试、过期/冲突、审计失败回滚、恢复继承、复制到新旧登记和实际导入界面。

## 取舍

名称/路径身份会让改名与再次复制变得含糊，因此只作为匹配建议。按文件内容整体替换会把意外截断变成删除，因此删除必须显式，且不在复制模式执行。保存基准增加产品存储，但支持并发编辑，避免信任用户可修改的基准字段。原子治理需要共享事务和覆盖现有 writer 的锁协议；循环调用现有 API 会导致部分导入。停用归属通过正式治理扩展支持，不使用隐藏生命周期切换。

格式不承担灾难恢复备份或组织持续同步。独立部署迁移、Catalog 编制、源组织清理和 Agent 自动执行不在本决策范围。
