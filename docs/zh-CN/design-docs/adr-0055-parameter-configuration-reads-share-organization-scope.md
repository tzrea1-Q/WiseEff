# 参数配置读取统一采用组织范围

> English: [Parameter configuration visibility](../../adr/0055-parameter-configuration-reads-share-organization-scope.md)

## 状态

2026-11-05 经[参数库设计](2026-11-05-parameter-library-design.md) Q4 确认，用户随后于同日确认完整方案并定稿。设计已接受；本文档变更不代表已实施或部署。

## 决策

已认证、处于启用状态且具有 `parameter:view` 的用户，可以读取服务端授权的当前组织内项目配置。参数库中的项目数、当前实例／值数量、配置明细和对比采用同一组织范围。来自某个项目角色的参数查看能力，不将这些参数读取限制在该项目。编辑、提交、审核、合并仍分别遵循已有的项目和操作权限。

已发布的平台参数定义继续遵循已有 Catalog 授权，不因本组织未登记或没有项目使用而不可读。能够读取定义本身不授予项目配置查看权；数量与明细要求同样的配置查看能力，权限不足或统计不可用不能显示为零。平台定义可读不意味着可以跨组织查询配置值。明确授权的 Operating organization 沿用服务端所属上下文，不变成无组织范围查询。

实施本设计时，明确替换定义当前配置用量统计中原有的项目角色可见性规则，使其与现有项目参数、对比行为及 [ADR-0051](adr-0051-organization-provisioning-and-member-admission.md) 一致。这不是仅凭项目列表可见就推导出来的隐式权限变更。它不扩大 Catalog 发布、治理队列、策略／引用明细、破坏性操作影响预览、其他业务领域或机器身份的权限。

## 权衡

保留按项目限制的统计是实际可选方案，但它会隐藏用户已经能逐项阅读的配置数量，或者要求收紧现有项目参数阅读权限。选定规则支持组织内工程经验查询与对比，同时保留项目修改权限和组织隔离。未来反转该决定会改变组织成员可以学习的配置范围，因此单独记录这一边界。

## 实施所需证据

当前 `parameterUsageProjectScope` 与 `rootUsageScope.integration.test.ts` 仍执行原有统计范围。在获得实施授权并修改共享入口及调用方之前，保留现有行为。实施时以新确认规则的覆盖替换受影响断言，不删除授权覆盖，也不将历史通过结果当作新验收。

实施需要独立审查和按真实角色运行的 PostgreSQL 证据，覆盖同组织非参与者、项目角色读者、缺少 `parameter:view`、禁用用户、跨组织标识、查询／缓存组织隔离，以及读者修改被拒绝。数量和明细必须来自同一当前实例集合，覆盖配置集、来源可用性、删除与退役规则。环境不可用时明确记录未运行。此 ADR 不授权线上策略变更、生产发布或数据迁移。
