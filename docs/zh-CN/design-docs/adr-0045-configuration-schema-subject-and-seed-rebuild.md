# ADR-0045：配置模型共用新版参数目录

> English: [English](../../adr/0045-configuration-schema-subject-and-seed-rebuild.md)

日期：2026-09-14；D10 于 2026-09-15 确认。状态：D01 至 D10 的目标决策已确认；实现与目标操作仍须遵循[统一计划](../exec-plans/active/2026-09-14-parameter-unification-and-seed-parity.md)。源码基线 `6d72e17cb4c581e7235b181dbbfd45d92f4dee7b` 中 0044 尚未使用，集成前再次检查编号。

保留的业务种子包含没有权威设备 compatible 的软件配置。因此新增 **ConfigurationSchema（配置模型）**，作为以受治理模型标识确定身份的第三种正式目录主体。保持 Driver 的 compatible 匹配和 NodeType 后备匹配规则，共用已有参数定义、定义版本、注册、位置、绑定、项目值和唯一发布写入者。文件格式与模型身份分离；两个 JSON 兼容种子仍需配置模型。

2026-09-15 已确认范围修正：本轮原生支持 DTS／JSON 项目源导入、审批写回和导出。YAML／TOML／ENV 项目源能力及对应 8 项兼容种子延期到 [TD-124](../exec-plans/tech-debt-tracker.md)，保留原元数据、示例和项目初始／推荐值，不转换为活动 JSON 种子；4 项 DTS／JSON 兼容项保持本轮交付。不支持的项目源格式在暂存／应用前明确拒绝。厂商 YAML 目录定义仍作为 DTS 发布的元数据输入。本修正仅调整交付时间，共享主体模型和其他归档重建决策保持不变。

三个内置项目采用完整、明确标识的示例 DTS 基底。悬空 overlay 引用必须解析到受审源声明；编译桩节点或相似名称不能证明正式 Driver／NodeType 身份。保留业务属性和各项目值，记录逐项身份归属，明确这些配置用于演示，不是真实设备固件。

本决策仅在主体类型、选择器及相关消费者识别配置模型的范围内扩展 ADR-0040／0041／0042 的“两种主体”限制。稳定身份、完整不可变发布、显式生命周期、固定版本解释、授权、审计及 ADR-0043 发布控制继续适用。历史两种主体的发布仍须可回放；新能力通过显式版本准入，不能重新解释旧字节。数据库采用新增迁移，不重写已执行迁移或旧 ADR 历史。

不采用虚构 compatible，因为它会伪造来源身份；不扩展逻辑服务驱动，因为它会改变现有设备匹配契约；不建立第二套配置定义／值库，因为它会重新制造本次要消除的数据分歧。代价是明确扩展编译器、匹配器、存储约束、API、注册／位置以及编写和工作台界面。

针对本次部署，用户同时选择种子重建：保留非参数数据，旧参数值、草稿、历史和源版本归档，仅初始化 Atlas／Aurora／Nebula，保留 acme 发布历史并将样例从新选择中退役。

限定的 `archive-rebuild` 运行配置**仅针对明确选定的部署及已枚举的旧参数入口**替代普通两次发布／90 天旧读取窗口：验证后的重建开放流量时，有权访问的旧链接立即显示已归档。原有新旧配置值等价比较替换为种子对齐、归档完整、非参数保留及全部消费者使用新版的核验。目标身份、范围与候选由操作计划固定；这不构成正常 S13／P13 退役证据、OP-09 完成或其他部署的规则变化，原 R0–R10 分类事实保持不变。整套恢复、权限、审计、引用核对、完整发布谱系和发布授权均不豁免。离线归档／映射／审计按部署既有保留策略保存，本决策不授权销毁归档。
