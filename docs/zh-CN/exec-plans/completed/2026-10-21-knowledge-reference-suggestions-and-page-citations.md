# 知识引用建议与 PDF 页级引用

> English: [English](../../../exec-plans/completed/2026-10-21-knowledge-reference-suggestions-and-page-citations.md)

状态：已于 2026-10-21 交付。设计于同日敲定（拷问式设计会话，三轮，所有建议均被采纳）；页级引用经 [#1347](https://github.com/tzrea1-Q/WiseEff/pull/1347) 合入，引用建议经叠加在 #1347 之上的 [#1348](https://github.com/tzrea1-Q/WiseEff/pull/1348) 合入（R25 按两个 PR 交付）。验证证据记录在各 PR 中。规格：[#1338](https://github.com/tzrea1-Q/WiseEff/issues/1338)；工单 #1339–#1341（引用建议）和 #1342–#1345（页级引用）。承接[用户自管知识](2026-10-21-knowledge-user-curation.md)延后的两项：导入时识别参数名（K15）和 PDF 页级引用（K22）。

## 授权目标

让导入的和已有的知识互相关联、可以核查：

- **引用建议。** 当条目文本提到某个参数定义时，平台为其建议定义引用，由条目的治理者接受或忽略。这样批量导入的文档无需逐条手动关联，也能出现在定义页、DTS 重载运行和调试节点中。
- **页级引用。** 对 PDF 知识的引用会注明出自第几页，读者可以直接打开到该页。

起点：

- 定义引用只能显式建立（`knowledge_definition_references`，按 K20 归条目治理，增删均有审计，并拒绝已退役定义）。
- 目录属性键在目录主体（模块）内唯一，而非组织内唯一。键是简短的 snake_case 字符串，例如 `r_pcb`、`ic_para1`。
- PDF 提取（`pdf-parse`）把各页拼接在一起并丢弃了逐页文本，分块不携带位置信息。
- 小泽引用链接到条目；日志运行只记录 `{entryId, revisionId}`。
- 文件以附件形式下载，没有 PDF 查看器。

## 决策

| 编号 | 决策 |
| --- | --- |
| R1 | **引用建议**按条目和定义持久化：`待处理 → 已接受 / 已忽略`。接受时经现有新增路径写入一条普通定义引用。忽略会被记住，同一条目和定义不会再次出现。 |
| R2 | 只有条目的治理者（所有者或 `knowledge:manage`）能看到并处理建议；读者只看到已接受的引用。 |
| R3 | 待处理的建议不是绑定：绝不改变任何知识范围、相关知识列表、小泽或日志分析的检索（ADR-0049）。 |
| R4 | 每次为修订建立索引时（含草稿）都运行检测，另对已有条目做一次回填。条目已引用的定义不再建议。 |
| R5 | 检测对所有知识来源方式一视同仁。 |
| R6 | PDF 引用的页码是从 1 开始的物理页序（即查看器 `#page=N` 打开的页），显示为「第 N 页」或「第 N–M 页」。 |
| R7 | 页级引用只适用于 PDF；DOCX、Markdown 和文本保留按标题层级的引用。 |
| R8 | 已有 PDF 通过重新提取和重建索引获得页码，不产生新修订。已存储的引用和已完成运行的来源记录永不改写。 |
| R9 | 提及指与属性键完全一致、区分大小写的整词匹配（两侧不能紧邻 `[A-Za-z0-9_,.+?#-]`），键长至少 4 个字符；不匹配显示名称。每条建议保存证据：一段摘录，PDF 还保存页码。 |
| R10 | 同一个键存在于多个模块时，每个候选定义各生成一条建议，界面上按键分组并显示模块名称。接受其中一条不会忽略其他条。 |
| R11 | 生效和已弃用的定义都会被建议，已弃用的标记「已弃用」；已退役的定义永不建议。 |
| R12 | 候选定义来自该组织经认证的目录读取；接受时由现有新增路径再次校验。 |
| R13 | 治理者在条目详情的定义引用编辑区看到建议（「建议关联」，提供 接受 / 忽略 和「全部接受」），列表另有「待处理建议」筛选和数量徽章。不发通知。 |
| R14 | 批量操作栏新增「接受建议关联」：每个选中条目单独授权、单独接受，各有审计和逐条结果（规则与 #1331 相同）。 |
| R15 | `/knowledge-admin` 提供「重新检测建议关联」（`knowledge:manage`），用于目录变化后重新扫描整个组织；目录发布与知识不耦合。重新扫描后忽略记录依然有效。 |
| R16 | 接受时写入现有的定义引用新增审计，并标明来自建议；忽略写入单独的审计事件；检测本身不写审计（派生数据，与建立索引相同）。 |
| R17 | 提取时在提取文本旁保存每一页起始的字符偏移。分块保持原有的段落窗口，并记录 `page_start` / `page_end`。引用指向起始页。 |
| R18 | 点击页级引用会打开条目详情，显示「引用位置：第 N 页」和「打开第 N 页」；后者通过带 `#page=N` 的类型化 blob URL 在新标签页中打开 PDF（使用浏览器自带查看器；不引入 pdf.js；附件响应头不变）。 |
| R19 | 页码出现在 `/knowledge` 搜索结果、小泽引用（标签和链接）以及新的日志分析运行中。新运行按条目修订记录所检索分块的页码，报告显示「第 3、7 页」。此前的结果保持原样。 |
| R20 | 页级引用携带其修订。若该修订不是最新修订，打开时提示「引用的是历史修订」，并打开该修订的文件（K9）。 |
| R21 | 若最新修订不再提及某个键，相应的待处理建议会被撤回；之后的修订再次提及时可以重新出现。已接受的引用和忽略记录绝不自动改变。 |
| R22 | 已归档条目不做检测；其待处理建议在取消归档前保持隐藏，取消归档后按最新修订重新核对。 |
| R23 | 所有匹配都连同提及次数保存，按次数从高到低排列，不设上限。 |
| R24 | 本轮小泽不列出、也不处理建议。 |
| R25 | 两项功能作为两个独立 PR 交付，并行开发，各自通过检查后合入。 |

## 不变量

- 检索范围不变。只有已接受的显式引用才把知识绑定到定义（ADR-0049）。仅已发布检索和组织隔离同样覆盖建议及其证据、页偏移和页级引用。
- 没有治理者的操作，建议绝不会变成引用。每次接受和忽略都是在独立事务中完成的带审计写入（ADR-0027）。
- 检测、重新扫描和重建索引绝不改写已存储的引用、运行来源记录和忽略记录。

## 切片

### 功能 A — 引用建议（一个 PR）

- **A1，检测与治理：** 建议的存储；建立索引时检测；撤回（R21）和归档（R22）规则；一次性回填；带审计的治理者读取、接受和忽略 API；条目详情中的「建议关联」区块；「待处理建议」筛选和数量徽章。
- **A2，规模化：** 批量操作中的「接受建议关联」，以及 `/knowledge-admin` 上的重新扫描。
- 验证：在真实 PostgreSQL 上测试知识 HTTP API（匹配规则、歧义、生命周期、治理拒绝、跨组织隔离、撤回、忽略记忆）；页面级界面测试；知识库验收用例覆盖 导入 → 建议 → 接受 → 定义相关知识。对治理边界做一次独立审查。

### 功能 B — PDF 页级引用（一个 PR）

- **B1，索引中的页码：** 提取时保存页偏移；分块页码范围；已有 PDF 的一次性重新提取和重建索引；`/knowledge` 搜索结果显示页码。
- **B2，引用中的页码：** 小泽引用的标签和链接；新日志运行记录页码并在报告中显示；条目详情「打开第 N 页」及修订固定（R18、R20）。
- 验证：针对多页 PDF 的提取和分块测试；知识 HTTP API 覆盖搜索页码和固定修订的引用；引用及「打开到该页」操作的界面测试；验收用例覆盖 搜索 → 打开到该页。`/knowledge` 和日志报告在 1440x900 下检查。

## 延后

由 Agent 辅助关联（需审批）；新建议的通知；显示名称或模糊匹配；印刷页码标签；DOCX 页码估算；内嵌 PDF 查看器。
