- [模块结构导入](../../../../src/components/parameter-admin-next/ModuleStructureImport.tsx)及其[提交服务](../../../../server/modules/parameter-governance/moduleStructure/apply.ts)可提供预览、确认、重新校验和幂等重放的实现参考；其数据表和业务语义仍属于参数领域。

## 决策树与范围

模板 → 偶尔批量且不超过 500 人 → 一个组织 → 已启用本地账号 → 账号资料与组织角色 → XLSX → 填写密码且不强制改密 → 预览及整批确认 → 无密码结果导出、不做历史页面。Q1–Q16 已收敛产品分支；Q17 已确认完整方案及以下技术默认值。规划决策已全部收敛，后续 `/implement-spec` 请求已授权开发。

不包含邀请、OIDC、CSV、跨组织文件、更新/恢复/调动已有账号、团队/项目/评审职责分配、密码生成、通知、表格在线编辑、批量撤销和后台任务管理。修改原始文件后重新预检。成功后的账号调整使用现有管理功能，不自动批量删除来“撤销”。

不新增 ADR：现有成员接纳、身份和组织边界不变。批量行为的理由记录于本方案，已确定术语写入 `CONTEXT.md`。

## 用户流程

1. 在 `/organization/members` 单人创建入口旁增加“导入用户”，全程显示选定组织。要求既有管理员权限及本地认证；暂停或只读组织不能发起。服务端独立执行相同约束。
2. 下载模板、填写数据页并选择 XLSX。在浏览器解析，将结构化行提交预检；选择文件不会创建账号。
3. 预览原表行号、规范化用户名、姓名、职务和角色；展示总数、所有可确定的逐行/字段问题及管理员权限人数，不设密码展示列。工作簿不可读取时展示文件级错误，不声称已检查全部行。
4. 任意错误禁用创建。可下载无密码错误清单，修改原文件后重新上传。预览无误后启用“确认创建 N 位用户”；文件或目标组织变化使预览失效。
5. 提交时锁定本次输入和组织，防止按钮重复提交。成功后显示组织、批次编号、创建人数及逐行结果，刷新成员列表并提供结果下载。确定回滚时说明创建 0 人；响应丢失时显示“结果尚未确认”，恢复原批次结果。

确认前取消仅清理草稿。提交后关闭弹窗或断网不保证取消。刷新后可按非敏感批次编号恢复最近待确认结果；查不到回执仅表示尚未确认，原请求仍可能执行中。不能因结果不明就自动新建批次。

## 模板与校验

生成“用户数据”“填写说明”和明确标注为虚构的“填写示例”工作表。只读取名为“用户数据”的表，不依赖标签顺序。下载文件名可带 `v1`，允许用户改文件名。输入单元格预设文本格式；说明密码私下交付，以及结果清单不能代替含凭据的原始模板再次导入。

| 中文列名 / API 字段 | 计划规则 |
| --- | --- |
| 姓名 / `name` | 必填文本，去首尾空白，1–100 字符 |
| 用户名 / `username` | 必填文本，复用去首尾空白并转小写规则；3–64 字符，仅 `a-z`、数字、`.`、`_`、`-`；预览规范化值 |
| 初始密码 / `password` | 必填文本，8–1024 字符；完整保留空白和前导零，不 trim，不静默转换数字单元格 |
| 职务 / `title` | 可选文本，去首尾空白，至多 100 字符；空白沿用现有默认值 `User` |
| 组织角色 / `roles` | 必填现有中文角色名，用 `；` 分隔；逐项去首尾空白并去重，空段或未知角色报错 |

复用当前界面角色名和角色 ID。说明页列出操作者可授予的角色；手工修改文件仍需服务端授权。多个角色叠加既有权限，不授予项目参与或评审职责。

计划采用的导入专用限制：XLSX 至多 2 MiB，1–500 个非空数据行，数据表物理行数至多 5,000，每次预览/确认 JSON 请求至多 4 MiB。不改变单人创建字段上限。必须具备五个指定表头，顺序可变；缺失、重复或未知非空表头均报错。忽略全空行，校验部分填写行，保留物理行号；隐藏或筛选掉的数据行也参与导入。拒绝输入区域合并单元格、公式（即使有缓存值）、数字/日期/布尔值、加密或损坏文件、不支持的类型及过大范围，不静默截断。

复用 `xlsx`，不复用参数解析器。调用其工作簿读取器前，用已安装的 `jszip` 校验 ZIP 结构并累计流式解压的实际字节数：至多 256 个条目、单条目 8 MiB、合计 32 MiB。触及上限即停止，不信任 ZIP 声明大小，不用无界 `Promise.all` 解压全部条目，不自写 ZIP 解析器。这在 XLSX 解析前拦截过大的共享字符串和不参与导入的工作表；解析后检查行数不能防止解压耗尽。随后检查声明及实际工作表范围并明确报错，不能静默截断。

API 接收 JSON 而非工作簿 ZIP，独立校验行数、长度、角色和未知字段。不执行公式、宏或外部链接。结果中的用户文本以字符串单元格输出，不带公式或超链接元数据。

## API 与原子创建

计划端点沿用既有操作组织查询参数约定：

| 端点 | 行为 |
| --- | --- |
| `POST /api/v1/users/imports/preview` | 只读校验、用户名冲突检查，返回不含密码的预览、错误和令牌 |
| `POST /api/v1/users/imports` | 提交行、预览令牌和客户端生成的批次 ID，整批原子创建 |
| `GET /api/v1/users/imports/:importId` | 原操作者在目标组织权限范围内查询已提交结果，不提供历史列表 |

具名导入路由优先于通用用户 ID 路由注册。服务端要求本地认证、可信用户发起上下文、`users:manage`、目标组织和角色授予权限；拒绝请求体覆盖组织、项目角色及客户端密码哈希。预览令牌仅用于一致性检查，不构成权限。其非敏感投影包含操作者、组织及生命周期版本、规范化行和角色；明文密码不进入公开令牌或普通持久请求摘要。提交时再次校验密码；文件变化时浏览器使预览失效。

1. 检查传输限制、批次 ID 外层结构、当前身份与目标访问权限，以及非敏感意图比较所需字段；尚不要求已提交操作具备新鲜预览，也不重验其密码或授予权限。
2. 在新用户冲突、预览新鲜度、密码校验及哈希之前查询已提交回执；有权限的重放直接返回原结果。只有新批次继续完整的行、密码、角色授予和预览校验，并通过白名单结构返回所有可确定的问题。
3. 在数据库事务和管理员锁外使用现有加盐 scrypt helper 计算全部密码哈希，初始并发限制为 4；明文仅保留于请求内存。
4. 在一个事务中沿用管理员及生命周期锁顺序，重读操作者启用状态、角色/授予权限、所属与操作组织关系、目标组织状态。对批次 ID 串行化并再次查询回执。
5. 重算非敏感预览投影、检查全局用户名占用，写入所有用户、凭据、组织角色、逐用户审计和批次回执。既有用户名唯一索引仍防御注册/邀请等路径的并发冲突。
6. 只提交一次。凭据、角色、审计、回执或约束任一失败，整批回滚。必要时回滚后将用户名竞争转换为安全的逐行错误，不泄露其他组织或成员详情。COMMIT 响应丢失进入结果恢复，不误报已回滚。

从现有单人创建中提取最小内部准备/写入步骤，让单人和批量共用规则及审计；HTTP 永不接受哈希。不能循环调用单人 HTTP API，也不能持有全局锁计算 500 个密码。保持单人 OIDC 行为；不借用参数领域表，不建立通用导入框架。

## 安全重试与数据留存

每次创建意图生成随机批次 ID，绑定原操作者和目标组织。标签页会话存储只保留最近待确认批次的非敏感定位信息，不保存行、文件或密码。前一结果明确后，修改后的源文件对应新创建意图。

在账号创建事务内增加用户领域的最小回执：ID、操作者、组织、时间、计数、非敏感意图摘要，以及原行号到已创建用户 ID 的映射。稳定摘要包含请求的规范化非敏感资料、身份与作用域，不包含操作者当前权限、组织生命周期版本或预览令牌；这些可变事实只属于预览及当前授权检查。同一 ID 的非敏感内容不同则拒绝；相同 ID 的并发请求串行化。已提交 ID 永远返回原创建结果：重放中的密码不会再次应用，也不会重置用户密码。改密码属于新意图，不是重试；此时已有用户名正常报冲突。明确采用“首次提交结果有效”，避免仅为比较重试而保留明文或可快速验证密码的摘要。

不存在已提交回执表示“尚未确认”，不证明失败。刷新后的查询不需要密码。需要重放时，使用相同待确认 ID 重新选择原文件；查已提交结果优先于预览及新账号冲突检查。查询结果也重验当前权限；其他操作者、其他组织或已撤权管理员不能仅凭 ID 读取结果。

最小回执随组织生命周期保留，不做历史页面，也不设置可能导致意外重新创建的幂等过期窗口。当前姓名/用户名经授权用户查询获取；已删除用户保留历史 ID，重放不重新创建。新表必须纳入组织删除清单及清理，沿用操作者删除后的归属展示约定，保留其他组织回执。回执不保存原始单元格、重复用户名、密码哈希或工作簿。

错误、预览、审计、日志、遥测、快照和下载使用字段白名单。密码错误仅含行号、字段和规则，不携带原值 `received`、请求体或整份请求摘要。持久密码哈希只在现有凭据表中。完成后清理草稿/请求引用，不承诺 JavaScript 内存物理清零。

结果工作簿包括原行号、可用时的用户名、状态、错误字段和修正建议，以及批次/组织上下文，不含密码列。整批被阻止时，合法行显示“未创建：整批校验未通过”，不能显示成功。它是报告，不是可替代原文件的导入模板。

## 验收与验证

| 用例 | 必须观察到的结果 |
| --- | --- |
| A1 模板 | 空模板不创建；说明及示例不参与；标签顺序、原行号和密码/文本保真正确 |
| A2 正常批次 | 不同角色账号启用并可用填写的密码登录；不强制改密，不分配团队/项目 |
| A3 校验 | 一次展示全部可确定的缺失、非法、重复字段；拒绝公式/非文本；创建 0 人 |
| A4 冲突 | 文件内规范化重复和任意组织已有用户名阻止全部行；已有资料/密码/角色不变 |
| A5 限制 | 1 和 500 行成功；0、501 及超限字段/文件/请求/范围失败，不截断；ZIP 条目及实际解压大小限制在 XLSX 解析前拒绝过大的共享字符串和被忽略工作表 |
| A6 权限 | 非管理员、伪造作用域、跨范围查回执、普通管理员授予平台权限均失败；平台管理员可显式选择其他正常组织 |
| A7 过期状态 | 操作者撤权/调动/禁用、组织暂停/删除、预览后用户名被占用都不能绕过最终检查 |
| A8 回滚 | 在部分用户及凭据/角色/审计/回执写入后注入失败，所有新账号和成功审计一起回滚 |
| A9 重试 | 双击、同 ID 并发、响应丢失、刷新和重放只创建一批；过期预览不阻断已提交结果恢复；非敏感内容变化拒绝；重放不改密 |
| A10 凭据 | 预览/错误/审计/日志/回执/下载/会话存储无密码或快速密码摘要，导出文本不作为公式 |
| A11 生命周期/回归 | 回执清单及组织删除保留其他组织数据；删除用户/操作者后不能通过重放重建；单人创建、改密/重置及 OIDC 行为不变 |
| A12 浏览器 | 真实本地认证 API、1440×900：模板、错误预览/导出、正确确认、结果导出、新用户登录、结果恢复及操作证据 |
| A13 容量 | 记录真实 API/PostgreSQL 的完整 500 人耗时和锁占用；宣称目标环境支持前核对实际代理及超时 |

2026-11-07 本机使用现有 `hashLocalAccountPassword`、虚构输入、并发 4 执行 500 次哈希，耗时 **2,489 ms**。未创建用户、连接数据库或发 HTTP 请求。这支持从有界同步命令起步，不是端到端或目标环境性能验收。交付前测量完整请求及其他管理员操作响应；若目标无法容纳 500 人，应明确重新讨论执行方式，不静默降低行数或部分提交。

实施时运行 `npm run test:impact -- <changed-files>`，检查两项回退标志，执行所有选定原生门禁。保留用户/认证定向测试、工作簿回读/错误测试、真实 PostgreSQL 回滚/并发测试、类型检查/构建、API/OpenAPI 检查，以及隔离 `WISEEFF_RUNTIME_LANE` 下的浏览器命令。既有 `PERM-USER-MGMT-001`/`ORG-OPERATING-LIFECYCLE-001` 仅为回归参考，不能代替批量证据。一次独立审查覆盖权限、租户、凭据、迁移/删除及并发；在获授权的 PR 中记录准确命令、数量和环境。

实施进度记录在 [PR #1535](https://github.com/tzrea1-Q/WiseEff/pull/1535)。工作簿、真实 API/PostgreSQL 及本地认证浏览器定向验证已覆盖预检、原子创建、重试和结果报表。完整候选回归、独立审查及页面效果确认仍为交付门禁，PR 记录当前命令、数量和代码版本。规划阶段因数据库不可达而跳过的 schema 检查，现已由一次性 pgvector PostgreSQL 验证补齐。本机真实 500 人请求耗时 3.2–3.3 秒；不宣称已具备目标部署或代理验收证据。
