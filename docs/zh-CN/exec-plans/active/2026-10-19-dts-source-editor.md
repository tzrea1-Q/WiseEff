## 目标和范围

以当前选中的完整 DTS 文件作为编辑对象。工作台只保留一个源码编辑器、预览／编辑切换和保存修改入口。字符串、数组、引用、注释和节点结构直接在源码中修改。左侧继续只显示组织已登记模块及其实际 DTS 父模块；过滤导航不裁剪源码。

本方案包含注释、排版、未登记属性、节点新增和删除的保存能力，不限于已绑定参数的值。保留组织参数定义和稳定的 Binding 身份；项目源码编辑不修改全局 Definition 名称。身份延续不明确或引用无效时，阻止应用并解释具体原因。

一次保存一个文件，继续使用当前 2 MiB UTF-8 字节上限、配置文件成员关系和文件写入／审核权限。include 与 overlay 在固定配置上下文内校验。新增／移除文件、调整配置成员、发布基线和设备写入继续使用原有独立入口。本轮不加入跨文件原子编辑、多人协作、AI 补全和整文件自动格式化。JSON 流程保持现状。

## 当前代码与必须补齐的能力

| 已确认的实现 | 方案要求 |
| --- | --- |
| `ProjectPrimaryDtsViewer.tsx` 为每行生成 DOM，滚动时扫描行元素 | 它是查看器。在本工作台接入编辑引擎，不在现有 DOM 上直接开启 contentEditable。 |

| `canonicalFileWorkflow.ts`、`canonicalSource.ts` 只证明固定参数位置的精确修改 | 注释、排版和未绑定内容需要明确的整文件请求类型；旧操作保留原证明规则。 |
| `ingestService.ts` 的 sourceCommit 要求节点集合不变且不能创建逻辑身份 | 整文件修改需要携带已审核身份延续方案的独立导入模式。 |
| 当前请求只有 single／batch，迁移 0165 要求 batch 至少两个目标 | 纯注释变更必须支持零参数目标，不能伪造 Binding 或放宽原 batch 约束。 |
| `sessionDraftStorage.ts` 明确只存属性补丁 | 保持旧格式兼容，整文件草稿使用独立、按用户和项目隔离的存储。 |
| `parser.ts` 会容忍部分未知值形式 | 索引成功不代表语法或编译通过。保存必须复用配置解析、当前工具链和 Definition 校验。 |

遵守 [ADR-0046](../../design-docs/adr-0046-source-occurrence-identity-spans-dts-and-software-configuration.md) 的来源与 Binding 身份约定，以及 [ADR-0034](../../../adr/0034-referenced-property-key-rename-is-a-source-cutover.md) 的全局属性名变更约定。实施时记录整文件请求的新契约，不重新解释既有 single／batch 请求。

## 用户界面和交互

源码顶部显示文件名／版本、预览／编辑切换、草稿状态、保存修改和放弃修改。右侧默认收起，只放只读参数定义与诊断。替代保存链路完成后，移除本 DTS 工作台的类型输入表单和宽编辑弹窗；其他页面使用的共用组件继续保留。

| 操作 | 明确行为 |
| --- | --- |
| 打开文件 | 默认预览。有兼容本地草稿时恢复并明确标记；否则显示当前来源。 |
| 切到编辑 | 开启同一个编辑器的写入能力，保留选区、滚动、折叠和撤销记录。 |
| 切回预览 | 当前缓冲区只读，粘贴、拖入和替换命令也不能写入。保留搜索、复制、折叠；不重新加载服务端文本。 |
| 输入内容 | 立即显示未保存；语法错误和未完成文本仍可编辑、恢复。 |
| 保存修改或 Cmd/Ctrl+S | 固定本次文本快照，校验后进入现有确认／审核界面并显示完整差异。没有差异就不创建请求。 |
| 校验失败 | 保留文本和撤销记录，编辑区下方显示问题；有位置时可点击跳转。 |
| 提交成功 | 显示待审核并链接现有请求，不显示已更新工作配置。活跃版本不变时仍可查看提交文本。 |
| 审核应用完成 | 刷新服务端文件、版本和导航。只清理与应用回执完全匹配的本地快照，后续输入继续保留。 |
| 切换文件、离开或刷新 | 及时持久化并按范围恢复。持久化失败或尚未确认时，离开前提示，不能宣称一定可恢复。 |
| 放弃修改 | 仅在有修改时确认，回到已明确加载的基线；放弃本地草稿不等于撤回已提交审核。 |
| 历史、候选、对比视图 | 保持只读，返回工作文件时恢复编辑会话。 |

保存只使用一个紧凑对话框：源码差异、参数／结构变更数量、必要的修改原因和审核人，再按服务端流程显示确认更新或提交审核。存在冲突的参数草稿时，阻止提交并链接原有处理流程；不自动覆盖，也不在编辑器里增加一套冲突选择矩阵。

## 编辑器与草稿实现

采用 CodeMirror 6，以一个 React 组件直接封装，在工作台路由按需加载。当前仓库没有编辑引擎。复用搜索、撤销重做、行号、括号匹配、选区、可视区域渲染和动态只读配置。只新增必要的 CodeMirror 包，不再加入 React 包装库或编辑器框架。参考官方[只读示例](https://codemirror.net/examples/readonly/)、[可视区域接口](https://codemirror.net/docs/ref/#view.EditorView.viewport)及[基础扩展](https://codemirror.net/examples/basic/)。

实现小范围 DTS 高亮适配，覆盖注释、字符串、数字、标签／引用和指令；高亮不负责语义校验。折叠范围必须识别注释和字符串中的括号。需要解析范围和导航时，在 worker 内复用现有 DTS lexer/parser，不能把数据库或服务端依赖带进浏览器，也不另写一套权威解析器。首个编辑器包通过构建确认此边界。

文档和撤销记录由 CodeMirror 管理；React 只管理文件范围、模式、修改／提交状态及候选／请求编号，不随每个字符复制整份文本。草稿持久化和局部范围分析采用防抖，过期文档版本的异步结果丢弃。只在持久化或保存时序列化全文。长数组默认不自动换行，换行显示不改写数组内容。

文件草稿记录如下：

```text
scope：userId、organizationId、projectId、configSetId、fileId
base：fileVersionId、configRevisionId、sourceDigest
content：sourceText、编码／换行元数据、updatedAt、generation
position：选区、首个可见行
submission：candidateId?、requestId?、submittedDigest?
```

使用浏览器原生 IndexedDB 异步保存全文，每个范围内的文件保留一份当前草稿和固定基版本。不把数 MiB 文本放进旧的同步 localStorage 属性草稿。写入失败或超配额时保留内存文本，明确显示无法恢复，并提供下载草稿。存储事务核对 generation，避免两个标签页静默覆盖恢复副本。账号或组织切换不得读出其他范围的草稿。刷新恢复文本和位置，不承诺跨刷新恢复撤销栈；同会话模式／文件切换保留撤销记录。

数字原始 token、空／重复字符串、分组、`/bits/`、引用参数和注释直接保留，不经过 JS Number／JSON 重建，不在保存时自动格式化。保留受支持 UTF-8 BOM 及统一 LF／CRLF；若编辑器需统一混合换行，必须在提交差异中体现，不能默默转换后宣称字节保真。应用和下载内容必须等于用户确认的序列化缓冲区。

导航使用编辑事务映射已有源码范围，避免插入几行后仍跳旧行号。输入暂停或主动校验后重建草稿定位；语法失败时保留最后有效映射并标记状态。删除／歧义目标不能跳到无关代码。草稿新增导航仍按组织已登记模块过滤，不能重新展开完整 DTS 树。审核应用后刷新正式导航。

## 服务端接口和存储契约

扩展现有候选创建接口。编辑器请求增加明确的 `intent=source_revision`、`expectedCurrentVersionId`、`expectedConfigRevisionId` 和 `clientMutationId`；旧上传调用保留兼容契约。服务端在接受候选前核对权限、文件／配置归属、成员关系、大小和两个版本，并持久化该基线，不能以最新版本替代。

在现有候选来源预览、提交审核接口中增加整文件分支。参数影响、身份延续、权限要求和阻断原因均由服务端推导，客户端不能指定可信映射或绕过审核。诊断可用时返回文件／行／列，否则返回文档级原因。预览显示全文差异、受影响已登记参数、未登记内容变更、节点增删和跨成员文件引用影响。大差异采用上下文片段和编辑器渲染，不为全文每行建立独立 React DOM。

新增迁移，为现有审核请求头增加 `request_kind=source_revision`。保留 single／batch 约束和历史。严格的来源上下文记录文件／配置／基版本、候选与内容摘要、固定成员版本、目录／登记版本、现有 Binding 当前值及已审核的身份／影响方案。受影响的既有 Binding 可复用关系型 targets；新增 occurrence 计划和零参数变更在应用前保存在类型明确的来源上下文。不能为了复用 batch 分发而伪造旧 batch 字段。

同步更新归属约束、不可变快照／回执约束、角色授权、审核分发、差异读取、收件箱／历史、待审核判断和就绪检查。修改前搜索全部 single／batch 分支；尚不能识别新类型的读取者必须明确拒绝，不能按 single 处理。升级测试从已有 single／batch 历史出发，证明旧行为不变。

候选创建和审核提交采用按范围隔离的幂等键。同键同内容返回原结果，同键不同内容冲突。待审核请求固定不可变候选；继续编辑生成新的本地 generation，变更已提交内容需要经现有撤回和重新校验流程。首版每个配置集只允许一个待审核整文件请求，避免完整配置证明互相覆盖；保存对话框直接链接该请求。

## 校验、审核和原子应用

1. 固定提交文本、两个基版本和幂等键，检查 UTF-8 字节大小；创建候选但不改变活跃文件、值、导航和成员关系。
2. 在固定成员快照中替换这一个文件，使用原入口、include 搜索路径、overlay 顺序及工具链解析完整配置。如实报告编译结果；不可用或关闭不能显示为通过，应用前满足当前有效校验策略。
3. 在只读准备过程复用匹配和身份延续逻辑，计算语义影响。将结果与准确候选摘要、目录上下文固定；预览不创建活跃 Binding 或值。
4. 审核准确源码差异和影响。提交及应用时重查角色、指定审核人、自审限制、敏感节点、文件／配置／Binding／目录漂移和草稿冲突。沿用当前管理级文件写入权限，不默默向所有参数编辑者开放整文件修改。
5. 候选内容使用现有对象存储；文件版本、配置修订、结构 occurrence、Binding／值／来源 pin、历史、审计和批准回执在数据库事务中一起生效。对象存储不属于 PostgreSQL 事务：失败最多留下可由现有清理流程回收的暂存对象，不得留下活跃的半成品版本。
6. 重新读取／解析新来源，核对冻结影响，返回服务端权威版本／配置／审核回执。重复批准返回已验证的原回执；失败回滚活跃关系数据并保留候选和本地文本。

| 修改类别 | 应用规则 |
| --- | --- |
| 仅注释／排版，零参数变更 | 允许审核；推进文件／配置来源和相关 pin，参数业务值相等。 |
| 已登记属性的值 | 按固定 Definition 校验，并审核 include／overlay 造成的全部有效值变化；Binding 身份保持。 |
| 未登记属性或节点 | 保留全文并检查结构／引用；不自动创建组织 Definition，不进入未登记导航。 |
| 新增节点／属性且匹配已有登记 | 准备阶段固定匹配关系，通过审核才由既有模块创建 occurrence／Binding；登记变化时重新校验。 |
| 删除节点／属性 | 先看完整配置最终结果：下层属性重新生效时审核其实际值；确实消失时保留历史，记录关联旧 occurrence 和新修订的明确缺失／墓碑证明，不能删除历史或伪造旧位置。 |
| 节点移动／重命名 | 只有明确的延续证据才保留身份；歧义时阻止应用并指出问题，不能按行号或显示名猜测。 |
| 修改引用／include／compatible | 评估完整固定配置集和全部相关已登记值；引用不完整、依赖不在成员内、身份影响不明确时阻止应用。 |

导入增加携带冻结延续方案的已审核来源模式。保留原 sourceCommit 的节点集合保护，不能绕到会静默创建映射的无限制导入入口。纯源码变化若因当前数据模型需要产生新的值修订，标为来源派生更新，而不是业务值修改。

## 验收与性能

全部使用构造样本，不需要部署机项目。分成大文件无绑定样本和真正注册／绑定的配置集两类，分别证明编辑性能和审核应用。

| 用例 | 必须结果 |
| --- | --- |
| 20／200／2,000 项字符串与数组，另含超长单行 | 直接粘贴、编辑和撤销，无逐项输入矩阵，空串／重复／转义／分组保留。 |
| `/bits/ 64`、大于 2^53 数字、字节、重复和带参数引用 | 源码 token 在编辑、审核、应用、下载、重新导入之间一致。 |
| 语法错误、未完成值、无效引用、已登记值越界 | 定位明确，不写活跃数据，本地输入保留；索引器容错不算校验通过。 |
| 仅注释／空白 | 零目标审核可应用，业务值不变。 |
| 节点／属性增删、overlay 回退 | 影响完整、身份／历史一致、过滤导航正确刷新。 |
