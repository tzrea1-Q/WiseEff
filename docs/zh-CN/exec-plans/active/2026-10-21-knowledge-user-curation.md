# 用户自管知识

> English: [English](../../../exec-plans/active/2026-10-21-knowledge-user-curation.md)

状态：设计已于 2026-10-21 敲定（拷问式设计会话，三轮，所有建议均被采纳）；尚未实现任何切片。规格：[#1324](https://github.com/tzrea1-Q/WiseEff/issues/1324)。每个切片基于最新 `main` 单独提交一个 PR。

## 授权目标

用户自行策划的知识成为与沉淀、Agent 草稿并列的一等来源：用户可单个或批量上传 Markdown、文本、PDF 和 Word 文档，批量管理，并能在发现面找到该工作流。每个消费模块都通过同一契约使用这些知识（[ADR-0049](../../design-docs/adr-0049-knowledge-scope-is-an-explicit-binding-or-the-organization.md)）。

起点：`/knowledge` 已支持单条 Markdown 编写和单文件上传（PDF、DOCX、TXT、MD；20 MB），但该工作流在发现面隐藏（ADR-0036），上传一次只能一个文件，上传的 `.md` 被存为不可编辑的文件型条目。

## 决策

| 编号 | 决策 |
| --- | --- |
| K1 | 目标是可发现、可批量管理、由用户策划并经同一契约消费的知识来源——不是新建上传系统。 |
| K2 | 在管理类切片落地后，以把 `knowledge` 加入 `VISIBLE_WORKFLOWS`（S4）作为收尾。模块集成（S5、S6）可以在上线之后进行。 |
| K3 | 不设单独的"用户知识"类别。**知识来源方式**（手动编写 / 上传 / 沉淀 / 小泽草稿 / 技能包导入）是面向读者的来源信息；是否可检索只由发布决定。 |
| K4 | `.md` 和 `.txt` 上传成为可编辑的 Markdown 型条目；PDF 和 DOCX 保持文件型。两个上传入口（`/knowledge`、技能工作区）行为一致。 |
| K5 | **知识导入**：多个文件或一个 `.zip`；每个文档成为一条草稿；文件夹名成为标签，绝不形成层级；每批上限 200 个文件、100 MB，单文件 20 MB。 |
| K6 | 格式保持 PDF、DOCX、TXT、MD。没有可提取文本的文件显示为不可检索，绝不显示为成功。 |
| K7 | 所有已发布条目对整个组织可见。受限知识留作以后的独立决策。 |
| K8 | 人工上传沿用轻量 wiki 式治理：所有者发布自己的条目；批量发布仅覆盖自己的条目，除非拥有 `knowledge:manage`；只有 Agent 草稿进入审核队列。 |
| K9 | 统一集成契约：仅已发布、组织隔离、引用固定修订、如实报告检索模式。消费方之间只在**知识范围**上不同。 |
| K10 | 纳入的消费方：小泽、分析技能、参数目录定义、DTS 重载与节点调试。项目配置、审计和管理页面不在范围内。 |
| K11 | 小泽始终在整个组织内检索；打开它的页面永不收窄检索。 |
| K12 | 技能绑定显式条目身份；"添加所有带 X 标签的条目"只是选择器快捷方式，展开为条目身份。 |
| K13 | 没有绑定条目的技能保留组织通用回退，并如实报告。 |
| K14 | 定义只展示被显式引用的知识（不做相似度推荐）；也可以从定义页添加引用。 |
| K15 | 导入不识别参数名、不推荐引用（延后）。 |
| K16 | 调试界面从其参数定义绑定推导相关知识；不新增绑定，没有定义时不显示；本计划中节点调试不作为沉淀来源。 |
| K17 | 导入从不覆盖：字节完全相同的文件跳过并报告；内容有变化则成为新草稿；更新已有条目仍需在单条目上显式替换文件。 |
| K18 | 导入可以在文件夹标签之外附加整批标签。 |
| K19 | 已有的文件型 `.md` 条目保持原样，不做转换迁移。 |
| K20 | 定义引用仍归条目所有：从定义页添加需要能治理该条目（所有者或 `knowledge:manage`），因此选择器只列出调用者能治理的条目。 |
| K21 | 调试界面在每个重载运行参数上、以及调试节点详情中展示只读的相关知识列表。 |
| K22 | PDF 页级引用延后。 |
| K23 | 批量导入只在 `/knowledge` 提供；技能工作区保留单文档上传。 |
| K24 | 已归档的绑定条目在绑定界面中保留并显示"已归档，不参与检索"；彻底删除仍允许（`knowledge:manage`，有审计），留下悬空身份并显示"已删除"；已完成运行的来源记录永不改写。 |

## 不变量

- 所有消费方都遵守仅已发布检索，导入结果也一样：导入的条目在发布前都是草稿。
- 组织隔离覆盖条目、修订、文件、分块、向量、来源方式和所有绑定。重复检测只与导入者可读的条目比较，绝不暴露他人的草稿。
- 每次创建、发布、归档、标签变更和引用变更都是在独立事务中完成的带审计写入（ADR-0027）；批次额外写一条汇总审计，绝不替代逐条审计。
- 批量操作逐条授权并逐条报告结果；单条被拒或失败绝不回滚或悄悄跳过其他条目。
- 压缩包约束：`.zip` 绝不能绕过路径穿越、条目数、解压后大小或嵌套层数限制。

## 切片

### S1 — 可编辑上传、如实提取、来源方式

- `/knowledge` 上的 `.md` / `.txt` 上传创建 Markdown 型草稿（要求 UTF-8；编码无效时明确拒绝；沿用现有 200 000 字符的 Markdown 上限）。PDF 和 DOCX 不变。
- 提取结果为空时记为失败（"无可提取文本"），条目显示为不可检索。已有的提取文本为空的文件型条目通过 `/knowledge-admin` 索引健康（零分块）呈现，而不是改写数据。
- 创建时持久化知识来源方式；技能包导入路径记为"技能包导入"。如实回填已有数据：Agent 来源 → 小泽草稿；有来源日志或重载运行 → 沉淀；文件型 → 上传；其余 → 手动编写（此前的技能包导入无法区分，保持手动编写）。
- 界面：条目列表增加来源方式列和筛选，条目详情显示来源方式徽章。
- 验证：在真实 PostgreSQL 上验证迁移和回填；服务层测试覆盖转换、编码拒绝和空提取；聚焦的界面测试；`/knowledge` 1440x900。

### S2 — 知识导入

- `/knowledge` 上的"批量导入"：选择多个文件或一个 `.zip`，可选整批标签，随后显示进度视图和导入报告（已创建 / 重复已跳过 / 不支持已跳过 / 提取失败），每行链接到对应草稿。
- 文件逐个请求提交，沿用现有单文件限制、审计和提取路径，进度自然可见；`.zip` 在服务端经有界压缩包读取器展开，并在批次上限内以相同方式处理。
- 文件夹路径各段成为标签（去空白、去重、限制标签长度）；不支持的类型会被报告，绝不悄悄丢弃。
- 重复检测：对文件字节计算 SHA-256，与同组织内可读条目的文件和 Markdown 源比较。
- 需要 `knowledge:edit`。对 diff 做一次独立审查（上传、压缩包和租户隔离边界）。

### S3 — 批量管理

- 条目列表支持多选，提供 添加标签 / 移除标签 / 发布 / 归档；逐条授权（自己的条目，或拥有 `knowledge:manage` 时任意条目），并给出逐条结果汇总。
- 对授权边界做一次独立审查。

### S4 — 上线

- 把 `knowledge` 加入 `VISIBLE_WORKFLOWS`；按 ADR-0036 更新首页卡片、流程标签和推广文案。
- 合入前在本地运行知识库验收用例，因为 PR CI 不运行浏览器验收。

### S5 — 绑定界面

- 定义详情新增"关联已有知识"：列出调用者能治理的未归档条目，通过现有定义引用 API 写入（K20）。
- 绑定界面（技能知识区块、条目引用编辑器）如实显示已归档和已删除的绑定条目（K24）；只补齐缺失部分。

### S6 — 调试相关知识

- DTS 重载运行：对每个有定义绑定的参数展示只读的相关知识列表，使用仅已发布的 related-to-definition 读取。调试节点详情：对绑定了定义的节点同样展示。没有定义或没有 `knowledge:view` 时不渲染。

## 交互决策（已委托，在此记录）

- 来源方式标签：手动编写 / 上传 / 沉淀 / 小泽草稿 / 技能包导入。
- 导入使用对话框：文件/压缩包选择和整批标签，随后是进度列表和最终报告表；离开页面不会取消已提交的文件。
- 不可检索的文件型条目在列表中显示警告徽章，在详情中给出说明，并提供"替换文件"操作。

## 延后

PDF 页级引用；导入时识别参数名；更多格式（PPTX、XLSX、HTML、OCR）；受限知识；节点调试沉淀；合集；MCP 接入面；Agent 自主维护（去重、过期标记、知识空洞发现）。
