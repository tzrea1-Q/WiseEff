# 长发布历史下的 Markdown 导入与目录激活

[英文版](../../../exec-plans/active/2026-11-25-catalog-publication-cost.md)

## 目标

同一目录、同样一至五项变更，应当在历史版本逐渐增多后仍能快速预览并发布。分别测量当前定义数、目标版本字节数和累计历史字节数。入队、取得发布锁、提交激活回执各自计时。

## 第一批实现

- 有可用的已验证快照时，Markdown 直接对当前目标做规划。对于已有主体上的新增和修订，校验前后两个版本和数据库中的历史身份约束，再写紧凑后继制品。旧库、证据不足及未覆盖的操作走完整编译。冷库连续导入全部跳过的条目，仍可能多次读取历史。
- 逐个检查完整和紧凑制品的物理校验和、前驱连接，将组装好的对象直接交给编译器。激活先结束读事务，再进行 CPU 密集计算。提交时重新核对候选、授权、执行令牌和物理字节校验和。此阶段仍要编译完整历史。
- 一条集合语句写入版本的定义头，一条关联更新恢复当前定义头，跳过当前修订相同的行。其他投影表、触发器和一致性检查仍有随目录规模增长的成本。
- 前端继续观察可重试的任务，终态超时给出明确原因。请求和发布尝试分别记录读取、编译、等锁、物化和提交耗时。用任务及其匹配的激活回执确认发布成功。

## 后续实现

1. **为现有目录一次性建立基线。** 运维任务在一致性快照中锁定并完整验证当前发布，写入前复核发布 ID、摘要和物理字节。对同一基线与编译器版本合并并发预热请求，记录进度，重启后可以重试。覆盖升级后首次导入和连续无变化的导入。
2. **常规激活只处理已验证基线和一个后继。** 持久化编译和安装需要的历史身份、工具链和能力信息。检查点绑定发布 ID、逻辑摘要、物理校验和、编译器契约、验证器版本和物化记录。与完整重放逐项核对摘要、计数、权限所依据的能力、投影和回执。现有编译模型摘要覆盖所有历史版本，保持摘要兼容需要验证增量编码的结果；变更摘要格式则需要独立版本与旧制品兼容策略。
3. **覆盖检查点失效与恢复。** 对授权擦除、重写、契约升级同步失效。验证基线过期、历史缺失或损坏、恢复旧版本、并发发布和晚到回执。对不兼容或存在歧义的输入保留完整重放。缺少检查点触发重建，完整性失败阻止激活；同一任务重试只允许推进一次指针。

## 验收

使用约 5,000 个定义的合成目录，经真实 PostgreSQL 执行预览、入队、发布及回执核对。独立增加历史深度和物理字节，至少覆盖 600 MiB。覆盖冷启动、快照命中、新增、修订、无变化、新主体、并发、提交前后中断和校验和错误。修复前后使用同一台机器，单列首次冷启动，每种代表性热路径至少取 20 个样本。

一至五项常规变更的建议目标为预览 P95 ≤15 秒，点击发布至回执 P95 ≤60 秒，一次尝试完成，每个成功任务仅一条匹配回执。热预览读取历史制品字节应为零，完成检查点改造后热激活也应满足这个条件。同时记录管理器 CPU、峰值常驻内存、数据库等待和读取字节数。绝对耗时需在代表性自托管机器上验收。
