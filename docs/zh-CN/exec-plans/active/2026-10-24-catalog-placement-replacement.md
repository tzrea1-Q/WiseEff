# 组织主体归属的显式替换

状态：实施中。负责人：本次部署归属冲突问题的协调智能体。

English: [Implementation plan](../../../exec-plans/active/2026-10-24-catalog-placement-replacement.md).

## 目标和边界

用户需要修正杂乱的主体与模块对应关系。目标模块可能已被另一条有效或退役登记占用，仅隐藏这些选项无法完成修复。

显式替换将当前主体 A 绑定到所选目标模块，并把原占用主体 B 的 `module_id` 置为 `NULL`（未分配）。A 原来的模块腾空，B 保留登记、放置身份和生命周期。双方的参数、绑定、项目值和历史均不删除、不转移。此操作不自动互换，也不放宽组织与模块的唯一约束。沿用迁移 0209 已有的可空放置语义，不新增数据库迁移，不操作生产数据。

## 实现

- 现有条件 PATCH 增加可选的显式替换信息：B 的登记标识、放置 ETag、登记 ETag 和非空原因；继续使用 A 的 If-Match 与当前目录发布 pin。
- 确认前读取双方影响，识别有效和退役登记的占用。用户必须明确勾选替换、填写原因并最终确认，不在冲突后自动替换。
- 在同一事务中核对组织、当前占用、生命周期和双方版本，统一登记写入的锁顺序；目录 guard 锁保持到提交；保存严格幂等结果，并审计双方归属变化。
- 区分目标已占用和版本过期。预览失效时保留输入，但必须刷新证据并重新确认。

## 验证与交付

编辑期间运行聚焦单元和组件测试。真实 PostgreSQL 覆盖原子性、角色与组织边界、当前发布、版本漂移、重放、并发和完整回滚。1440×900 真 API 浏览器用例修复已占用目标，覆盖失败和取消，并验证刷新后 A、B 的归属。执行影响选择器、生成契约检查、静态检查、生产构建与最终候选原生 CI；授权与并发边界交由独立审查。PR 记录准确结果和目标服务器尚未验证的边界；当前候选真实 Merge bar 和适用审查通过后合入。
