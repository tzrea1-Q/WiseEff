# 用户账号注销

> 状态：功能分支实现完成，尚未合并
> 日期：2026-08-28
> English: [English](../../../exec-plans/active/2026-08-28-user-account-deletion.md)

## 目标

允许有权限的管理员在组织管理中永久删除非本人用户，同时保留业务与审计历史。历史记录中的用户外键在删除后变为 `NULL`；只服务于该账号的安全与临时数据随账号删除。服务端继续负责组织范围、平台超级管理员保护、防自锁和持久审计。

## 验收标准

- `DELETE /api/v1/users/:userId` 仅允许拥有 `users:manage` 的活跃用户调用，目标必须属于调用者的主组织；事务成功后返回 `204`。
- 当前用户不能注销自己；普通管理员不能注销平台超级管理员；不存在或跨组织目标返回 `404` 且无副作用。
- 删除用户、角色绑定、密码凭据、登录会话、待处理本地注册申请、个人通知、活动设备租约和未提交参数草稿。
- 审计与业务历史保留，所有指向被删用户的外键通过 `ON DELETE SET NULL` 变为 `NULL`。
- 同一事务写入 High 级 `user-delete` 审计；仅保留不透明目标 id 和非敏感生命周期事实，不保留姓名、用户名、邮箱、密码或密码哈希。
- `/organization/members` 为可操作行提供“注销”按钮，确认框明确不可恢复及引用置空语义；API 成功后才移除行，服务端拒绝时保留弹窗并显示错误。
- mock 与 API 模式保持相同可见语义，后端授权始终是权威边界。

## 数据保留策略

| 类型 | 删除策略 | 示例 |
| --- | --- | --- |
| 账号专属安全/临时状态 | `ON DELETE CASCADE` | 角色、密码凭据、会话、注册申请、个人通知、活动设备租约、未提交参数草稿 |
| 持久业务/审计历史 | 可空 + `ON DELETE SET NULL` | 审计执行者、提交与评审、调试与 Agent 历史、知识作者、反馈、文件与配置历史 |

迁移 `0117` 必须把所有指向 `users(id)` 的外键收敛到上述两种策略，并由 PostgreSQL schema invariant 测试阻止未来新增 `NO ACTION`/`RESTRICT` 用户外键或不可空的 `SET NULL` 字段。
