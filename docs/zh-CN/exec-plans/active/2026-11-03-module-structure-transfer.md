## 目标与已确认决策

在 `/parameter-admin/modules` 导出当前组织完整结构，在外部编辑 JSON，上传后预览差异、解决冲突，最后一次确认提交。另提供同一部署内复制到其他组织的模式。

| 决策 | 已确认行为 |
| --- | --- |
| Q1 范围 | 业务模块、模块层级、主体登记、归属、展示别名、识别设置；Catalog 定义和驱动对子节点的固有归属只读 |
| Q2 部署边界 | 同一套 WiseEff 内的不同组织；不包含独立部署之间迁移 |
| Q3 格式 | 带版本的 JSON，附单独填写说明，适合人、脚本和智能体编辑 |
| Q4 删除 | 显式标记删除；文件缺少条目不代表删除 |
| Q5 源组织 | 复制成功后保留源组织 |
| Q6 已有目标 | 预览建议匹配，用户确认复用；字段、状态、归属冲突须解决，名称不作为身份 |
| Q7 有内容的模块删除 | 显式处理所有子模块，并为受影响根主体指定新归属或“未设置”；不隐式递归删除 |
| Q8 登记状态 | 支持显式登记、停用、恢复，保留权限、影响确认和驱动子节点联动规则 |
| Q9 并发编辑 | 以导出基准逐字段比较，仅应用外部实际修改；同字段冲突明确选择；预览后目标再变化须重新预览 |
| Q10 跨组织删除 | 源文件的删除标记只表示不复制该模块，绝不删除目标组织的匹配模块 |
| Q11 停用主体 | 完整复制其状态与归属；允许通过受控操作在保持停用的情况下调整归属，不临时激活 |

## 导出内容与 JSON 编辑契约

导出所有当前业务模块、组织内启用和停用的登记、当前归属、别名、显式识别覆盖及其有效值。未分类根和子节点结构作为参照，并保留每个子登记的状态与 `cascade_retired`：它决定以后恢复驱动时哪些子节点应恢复。解释现存引用所需的遗留技术模块、归档行属于只读历史，不重新创建。项目参数值、源码文件、凭据、权限、审计历史及 Catalog 定义副本不进入包。

在一致快照和固定 Catalog 发布版本下读取完整集合，不受页面搜索、筛选、分页影响。返回明确数量，绝不静默截断。复用服务端字节限制，在界面说明支持上限，并验证最大支持规模。超过上限时写入前明确拒绝，不自动拆成多个非原子批次。

以下为 v1 格式示意，S1 固化字段与路由：

```json
{
  "format": "wiseeff-module-structure",
  "version": 1,
  "source": {
    "exportId": "msex_example",
    "organizationId": "org_source",
    "catalogReleaseId": "release_example"
  },
  "modules": [
    {
      "ref": "module_power",
      "sourceId": "pm_example",
      "operation": "upsert",
      "name": "电源",
      "parentRef": null,
      "description": "电源管理",
      "scope": "整板",
      "sortOrder": 10,
      "importance": "high"
    }
  ],
  "subjects": [
    {
      "subjectId": "csub_example",
      "state": "active",
      "placement": { "kind": "module", "moduleRef": "module_power" },
      "displayAlias": "电源控制器",
      "recognition": { "mode": "inherit" }
    }
  ]
}
```

- 同组织现有模块依靠稳定 `sourceId` 定位。新模块不填写 `sourceId`，填写包内唯一 `ref`；父子关系引用 `ref`，改名不会改变身份。
- 删除用 `operation: "delete"`。被删除模块仍被保留条目引用时，整批校验失败，跨组织复制也一样。删除父模块必须移动或逐个显式删除其子模块。
- `placement` 明确区分普通模块、保留未分类根和 `unset`。所属子节点的归属、状态、根展示别名不可独立编辑；其组织识别设置仅按现有领域允许的能力修改。
- `state` 表示根主体期望登记状态，差异编译成预览中明确列出的登记、停用、恢复。缺少主体条目不代表停用；不提供登记硬删除。
- 保留“继承默认”和“显式覆盖”的区别；原样导回不能把有效值变成覆盖值。compatible 数组整体作为一个冲突字段，不自动合并。若现有 writer 缺少清除覆盖能力，补受控重置操作。
- 对已有对象，省略可编辑字段表示不修改；允许清空的字段使用 schema 规定的空值。新对象必须填写必需字段。ID、kind、固有 owner、来源、统计均不是可改写权威字段。
- 严格检查版本、重复 ref/主体、类型、未知可写字段、引用闭包、最终图、同级重名和主体设置。错误定位到 JSON 字段路径；名称只作辅助显示。

填写说明包含字段字典、新增/改名/移动/删除、主体状态与归属、继承、未设置与未分类的区别，以及智能体保留身份、对不确定信息列明疑问的指令。导入时只做确定性解析，不执行文件内容，也不由模型解释。

## 基准、冲突与身份

**同组织更新。** 导出时在服务端保存不可变基准，文件带不透明 `exportId`。不能把可编辑文件里的“原始值”当可信基准。基准只能在获授权的源组织内读取；改文件中的组织 ID 不能改变写入范围。基准不存在时明确拒绝，不降级成覆盖。v1 不设置短期自动过期；基准属于组织产品数据，按组织保留策略处理，不是额外的证据台账。

每个实际提供的可编辑字段以 B=导出基准、F=文件、T=当前目标比较：F=B 时保留 T；T=B 时采用 F；F=T 时无需变更；其他情况必须解决冲突。字段合并后仍校验整棵最终图。并发删除、互相冲突的移动、新增子模块、删除影响变化属于结构冲突；不能按名称重建一个已被删除的 sourceId。

**跨组织复制。** 采用文件中保留的期望结构，不能只应用相对源基准的增量。导入不得用 `exportId` 读取或泄露源组织状态；持有文件不获得源组织 API 权限。Catalog 主体 ID 在本部署内复用，并核对当前发布和 owner；缺失、平台退役或归属不匹配时，不猜测、造主体或偷偷按名称替换。

完整路径只用于建议模块匹配，用户确认后把“包内 ref → 目标 ID”固定到预览计划。新模块生成目标 ID，复用模块保留目标 ID，未分类引用映射到目标保留根。同一个 Catalog 主体在目标只能有一个保留登记：复用该登记，明确解决状态、归属、设置差异，不自动恢复。未提及的目标模块和登记保持不变。

回执保留新建 ID 映射与确认结果。持久保存 `(目标组织, 源组织, exportId, 包内 ref)` 到新建目标身份的唯一映射及首次接受的字段快照。以后即使换请求键、目标已改名，仍复用同一身份；同组织包中新建对象使用首次创建快照作基准。已映射目标被删除时明确冲突，不按旧名称重建。同一请求键、同一内容重试返回已提交回执；同键不同内容拒绝。以后再次有意导入须重新预览，不构成持续同步；无映射条目仍须确认目标匹配。

## 界面流程

在模块管理增加“导出完整结构”“导入结构”和填写说明下载。明确选择“更新当前组织”或“复制到当前目标组织”；醒目显示源与目标，目标取自获授权操作上下文，不由文件指定。

1. 解析校验，展示范围和只读参照，不写领域数据。
2. 分类展示模块新增、修改、移动、删除，以及登记状态、别名、识别设置变化；显示不变项、只读跳过项和受影响主体/项目数。
3. 确认目标匹配并处理冲突。同组织显示“基准 / 文件 / 当前”，跨组织显示“源 / 目标”；选择变化后重新服务端预览。
4. 对每个删除模块列明子模块去向、受影响根登记（包括停用登记）、新归属或显式未设置；同时说明会被取消归属的遗留引用。不隐式删子模块或停用主体。
5. 沿用真人权限与影响确认，填写整批原因。未解决冲突时禁止提交；一次确认后显示含目标、数量和定位链接的持久回执。

不新增审批流。智能体可编写 JSON，但不获得直接执行权。失败重试保留文件与选择；离开未完成导入需确认丢弃。真实 API 浏览器在 `1440x900` 核验流程与键盘操作，存在布局风险时增加一个紧凑 PC 窗口。

## 服务端落点

在现有 Catalog 治理 API 族中提供导出、预览、执行三个操作，S1 同步登记路由、DTO 和 manifest 并接入现有模块管理适配层。导出会保存基准及审计，采用明确 POST；预览无领域写入；执行接收文档、模式、匹配/冲突选择、预览凭据、幂等键和原因。

**事务归属。** 在 `parameter-governance` 内增加专用结构导入协调器，由其私有 UoW 统一调用受控登记 writer、事务内模块写入、识别校验和审计。HTTP 只调用一个公共命令，不外露私有 writer/UoW，不建立通用导入框架。只提取单项入口与批量入口确实共用的事务内逻辑，保留校验和错误语义；Catalog 实体化仍由 Kernel/发布流程负责。

**基准与回执。** 新增组织内导出基准表，以及具备上述唯一约束的持久包内引用映射。现有治理幂等存储若能承载独立命令族及不可变结果则复用，否则仅补必要回执存储。请求指纹绑定目标、身份上下文、模式、文件和明确选择；审计日志不保存上传全文。基准只由服务端导出创建。

**并发。** 复用 Catalog pointer、组织识别、登记和树锁，建立统一且经验证的顺序。实施前列出单项/批量模块写入、登记时新建分类、初始化、识别编辑和影响校验的 Binding/导入路径，让所有冲突写入参加同一协议，把决定正确性的锁前检查移入事务。具体锁序由调用图确认，并用独立 PostgreSQL 会话验证；只锁新导入入口不合格。

#1494 实现采用共享 Catalog pointer → 组织识别 → 组织登记 → 模块树的顺序，再锁登记行。模块增改移删、单项及批量登记和创建分类、种子归属及 M1 种子模块写入均使用该顺序。识别编辑、规范 Binding 写入、DTS 导入及普通项目删除持有组织识别锁；规范 JSON 来源在读写来源前取得该锁。项目彻底删除在锁表前独占 Catalog pointer。模块结构迁移已取得相同的组织锁。历史身份迁移要求维护令牌、写锁确认和快照；质量重置及实验夹具脚本属于运维/测试工具，不是并发运行时入口。SQL 迁移在部署上下文执行。后续应用操作仍须使用相同顺序，并验证其完整写入清单及竞态。

旧上传、文件和基线回滚、候选激活、审核写回及种子平面清理在来源写入前取得识别锁，包括关闭语义导入时。规范来源提交通过治理检查或导入取得该锁；初始化在导入前创建新文件，不替换已计数的版本。

执行先鉴权。可以快速返回已有匹配回执，但在目标复核前，必须在加锁事务内原子占位或重读幂等记录；两个同时到达的相同请求应得到同一回执，不能让后者等锁后误报预览过期。然后重读目标、重建计划并核对预览凭据。凭据绑定目标身份、模式、文档、选择、有关字段/结构版本、登记/识别版本、当前 Catalog 及删除/容量影响；变化则返回预览过期。凭据不是权限。

**写入排序。** 先校验最终图，再创建所需父节点、安排改名/移动、写入登记/归属/别名/识别、处理明确取消归属，最后从叶子向上删除。同级唯一索引即时生效，交换名称或移到即将腾空的路径需要专门执行排序；必要的临时名称/位置仅存在于未提交事务，不进入业务审计。不能关闭约束或提交中间状态。最终检查延迟约束，领域写入、审计、回执一起提交；任一步失败全部回滚。

**治理扩展。** 增加别名编辑/清空、显式取消归属和 Q11 停用期间归属/复制能力，具备版本校验和审计。停用主体始终停用，不能创建新的项目 Binding，不暗中恢复再停用。复制 writer 需要直接创建停用根及其保留子登记/结构归属，并保留每个子项的状态与 `cascade_retired`；现有 `retire-unregistered` 不会创建缺失子登记。子生命周期事实作为经校验的快照进入确认，不成为独立启停命令；保留“父启用、子历史停用且不随父恢复”的情况。若源状态与当前 Catalog/级联规则无法兼容，明确报冲突，不伪造子节点或丢弃状态。识别复制必须重新执行目标项目容量与标识校验；重置继承必须显式。

权限取整批各操作所需权限的交集，不能只用模块的 `admin:access` 放行所有动作。使用可信真人调用和获授权操作组织；完整管理包导出也校验组织设置访问权。来源字段不赋予目标权限；保留审计来源，不触及设备或生产写入。

## 验收案例

1. 原样导出再导入，领域数据零变化，ID、继承、状态不变；页面筛选和分页不影响全量集合。
2. 同批新增父子、改信息、移子树、交换同级名称、显式删除旧模块，最终树正确，无已提交中间状态。
3. 缺条目/字段不删除或覆盖，清空只对允许字段有效；sourceId、包内 ref、主体 ID 不混用。
4. 删除有内容父模块前必须处理全部子模块和根归属；未设置与未分类不同；参数与历史保留。
5. 向非空目标复制支持确认复用和新 ID，不改目标无关数据或源数据，不执行源删除标记。
6. 启用/停用登记、子节点、别名和继承/覆盖设置往返；停用归属编辑不启用 Binding。复制停用驱动后恢复，只有原应随父恢复的子项恢复；保留“父启用、子非级联停用”的状态。不兼容 Catalog/状态明确报错。
7. 不同字段并发修改可合并，同字段差异需选择；并发删除、新增子模块、项目影响变化报冲突；最终图非法则拒绝。
8. 与单项增改移删、登记、识别、来源导入和 Catalog 激活竞态时串行化或报过期，无死锁导致的部分成功。
9. 跨组织 ID、身份伪造、只读用户和 Agent 执行被拒；文件不能读取其他组织基准或绕过权限。
10. 同时重复请求、丢响应重试返回同一回执，同键不同内容拒绝。把首次新建的目标模块改名，再换请求键重导相同文件：复用映射身份，按规则合并或报冲突，不能创建第二个模块/登记或重复原变更审计。
11. 在模块、登记、识别、审计、回执后分别注入失败，用真实运行角色验证全部回滚；基准/回执按组织隔离。
12. 非法版本、重复项、悬空引用、环、保留/遗留节点改写、无效标识、单例冲突均有可定位错误；最大支持包不截断、无无界递归、不拆批部分提交。

使用 `npm run test:impact -- <changed-files>` 并检查 Vitest/browser 两个 fallback。执行所选原生检查；数据库不变量使用真实 PostgreSQL；实现包含 TypeScript/构建门禁；敏感变更做独立审查。单元、PostgreSQL、浏览器、CI 与部署证据分别报告。
