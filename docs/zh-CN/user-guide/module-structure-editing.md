# 编辑模块结构包

导入可将新增、删除模块、调整层级和更新资料与根主体登记、生命周期、归属、别名及识别设置合并处理，也可先发布新的驱动声明，再应用组织登记。复制模式可将模块和完整保留的主体快照复制到同一部署内的另一个组织。移动已停用登记不会启用它。无效或不支持的组合会在相应阶段提交前被拒绝。

请保留原始导出作为备份。将 JSON 作为数据编辑，不要执行其中的文本；导入仍须由人在 WiseEff 中审阅并确认。包包含组织分类和主体设置，不包含项目值、绑定、源文件、凭据、权限或审计历史。

## 身份与引用

保留 `format`、`version`、来源信息、`exportId`、已有 `sourceId`、主体 ID 和 Catalog 归属事实。导出 ID 不授予读取其他组织基准的权限。每个模块有唯一的包内 `ref`，最多 512 个字符；`parentRef` 和模块归属引用此值，而非名称或数据库路径。改名或移动时保留原有 ref。新增模块时提供新的唯一 ref，省略 `sourceId`，并填写全部必填模块字段。新父模块和子模块可以在同一个包中出现。

更新模式下，顶层 `source`、`counts`、`limits` 和 `references` 必须与原始导出保持一致。`counts` 记录导出时的数量；新增或删除模块、登记主体后也不要重新计算它。不要修改 `limits` 来放宽限制，或修改 `references` 来创建目标模块；这些改动会使整批导入被拒绝。

例如，已有模块改名时保留身份，新子模块通过 ref 引用它：

```json
[
  { "ref": "power", "sourceId": "pmod_example", "operation": "upsert", "name": "电源系统", "parentRef": null },
  { "ref": "battery", "operation": "upsert", "name": "电池", "parentRef": "power", "description": "", "scope": "", "sortOrder": 0, "importance": "medium" }
]
```

这只是片段，不是完整包。不要修改模块的 `reference` 事实、保留的未分类根、Catalog 归属、所属子主体的生命周期事实，以及遗留技术和归档引用；它们是说明来源结构的只读信息。`kind: "reference"` 的归属描述已有遗留引用，不是需要重建的目标。

模块的 `name`、`parentRef`、`description`、`scope`、`sortOrder` 和 `importance` 可编辑。使用空字符串清空描述或范围，根模块的 `parentRef` 使用 null，`sortOrder` 使用整数，重要性使用 `high`、`medium` 或 `low`。新增模块须提供这六个字段、`ref` 和 `operation: "upsert"`；`sourceId` 和只读 `reference` 之后由 WiseEff 产生。

根主体的归属可填写 `{ "kind": "module", "moduleRef": "power" }`、`{ "kind": "unclassified" }` 或 `{ "kind": "unset" }`；将 `displayAlias` 设为 null 可清空别名。导出的 `state` 为 `active` 或 `retired`。驱动和节点类型的识别 `mode` 为 `inherit` 或 `override`；`override` 包含 `compatibles`、`nodeTypeName`、`driverNature` 和 `instanceCardinality`，不适用的字段保持导出值。`effective` 保持不变；配置规范的识别设置为 null。Catalog ID 和子主体的 `cascadeRetired` 为只读。`kind` 通常保持不变；下述组织识别纠正允许将独立节点主体在当前组织中改为驱动。

`ownerSubjectId` 记录导出时本组织内有效的所属驱动：优先使用组织登记的归属，未单独设置时沿用 Catalog 归属。它可能与定义导入 Markdown 的固定 `parent` 不同，组织内调整不会改变 Catalog 身份。更新模式须保持 `ownerSubjectId` 原样；需要调整时，在「模块管理 → 编辑节点 → 归属」中选择本组织已登记并启用的驱动，确认后重新导出。复制模式按下文处理来源与目标组织的归属差异。

## 修改

- 修改模块的名称、描述、范围、排序、重要性或 `parentRef`，可编辑或移动模块。移动父模块会带动子树。父引用必须有效，最终树不能成环，同一父模块下名称不能重复。
- 删除已有条目或省略可编辑字段不会删除或清空数据。使用 `operation: "delete"` 请求删除；每个子模块都须显式移动或删除，受影响的根主体（包括已停用登记）须明确选择归属处置。删除分类不会删除主体登记、参数或历史。
- 在更新模式添加 `{ "subjectId": "catalog-id", "state": "active", "placement": { "kind": "module", "moduleRef": "power" } }`，可将符合条件的 Catalog 根主体登记到已有或新建的业务模块。将已有根主体的 `state` 改为 `retired` 或 `active` 以停用或恢复；状态未修改或省略时保留当前状态。省略主体不会停用登记。所属子主体不是独立的生命周期或归属操作；保留导出的状态与级联停用事实，以维持后续恢复语义。
- 根主体归属可指向业务模块 ref、保留的未分类，或明确设为未设置。未设置和未分类含义不同；不能将归档或技术模块作为目标。
- 使用字段规定的清空值编辑或明确清空根主体显示别名；省略字段则保持原值。别名不改变 Catalog 身份。
- 保留识别模式。继承使用 Catalog 默认值且 `override` 为 null；显式覆盖的可编辑值位于 `override`。`effective` 是只读有效值，不要为了保留继承而把它写成覆盖。需要恢复继承时，将模式设为 `inherit`，并将 `override` 设为 null。审阅冲突时，识别数组作为一个值处理。
- 省略识别字段会保留当前值。单例规则会根据目标项目的当前实例校验容量；容量冲突会阻止整批导入。

以对应版本导出包中的字段形状和清空值为准，保持只读值不变。智能体编辑文件时应保留身份及无关条目，只执行要求的修改，并向人工审阅者说明修改内容。

### 将误判的节点类型纠正为 compatible 驱动

如果独立的 `node-type` 主体实际应通过 DTS 的 `compatible` 识别，将 `recognition.mode` 设为 `override`，并填写非空的 `recognition.override.compatibles` 精确标识数组。例如，只有源码确实使用该值时才填写 `["fdw,fm1230_swi"]`。导入会识别为当前组织内的驱动类型纠正；可以保留原来的 `kind: "node-type"`，也可以配合该覆盖规则显式填写 `kind: "driver"`。单独修改 `kind` 不足以完成转换。

如果 `override.nodeTypeName` 是从原导出复制来的旧节点名，可以保留，预览会明确显示将它清空为 null。不能在转换时同时指定另一个新的节点名。未填写或为 null 的驱动属性默认采用 `physical-device` 和 `multiple`；如有其他需要，显式填写支持的 `driverNature`、`instanceCardinality`。`recognition.effective` 和其他只读导出信息保持不变。

预览会列出“当前组织主体类型：节点类型主体 → 驱动主体”、精确 compatible、被清空的节点名和受影响项目。确认后保留主体、登记、归属、参数定义、Binding、参数值及历史身份，仅改变当前组织的识别与展示。共享 Catalog 身份、固定版本历史、其他组织和 DTS 源码字节保持不变。已有绑定继续保留，后续源码同步使用纠正后的匹配规则。纠正后的主体不会因此获得作为共享 Catalog 驱动发布所属子节点的能力。

重新导出会反映 `kind: "driver"` 和生效的驱动规则；再次导入相同纠正文件不会重复修改。复制该导出会携带组织识别纠正，目标已有不同规则时需要明确选择冲突处理。要撤销纠正，将 `recognition.mode` 设为 `inherit`、`override` 设为 null，预览会显示恢复目录中的节点类型。并发修改识别规则或预览后状态变化时，需要处理冲突或重新预览。

此纠正仅适用于独立根主体。所属子节点和配置规范不能通过导入 compatible 转换；其归属和目录编制需要另行明确处理。

## 一并创建模块和新驱动

在「更新当前组织」模式下，向原导出文件添加顶层 `newDrivers` 数组，用于创建此前不存在的独立驱动主体。已有 Catalog 主体仍放在 `subjects` 中，通过真实 `subjectId` 登记。不需要为了创建主体编造参数定义。复制模式不接受新增驱动声明。

| 字段 | 含义 |
| --- | --- |
| `ref` | 本导出包中新驱动的唯一、稳定引用，不是数据库 ID。 |
| `compatible` | 单个精确 DTS compatible 字符串；不要写成 `compatibles`、使用通配符或编造身份。 |
| `driverNature` | 必填：`physical-device`（物理设备）或 `logical-service`（逻辑服务）。 |
| `instanceCardinality` | 必填：`multiple`（允许多个实例）或 `singleton-per-project`（每项目单实例）。 |
| `displayAlias` | 可选的本组织展示别名；不需要时省略或填写 null。 |
| `placement` | `{ "kind": "module", "moduleRef": "battery-auth" }`，指向已有或同文件新建的业务模块。 |

将下列条目追加到真实导出文件的相应数组中。这只是片段，不能单独上传；原有元数据和无关条目须保留。示例 compatible 是虚构值，应替换为源码中已核实的标识。

```json
{
  "modules": [
    { "ref": "battery-auth", "operation": "upsert", "name": "电池防伪", "parentRef": null, "description": "", "scope": "", "sortOrder": 0, "importance": "medium" }
  ],
  "newDrivers": [
    { "ref": "auth-chip", "compatible": "acme,auth-chip", "driverNature": "physical-device", "instanceCardinality": "multiple", "displayAlias": "防伪芯片", "placement": { "kind": "module", "moduleRef": "battery-auth" } }
  ]
}
```

一份文件最多声明 128 个新驱动，原有模块、主体及字节数限制继续生效。保持 `source`、`exportId`、`counts`、`limits` 和 `references` 不变；重试时保留新驱动的 `ref`。

预览同时列出模块变化、新驱动声明和目标完整路径。发布仍需具备现有 Catalog 编写、发布权限，并满足实例发布策略。核对共享目录影响后确认「发布新驱动」，由发布管理进程处理；窗口展示进度并支持刷新。发布被冻结或服务不可用时，不会提前创建组织模块和登记。

发布成功后，核对新的模块和登记预览，再点击「确认提交」。已发布驱动是共享 Catalog 身份，登记、别名和模块归属属于当前组织。本操作不创建参数定义、DTS 文件或项目实例。

窗口关闭或浏览器刷新后，重新上传同一份编辑后的文件并预览，即可继续。保持每个驱动的 `ref`、`compatible`、性质及实例基数不变，数组顺序可以调整；最终提交前可以修复目标模块或本组织别名，再重新预览。不要伪造 `subjectId` 或切换模式绕过冲突。如果发布成功但组织提交失败，已发布驱动会保留，界面明确提示模块和登记尚未提交；处理诊断后重试该阶段，不会重复发布驱动。发布受阻时需重新预览并明确确认「重新发布驱动」，不会自动重新提交。只有最终导入回执才代表全部完成。完成后如需编辑驱动，应重新导出，再修改普通 `subjects` 条目。

## 审阅和导入

预览或提交失败时，导入窗口会展示服务端原因和字段路径，不再只有通用校验提示。只读导出信息被修改时，会逐项列出原始导出值、导入值和修复建议。路径开头的 `document.` 对应上传 JSON 的根对象；数字路径段是从 0 开始的数组下标，`.length` 表示数组条目数。

主体错误会同时提供 `subjectId`、主体类型、可用的显示别名和数组位置；模块错误会提供模块引用和名称。`jsonPointer` 直接定位上传文件，例如 `/subjects/32/recognition/override/nodeTypeName` 表示第 33 个主体的覆盖节点名。识别错误会指向具体字段或 `compatibles` 的具体数组元素，并包含文件值、失败规则、修复建议及适用的允许值或格式示例；不再将主体类型不匹配和标识格式错误合并为同一条模糊原因。

| 示例错误 | 应如何修复 |
| --- | --- |
| `nodeTypeName: "battery_checker@0"` | 节点类型名不含单元地址；确认实际类型后填写 `battery_checker`。 |
| `compatibles: ["acme,*"]` | 不支持通配符；填写源码中的精确 compatible，多个值分成数组元素。 |
| `compatibles: "acme,power"` | 此字段必须是数组，例如 `["acme,power"]`。 |
| `driverNature: "physical"` | 按业务含义选择 `physical-device` 或 `logical-service`。 |
| driver 的 `nodeTypeName` 被填入节点名 | 恢复该不适用字段为导出中的 `null`，或在更新片段中省略它；不要改变主体类型。 |

示例只说明格式，不能直接代替实际设备标识。先按 `subjectId` 找到目标主体，再按 `jsonPointer` 修复指定字段；保留其他业务编辑和只读导出信息。校验按阶段返回错误，修复后需再次预览，当前报告不代表整包所有问题都已扫描。

点击「复制诊断信息」，将报告连同原始导出文件和编辑后文件交给编码代理。报告包含文件名、导入模式、来源与目标组织、错误码、可用的请求 ID 和字段诊断，不包含完整上传包或登录凭据。HTTP 环境不支持剪贴板或浏览器拒绝复制时，可选中诊断文本手动复制。每次最多返回 50 条字段诊断，过长的值会标明截断，截断预览不能直接作为替换值。只读差异应从同一次原始导出恢复；其他字段按具体规则修复，保留需要调整的可编辑内容，重新上传并预览。不要修改服务端基准或切换导入模式来绕过校验。

更新会比较文件、服务端保留的基准和组织当前状态。独立修改可以保留，冲突修改需要选择。复制的目标是同一部署内的另一个组织；路径匹配仅供建议，不代表已授权复用。来源删除标记不会删除目标模块。缺少基准时不能用编辑后文件中的值替代。确认前请审阅全部操作、冲突、受影响主体和项目影响；预览后目标发生变化时，需要重新预览。

复制模块时，在目标组织选择复制模式并上传文件，逐一明确选择复用目标模块或新建，再解决与目标资料的差异。目标会保存每项确认的映射，包括复用映射，供同一包后续导入使用；已映射目标缺失时会报告冲突。复制只使用文件和目标状态，不读取来源基准。

复制需要完整保留的主体快照，包括根主体归属和别名、识别继承或覆盖，以及每个所属子主体的状态和级联停用事实。在快照中填写期望的 `state`；主体的 `operation` 命令在更新模式可选，必须与提供的状态一致；复制模式不接受该字段。主体身份及根主体或所属子主体的分类必须与当前 Catalog 兼容。目标已有登记会保留身份；状态、归属、别名或识别规则不同时须明确选择。停用登记会直接以停用状态创建，恢复复制的驱动时只恢复因级联而停用的子主体。来源删除标记不会停用目标登记。

复制会携带来源组织的 `ownerSubjectId`。目标组织已有同一子主体但所属驱动不同时，预览会列出「所属驱动」冲突：选择「保留当前」保留目标归属，选择「采用文件」并确认后应用来源归属。该操作只调整目标组织的登记，不改写 Catalog 的固定所属驱动；来源快照中的所属驱动和子主体仍须满足当前 Catalog 及目标组织的有效性约束。

模块和主体各最多 10,000 条。上传的 JSON 文件最多 32 MiB；内容按解析后重新序列化为紧凑 JSON 的 UTF-8 字节数计算，最多 4 MiB。导出文件使用两空格缩进，排版空白不计入这 4 MiB 内容限制，字符串内的空白仍计入。超过任一限制都会拒绝整包，不会截断或分批应用。

新建或移动的模块路径还须满足保守的 2,560 字节预算，包含目标组织 ID、编码路径及 32 字节索引开销。新模块 ID 的每段按 36 字节计算，已有 ID 按 UTF-8 字节长度计算。该预算不依赖压缩，并为数据库索引上限留出余量，因此预览会拒绝部分数据库实际可能存储的路径。未变化的历史路径仍可原样导入或仅更新资料。
