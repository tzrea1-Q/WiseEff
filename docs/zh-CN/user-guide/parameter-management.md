# 管理项目参数

> English: [English](../../user-guide/parameter-management.md)

## 谁可以操作

- 访客（`guest`）具备 `parameter:view` 时，可以浏览参数和已发布的参数定义。
- 硬件开发、软件开发、硬件MDE、软件MDE具备 `parameter:edit` 且有目标项目的访问权限时，可以准备修改。项目完成初始化后，才能提交普通参数变更。
- 当前参数值请求由绑定到该项目的软件MDE或管理员（`admin`）审阅，提交人不能批准自己的请求。硬件MDE负责下文分阶段流程中的硬件检视。
- 组织管理员具备 `admin:access` 时，可以管理本组织的初始化、导入、项目文件、配置集和基线。平台超级管理员（`platform-admin`）可以从组织目录进入目标组织，管理该组织的项目、参数及规范主体登记。能否审阅或合入某个项目的变更，仍取决于服务端检查的独立职责；选择目标组织不会授予自审权限。

管理其他组织时，先核对「当前操作组织」提示。项目清单、初始化、配置来源、导出、活动记录和项目删除回执均使用该固定组织。另一个标签页可以继续操作所属组织；进入目标组织不会改变账号归属。项目被删除后，查看回执和重试对象清理仍保留原目标组织。共享 Catalog 参数定义属于平台资源，不会随项目删除。

需要申请角色时，先阅读[账号与访问](account-and-access.md)。下文使用界面上的中文名称和路由定位操作入口。

## 查找参数并比较项目

1. 打开「参数修改」（`/parameters`），选择项目。「我的工作台」（`/parameter-home`）也提供按项目查看工作和待办的入口。
2. 在参数表中搜索，按模块或重要性筛选。打开行详情，核对属性键、节点或配置实例、当前值、定义修订、源位置和历史。同名参数的含义可能不同，需要结合这些信息判断。
3. 在行详情中打开「跨项目对比」，仍位于 `/parameters`。选择要比较的配置实例，查看数值与修订信息。具备编辑权限时，「使用该项目配置加入草稿」只是准备修改，不会立即替换当前值。

原来的「对比分析」页面（`/parameter-comparison`）已下线，请使用行级对比。

## 准备并保留草稿

在当前 API 工作台的「参数修改」（`/parameters`）中，点击「编辑」，填写目标值和修改原因，再点击「校验并加入本轮」。校验成功后，草稿才会保存到服务端，并进入「本轮已修改」托盘。保存草稿不会改变当前值或源文件。若出现诊断信息，先处理问题；编辑框中的文字要通过校验才算已保存。

关闭编辑器后，只要工作台仍保持挂载，尚未校验的文字就会保留，可点击「继续编辑」重新打开。这些文字还没有保存到服务端，刷新页面或离开工作台后可能无法恢复。已成功创建的服务端草稿可以重新加载。从托盘移出已保存的草稿会将其删除，不只是隐藏这一行。

旧版非 API 编辑器需要点击「保存草稿」，才会把当前编辑内容放入本地轮次。关闭旧编辑器会丢弃未保存的修改，只保留上一次保存的本地版本。「暂存本轮」是另一个操作；使用 API 持久化时，它会保存待提交草稿，供之后继续处理。旧版的保存、暂存按钮与当前 API 编辑器的校验动作各有不同用途。

## 提交本次要改的内容

在「参数修改」（`/parameters`）中勾选要提交的已保存草稿，核对目标值和原因，从本轮托盘提交。当前参数值请求可以指定软件审阅人，也可以留在软件审核池。提交会固定待审目标和来源上下文，后续不能擅自换用另一份来源。

“一轮”用于组织一起准备的变更。当前规范参数请求保留各自的请求和批次身份，不会转换成旧版提交轮次记录。节点启用草稿与规范参数值草稿需要分开提交。若缺少角色候选人、工作版本过期或校验未通过，先按提示处理，再重试。

从工作台进入「我的历史提交」（`/parameter-submissions`），查看自己的请求。当前请求显示待审核、已批准、已驳回或已撤回状态，以及变更目标、来源证据和审阅意见。提交人可以撤回待审核请求；之后若要继续，需要准备并提交新的请求。

## 按请求类型审阅

打开「变更审阅」（`/parameter-review`），选择项目和待处理事项，先看清请求类型，再执行操作。

![Aurora 变更审阅队列](../../user-guide/images/parameter-management-review.png)

*管理员打开 Aurora 审阅队列中的种子已处理请求；截图不创建或批准请求。*

### 批准当前参数值请求

当前“软件配置”请求使用软件审核流程，不会自动经过“硬件检视 → 软件检视 → 单独合入”的时间线。项目软件MDE或管理员需要核对已固定的数值与源差异、受影响的绑定、修改原因，以及已有的冲突决定。批准时，系统会重新核对来源并提交审阅过的变更；这个面板无需另外填写合入链接。批量请求整批批准或驳回。若来源已变化或证据不一致，系统会阻止批准，不会自动更换目标。

### 推进分阶段请求

节点启用请求仍使用分阶段流程。保留的旧版记录也可能显示这些阶段；归档记录只供查看，不能继续处理。

- 硬件检视时，核对硬件条件、配置值、安全与风险影响，以及提交人的依据。
- 软件检视时，核对实现及配置影响、来源一致性，以及前一阶段的检视。
- 软件合入时，核对审阅条件是否齐备，并填写有效的 HTTP(S) 合入链接；逐条请求确认合入。

审阅与合入资格以持续维护的[用户权限设计](../security/user-permission-design.md)为准。

分阶段提交需要选择硬件检视、软件检视和软件合入处理人，各专业只处理自己获准的阶段。高风险分阶段变更在合入前必须有硬件和软件检视证据。操作权限由服务端根据账号状态、角色和项目范围检查，不能只以按钮是否可见为准。

## 阅读处理轨迹并回应退回

在「我的历史提交」（`/parameter-submissions`）查看自己发起的事项，在「变更审阅」（`/parameter-review`）查看审阅详情。旧版轮次的时间线依次显示选择参数、填写目标值、硬件检视、软件检视、软件合入。判断进度时，需要同时阅读状态和原因。已打回或已撤回的轮次已经停止，即使某个阶段仍被高亮。符合条件的进行中轮次可选择「撤回本轮提交」，归档轮次只读。

当前请求的进度记录在待处理或历史条目及审阅意见中，不使用旧版五步时间线。被驳回后，先读原因，再回到「参数修改」（`/parameters`）核对目标与来源，补充依据或修正数值，重新提交。撤回后若要继续修改，也需要新建请求，原请求不会重新打开。

## 先分清定义，再管理项目

打开「参数定义」（`/parameters/definitions`），浏览已发布的属性契约和修订。定义解释属性的含义，项目绑定确定实际节点或配置实例，项目值则是该实例采用的配置。修改某个项目的值，不会重新定义共享的属性契约。

Catalog 由平台持有，发布后的版本不可变。组织登记 Catalog 主体，并将其放入自己的分类树；定义结构仍由平台维护，并非组织私有副本。在「参数后台」（`/parameter-admin`）中，可通过「参数定义管理」（`/parameter-admin/specs`）参与治理。提案和上传的 DTS 需要经过独立的发布流程，详见[Catalog 编制与发布参考](../design-docs/catalog-authoring-and-publication-control-plane.md)。

在参数定义管理中，先查看取值类型、单位与范围，再编辑定义。身份纠错预演后返回修改，需要重新预演。关闭未保存的编辑器时会提示是否放弃；发布任务的处理进度会持续更新，也可手动刷新。历史面板可加载更早的修订，并与当前修订比较内容。

新增驱动、节点类型或配置规范，使用「规范主体与归属」中的「新增主体」，分别填写 compatible 标识、节点名称或配置规范标识；驱动还需明确选择性质和实例基数。主体可独立发布，不必先编造参数。参数定义管理中的「新增定义」只向已发布主体增加参数；缺少主体时可进入同一个创建流程，发布成功后继续新增定义。主体发布、组织登记和项目节点启用是三个独立操作。

示例字段接受完整 DTS 属性语句、DTS 取值或 JSON 示例数组。DTS 示例可包含 `/* ... */` 和 `// ...` 注释，包括最后一个分号后的注释。转换示例时会忽略字符串外的注释；引号内的 `"7|8"`、`"3^1"`、`"0xa"`、`"http://host"` 等内容保持不变。

具备 Catalog 编写与发布能力的平台管理员，纠正未使用的身份时可以不选择受影响项目。预演和发布会核对全平台当前引用；已有或并发新增引用会停止此快捷路径，需改用实际项目迁移。目标身份冲突时可定位到已有定义。纠错完成会建立替代 Definition，保留旧键与历史，不会自动删除或弃用旧身份。只有权威全局无引用证据成立时才显示「单独弃用旧定义」，打开原有弃用流程前还会重新核对。

在「模块管理」（`/parameter-admin/modules`）的「模块」页签中搜索模块树，按模块、主体身份、登记状态和定义数量筛选主体。模块树筛选也会约束右侧列表。模块选择、树状态和主体筛选保存在 URL 中，从定义详情返回时可恢复。没有写权限也能查看模块详情；分类维护与主体归属调整仍由具备权限的组织管理员操作。

「移除驱动」（节点类型、配置规范提供对应操作）会停用本组织的主体登记。确认弹窗读取当前定义、参数绑定和项目数量，最多列出前 50 个受影响项目，并要求填写原因、勾选影响确认。停用会阻止新绑定及现有项目的部分编辑、提交操作，定义、参数值和历史记录保留。默认主体列表隐藏已停用登记；选择「已停用」可恢复原登记和归属。如果原模块已删除，恢复后归属为未设置，需要重新调整；组织不能恢复平台已退役的主体。模块分类即使变空也会保留。参数定义管理同样默认隐藏已停用登记，勾选「包含已停用和退役主体」可查看保留记录。写入冲突时保留原因，刷新影响数据后须重新确认。

未登记主体同样可以从本组织移除，无论是否已有参数定义。确认后直接标记为本组织已停用，不需要先登记或选择模块，也不会删除共享 Catalog 中的主体和定义。可从「已停用」恢复；这类主体没有原模块归属，恢复后需再调整归属。

![本地 API 演示环境中的驱动移除确认及受影响项目](../../assets/parameter-admin/registration-removal-preview.png)

未登记主体没有合适的目标模块时，可在登记表单选择业务父分类，并填写新目标名称。确认后在同一事务中创建对应类型的目标并登记主体。组织尚无业务分类时，先使用表单中的入口创建分类。调整归属会显示完整目标路径和影响；发生冲突后需要刷新依据并重新确认。

「来源识别」集中展示已识别与需要复核的来源记录，使用独立的完整宽度列表。选择项目会在服务端限定查询范围；关键词和来源筛选只覆盖已加载记录，可继续加载后续页。空状态会说明观察记录如何产生。复核链接可准确打开授权范围内的对应项，包括不在第一页的记录。定义提案被记录不代表已经发布；成功回执提供进入当前定义目录继续编写的入口。

在参数定义管理中打开「待审核事项」，可搜索兼容标识、属性或来源，并按项目、原因筛选。处理页展示全部受影响来源和可执行方式；登记必须选择真实候选及同类型目标模块，恢复登记从已核实的退役登记中选择。未知来源可以记录定义修订意向或标为范围外。填写原因、核对影响后再明确确认。打开表单、返回窗口及点击继续确认时，系统自动核对最新依据并保留输入，无需手动刷新；依据或目标变化时需重新核对，读取失败时可重试，校验本身不会提交处理。退出已修改表单前会确认是否放弃。记录修订意向不代表定义已发布，应按回执中的入口前往参数定义管理继续；「处理记录」进入现有审计中心回查。

「历史注册表」是只读快照，与当前规范主体登记分开。可以搜索、筛选、排序，并查看已有驱动属性与解析覆盖详情；该接口不提供历史时间线。待办处理完毕后，节点对应历史仍可查看。

## 管理共享 DTSI 版本

在项目「配置组成」中打开私有 `.dts` 或 `.dtsi` 文件菜单，选择「创建共享资源」。服务端读取精确冻结版本及实际可达的私有依赖，保留原始路径和字节，进入现有共享草稿编辑页。已有共享依赖保留精确资源及版本 pin，可通过「查看源码」检查。项目自身的构建声明成为新资源的设置，共享依赖的设置仍属于其固定版本。草稿与发布源码可由本组织有共享资源查看权限的用户读取。来源项目的组成、值、引用及历史保持不变，发布不会把项目转换为共享引用。公开来源证据仅包含不透明的派生摘要；私有项目及版本 pin 留在来源项目受权限约束的审计中，遵循正常保留策略。

在参数管理后台打开「共享 DTSI」（`/parameter-admin/sources`）。组织参数管理员可点击「导入资源」，选择 UTF-8 编码的 `.dts` 或 `.dtsi` 单文件、文件集合、目录或 ZIP 归档，也可直接输入源码，填写资源名称后保存草稿。目录和 ZIP 保留原始相对路径与内容；选择普通文件集合时，浏览器仅提供文件名，嵌套结构应使用目录或 ZIP。`.h`、`.hpp` 作为头文件依赖保留，不作为 DTS 或 JSON 参数文件解析。多文件资源显示文件列表，可切换完整源码及修改路径；在当前草稿中重命名保留成员身份。准备中的不完整 DTS 文本也能保存；保存草稿不会发布版本或改变任何项目。

发布时填写「变更说明」，点击「预览发布」。服务端会冻结完整源码集合、成员身份、文件角色、校验和及 include 关系；核对只读预览后点击「发布版本」。只有 `compatible`、`status` 的声明也可以发布，不必虚构参数定义。共享库无需自带项目根 DTS；预览列出项目仍需提供的外部引用，不代表已完成项目编译。首个版本为 `v1`；已发布源码和历史不可改写，也不会自动更新项目配置。缺失 include、循环、路径逃逸、重复标签及语法错误会定位到原始文件行列，修正草稿后可重试。原生 `/include/` 与受控 `#include` 预处理均保留原始源码及头文件。在「构建设置」声明相对搜索目录和 `NAME=value` 宏；固定依赖仍拥有各自的构建声明。不支持的输入或服务端预处理环境不可用时会阻止发布，草稿仍可编辑。

导入上限为 128 个文件、单文件 2 MiB、源码共 16 MiB、ZIP 压缩包 8 MiB；路径和 include 嵌套最多 16 层，展开源码最多 32 MiB。归档解压还受 200 倍压缩比限制，最低解压预算为 1 MiB。不支持的文件类型、嵌套压缩包、符号链接、绝对路径、目录穿越和规范化路径重复会拒绝整次导入，不静默跳过文件。ZIP 在保存草稿时由服务端检查并展开，失败时保留所选归档和输入。

在「版本」中可以打开精确历史源码。「创建新版本」会从当前发布版复制草稿，并保留源码成员身份；丢弃这份草稿会保留已发布版本和历史。若预览后有其他管理员修改草稿，需要重新核对当前源码并生成预览；请求失败会保留输入，方便重试。

资源列表搜索名称、路径与「已验证 compatible 标识」。compatible 结果来自已发布版本或当前已保存草稿的成功预览；修改草稿会让旧预览的搜索证据失效。「来源识别」读取选定的不可变版本及有权限的固定依赖，分别显示节点路径、节点标签，链接原始成员与正式 Catalog 主体。多个 compatible 匹配不同主体时需要复核。有权限的管理员可记录来源识别修订，或从既有主体表单创建未知声明，预填经验证的标识与来源。驱动性质、实例基数仍须单独确认；源码值不会生成参数定义或约束。识别提案保留服务端验证的来源证据，不绑定全局项目实例。只读用户进入已发布的定义库，并可返回精确来源上下文。

版本记录显示发布者、发布时间和变更说明。选择两个已发布版本后点击「比较所选版本」，可检查原始文件差异和包含固定依赖的有序语义声明。语义比较保留独立节点以及赋值、删除的真实顺序，不代表项目最终配置评估。「使用情况」只展示有权访问的项目配置、准确固定版本和直接或传递引用；配置链接进入该配置的生效视图，版本链接进入只读源码。新发布版本显示可用且「未评估」，所有既有项目的固定引用保持不变。

在项目的「配置组成」中，打开直接共享引用的文件菜单并选择「切换共享版本」。选择较新或较旧的已发布版本后，预览旧依赖、目标依赖、保留的项目源码，以及最终值、节点状态、来源和真实发布构建结果。当前项目覆盖会保留。填写原因并确认后创建新配置修订；切回旧依赖不会倒退历史指针，也不等于恢复完整快照。缺失引用、身份歧义、移除已关联参数、约束不兼容或宏来源无法证明时，整次变更都会阻止。源码、权限或 Catalog 状态变化后需要重新预览；取消预览及确认失败会保留版本选择和原因。

阻断项显示原始来源位置。可修正的项目声明进入已有源码编辑器；共享声明进入对应固定版本的只读源码或来源识别。节点连续性含糊时不会另建身份或空审核任务；没有适用的修正路径时，可重选目标版本或取消。查看或修正后返回，同一登录用户、组织、项目和配置的目标版本与变更说明会保留。源码修正仍须通过原有审核或应用流程生效，随后重新预览版本切换；旧证明会丢弃，刷新也不会恢复。服务器再次变化时还须重新预览。

所选版本声明的搜索目录或构建宏不同时，可展开「构建设置变化」核对。仅修改构建宏也可能改变语义值，原始文件仍保持一致。CPP 语义差异来自核验过的冻结展开结果，原始源码差异保留实际头文件和宏调用文本。

平台管理员彻底删除组织时，影响预览和清理包含该组织的共享 DTSI 草稿、预览与发布历史。普通资源操作保留发布历史；其他组织的源码和平台 Catalog 保留。

从列表重新打开资源可继续编辑。若其他管理员先保存了修改，本地输入会保留，需要重新载入并核对当前草稿后才能继续保存。离开有未保存修改的页面时会要求确认。「丢弃草稿」经确认后移除尚未发布的资源及草稿。只读用户不能创建、保存或丢弃草稿。

原生节点路径引用（如 `&{/soc}`、`<&{/soc/clock}>`）保留原始源码位置。共享库发布会列出库内尚未声明的路径要求；项目组合必须找到真实目标节点，缺失时拒绝组合。这些路径是定位符，不能单独证明逻辑节点身份。

## 初始化或导入项目参数

管理员从「参数后台」（`/parameter-admin`）进入「项目清单」（`/parameter-admin/projects`），启动项目初始化向导。填写项目身份和负责人，选择来源项目；使用多个来源时指定主来源，再选择候选参数，提交快照审阅。也可以明确选择从空库开始。提交后项目进入待审阅状态。管理员在「变更审阅」（`/parameter-review`）批准或打回初始化：批准后生成所选绑定，打回后由创建人修改。初始化通过后，才能提交普通参数变更。

在「参数后台」（`/parameter-admin`）的组织配置区域打开「批量参数导入」，选择目标项目，上传或粘贴 JSON、CSV、DTS 内容。确认前先检查解析报告、逐行决定和批次预览。完整 DTS 由服务端解析，本地不会推测其内容。规范参数导入只暂存草稿，提交并批准后才会改变当前值或源文件。导入是否生效，应以确认界面和返回状态为准，预览只是供核对的结果。从确认步骤返回时会保留预览及勾选；修改来源或核对结果后才会重新生成。暂存成功后，可从回执点击「查看草稿并继续提交审核」，前往目标项目继续处理。

管理项目 DTS/JSON 源文件时，进入「参数后台」的「配置工作台」（`/parameter-admin/projects/:projectId/configuration`，`:projectId` 替换为选中的项目）。核对工作源、上传候选、差异和历史。上传文件或候选后，需要明确把文件编入配置集，并按界面提供的审阅或应用动作处理。仅上传不会自动激活工作配置。JSON 源变更也会保留精确来源上下文，仅针对项目源文件，不允许任意编辑全局 Catalog。

API 模式的配置导航只显示匹配本组织有效登记模块的 DTS 实例，以及它们在 DTS 中的实际父级路径，无关分支会隐藏。仅作路径的父节点不展开无关属性，命中实例保留原有属性展示；禁用实例和尚无参数值的实例也会保留。导航搜索采用同一范围，仍可查找文件名。源码区域保留完整文件；历史或冲突链接指向范围外节点时，仍可定位源码，并显示范围提示。没有匹配模块时仍可打开文件；范围加载失败时可重试，不会当作成功空结果。

API 模式的项目清单提供可恢复的「归档」与「恢复项目」。默认清单隐藏归档项目，可通过「已归档」状态筛选查找。归档项目也会从「项目参数」「参数调试」等工作区的项目选择器中移除，恢复后重新可选。当前项目归档后，工作区刷新时切换到其他可用项目；没有可用项目时清空选择。归档保留历史和现有访问权限，不会冻结配置写入；恢复也会保留原来的初始化进度。从配置工作台和审核角色页面返回时，保留清单的筛选、排序和页码。

组织管理员可从项目操作打开「删除影响预览」。核对项目专属配置、源版本、参数值、审核与历史，以及保留资源、对象引用和阻塞后，勾选确认并选择一次「确认彻底删除」。数据变化时需要刷新预览。进行中的工作、单独保留的离线迁移归档或部署证据，需要先通过各自流程处理。平台共享定义与 Catalog release、其他项目、独立知识、日志和设备保留，仅解除项目关联。数据库和独占对象清理分别显示状态。存储故障会在「项目清理记录」保留可重试回执，刷新页面后仍可处理；两项状态均完成才表示彻底删除完成。重试同一确认不会重复数据库删除或审计。已删除项目 ID 不允许旧任务重新创建。

## 区分工作配置与发布结果

![本地 API 演示项目中的完整 DTS 源码编辑](../../user-guide/images/parameter-management-dts-source-editor.png)

在「配置工作台」（`/parameter-admin/projects/:projectId/configuration`）中：

- 「生效配置」展示完整合成设备树，包含未纳入组织业务导航的节点。选择节点可查看最终值、自身状态及祖先可达性；相同 `compatible` 的节点仍是独立实例。按需展开「继承与覆盖」可查看真实有序来源。源码链接打开固定文件版本；共享资源链接打开只读的固定发布成员，并保留返回项目节点的链接。当前来源更新后，历史配置链接仍保留原修订。未记录原始行号的删除效果仍可打开精确文件版本，并明确提示行号缺失。
- 在当前「生效配置」中，对属性选择「在本项目覆盖」，输入 DTS 值后查看准备好的项目源码差异。普通项目参数编辑者只能将服务器证明的单属性补丁提交给独立审核人；管理员也可直接应用。此草稿锁定整份源码编辑，刷新后可恢复。「撤销本项目覆盖」只移除选定的本地声明，预览恢复的下一层本地/共享值，或明确属性缺失，不插入设备树删除指令。共享版本和其他项目保持不变；可证明连续的 occurrence/Binding 身份与历史保留。原始位置或宏来源含糊时阻断该补丁，并提供原始源码修正路径；没有正式 Binding 的属性仍可由有权限的管理员通过项目原始源码修正。
- 选择配置集和 DTS 文件，在源码上方切换「预览 / 编辑」。直接修改 DTS 字符串、数组、注释和节点；预览只读并保留当前输入。编辑器支持搜索、折叠和撤销，检查器显示关联的定义说明。
- 点击「保存修改」或按 Cmd/Ctrl+S 校验整份文件、查看差异并填写原因。具备当前文件管理和参数编辑权限的管理员可选「直接应用修改」，包括纯注释修改，无需另找审核人；也可选择软件审核人后「提交审核」。语法或定义校验失败会保留输入并显示诊断。源码须非空且不超过 2 MiB；已有参数草稿和待审请求需先处理，才能应用整文件修改。
- 直接应用会一起更新工作源码、配置和派生参数，并刷新工作台。历史明确标记为管理员本人应用，没有独立审核人。响应丢失时可重试同一操作，不会重复应用；预览过期或权限撤销会拒绝操作并保留本地文本。发布基线和设备写入仍是独立操作。
- 「已提交」表示待审核。提交人可在个人提交记录中撤回，指定审核人可在审核队列批准或驳回。批准会一起更新工作文件、配置及受影响的参数值。回到工作台检查审核结果后加载正式版本，之后继续输入的本地内容仍会保留。
- 具备当前项目文件管理权限的管理员也可在审核队列查看本组织的源码请求。在「管理员接管」中，把待审请求重新指派给当前有资格的审核人，或填写理由后「取消源码请求」，解除配置阻塞。重新指派保留固定差异；取消单独记录实际管理员和理由，不冒充审核签名，也不删除历史。已终结请求保持不变。指派、权限或状态发生冲突时，请刷新后重试；作者撤回和有效指定审核人的原操作继续保留。
- 本地恢复与服务端提交独立。草稿按当前账号、组织、项目、配置和文件隔离。存储失败或多标签页冲突时可下载草稿；基线过期时，需要与最新来源核对后再提交。「放弃修改」恢复已加载的工作源码，不会撤回已有请求。同一页面内切换会保留编辑历史；刷新页面恢复文本与位置，不恢复撤销历史。
- 配置集按角色和顺序组织一组成员文件。Working 工作配置来自成员的现行版本；未编入集合的文件不属于该集合的 Working 和 Release 视图。空配置集可编入已验证来源的现有文件；需要审核才能变更成员或来源未知的文件仍会被阻止。
- 发布基线是固定成员版本的快照。草稿基线仍需单独发布。发布前，先看服务端发布就绪摘要，解决阻塞项，并按要求确认警告。本地未保存的编辑、不可用或过期的就绪结果都可能阻止操作。
- 恢复 Canonical 配置快照时，先核对所钉版本、成员用途和顺序、include/overlay 组成及参数影响，再填写原因。快照后新增的成员默认保留并逐项列出；补回已移出成员或改变用途、顺序须明确确认。一次事务生成新的 Working 来源修订、参数值及历史，原快照与正式版本保持不变。文件历史中仍可申请单文件回滚。
- 旧快照缺少完整组成信息时，页面会列出具体缺项并提供配置编辑器入口。如果有文件版本完全匹配、且保存了完整来源回执的真实历史修订，可以明确选择后重新预览；否则需补齐配置并另存新快照。源对象缺失、定义已彻底删除，或来源、Catalog、参数状态变化时，整次恢复会被拒绝。
- 冲突表示文件内容和界面草稿对同一变更给出不同结果。在冲突任务中检查两边来源，选择采用文件值还是草稿值。选择会保留在待审请求里；批准时若发现来源偏离该决定，系统会拒绝继续。
- 回写会在批准或合入时，将审阅过的修改写到精确的项目源，并保留版本和历史证据。回写仅修改项目源文件，不会写入设备或发布基线。若固定的来源已经变化，需要先解决冲突，或刷新后重新提交，并核对文件是否更新。

旧项目的 `/files`、`/config-sets`、`/structure`、`/conflicts` 链接会转入这个集成工作台。底层模型见[配置工作台参考](../design-docs/2026-08-06-project-configuration-workbench-design.md)，其它操作可回到[用户指南](README.md)。
