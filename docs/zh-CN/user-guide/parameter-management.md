# 管理项目参数

> English: [English](../../user-guide/parameter-management.md)

## 谁可以操作

- 访客（`guest`）具备 `parameter:view` 时，可以浏览参数和已发布的参数定义。
- 硬件开发、软件开发、硬件MDE、软件MDE具备 `parameter:edit` 且有目标项目的访问权限时，可以准备修改。项目完成初始化后，才能提交普通参数变更。
- 当前参数值请求由绑定到该项目的软件MDE或管理员（`admin`）审阅；提交人不能批准自己的请求。硬件MDE负责下文分阶段流程中的硬件检视。
- 管理员通过 `admin:access` 管理初始化、导入、项目文件、配置集和基线。平台超级管理员（`platform-admin`）能进入后台，并不代表自动具备所有项目的审阅或合入资格；服务端仍会检查相应角色绑定。

需要申请角色时，先阅读[账号与访问](account-and-access.md)。下文使用界面上的中文名称和路由定位操作入口。

## 查找参数并比较项目

1. 打开**参数修改**（`/parameters`），选择项目。**我的工作台**（`/parameter-home`）也提供按项目查看工作和待办的入口。
2. 在参数表中搜索，按模块或重要性缩小范围。打开行详情，核对属性键、节点或配置实例、当前值、定义修订、源位置和历史。同名不一定代表同一个参数，不能只凭名称判断含义相同。
3. 在行详情中打开**跨项目对比**，仍位于 `/parameters`。选择要比较的配置实例，查看数值与修订信息。具备编辑权限时，**使用该项目配置加入草稿**只是准备修改，不会立即替换当前值。

原来的**对比分析**页面（`/parameter-comparison`）已下线，请使用行级对比。

## 准备并保留草稿

当前 API 工作台的**参数修改**（`/parameters`）中，点击**编辑**，填写目标值和修改原因，再点击**校验并加入本轮**。校验成功后，持久化草稿才进入**本轮已修改**托盘。保存草稿不会改变当前值或源文件。遇到诊断信息，应先处理，不能把编辑框里的文字当成已经保存的变更。

关闭这个编辑器后，只要工作台仍保持挂载，尚未校验的文字会保留，可通过**继续编辑**重新打开。但这些文字还不是服务端草稿，刷新页面或离开工作台后不能依赖它们恢复。已成功创建的服务端草稿可以重新加载；从托盘移出持久化草稿会删除草稿，而不只是隐藏一行。

旧版非 API 编辑器的行为不同：必须明确点击**保存草稿**，才会把当前编辑内容放入本地轮次。关闭旧编辑器会丢弃未保存的修改，只保留上一次保存的本地版本。**暂存本轮**又是另一项操作；使用 API 持久化时，它将待提交草稿保存下来，供之后继续处理。不要把旧版的保存、暂存按钮与当前 API 编辑器的校验动作混为一谈。

## 提交本次要改的内容

在**参数修改**（`/parameters`）中勾选要提交的已保存草稿，核对目标值和原因，从本轮托盘提交。当前参数值请求可以指定软件审阅人，也可以留在软件审核池。提交会固定待审目标和来源上下文；草稿不是以后悄悄换用另一份来源的授权。

“一轮”将一起准备的变更组织起来。当前规范参数请求保留自己的请求和批次身份，不会被转换成旧版提交轮次记录。节点启用草稿与规范参数值草稿不能混合提交，应分开处理。缺少角色候选人、工作版本过期或校验未通过时，先解决提示中的阻塞项，再重试。

从工作台进入**我的历史提交**（`/parameter-submissions`），查看自己的请求。当前请求显示待审核、已批准、已驳回或已撤回状态，以及变更目标、来源证据和审阅意见。提交人可以撤回待审核请求；之后若要继续，需要准备并提交新的请求。

## 按请求类型审阅

打开**变更审阅**（`/parameter-review`），选择项目和待处理事项，先看清请求类型，再执行操作。

![Aurora 变更审阅队列](../../user-guide/images/parameter-management-review.png)

*管理员打开 Aurora 审阅队列中的种子已处理请求；截图不创建或批准请求。*

### 批准当前参数值请求

当前“软件配置”请求走软件审核，不会自动经过“硬件检视 → 软件检视 → 单独合入”的时间线。项目软件MDE或管理员核对已固定的数值与源差异、受影响的绑定、修改原因，以及可能存在的冲突决定。批准时重新核对来源并提交审阅过的变更；这个面板没有额外填写合入链接的步骤。批量请求整批批准或驳回，来源漂移或证据不一致会阻止批准，不会自动换目标。

### 推进分阶段请求

节点启用请求仍使用分阶段流程。保留的旧版记录也可能显示这些阶段，但只读归档记录并不是可以继续处理的现行请求。

- 硬件检视时，核对硬件条件、配置值、安全与风险影响，以及提交人的依据。
- 软件检视时，核对实现及配置影响、来源一致性，以及前一阶段的检视。
- 软件合入时，核对审阅条件是否齐备，并填写有效的 HTTP(S) 合入链接；逐条请求确认合入。

审阅与合入资格以持续维护的[用户权限设计](../security/user-permission-design.md)为准。

分阶段提交需要选择硬件检视、软件检视和软件合入处理人，各专业只处理自己获准的阶段。高风险分阶段变更在合入前必须有硬件和软件检视证据。按钮可见不等于拥有授权，服务端还会检查账号状态、角色和项目范围。

## 阅读处理轨迹并回应退回

在**我的历史提交**（`/parameter-submissions`）查看自己发起的事项，在**变更审阅**（`/parameter-review`）查看审阅详情。旧版轮次的时间线依次显示选择参数、填写目标值、硬件检视、软件检视、软件合入。应同时阅读状态和原因：已打回或已撤回的轮次不会因为某一阶段仍被高亮就继续推进。符合条件的进行中轮次可选择**撤回本轮提交**，归档轮次只读。

当前请求应看待处理或历史条目及审阅意见，不要期待旧版五步时间线。被驳回后，先读原因，再回到**参数修改**（`/parameters`）核对目标与来源，补充依据或修正数值，重新提交。撤回后继续修改也需要新请求，不会重新打开原请求。

## 先分清定义，再管理项目

打开**参数定义**（`/parameters/definitions`），浏览已发布的属性契约和修订。定义解释属性的含义，项目绑定确定实际节点或配置实例，项目值则是该实例采用的配置。修改某个项目的值，不会重新定义共享的属性契约。

Catalog 由平台持有，以不可变发布版本提供。组织登记 Catalog 主体，并放入自己的分类树，这不等于维护一份组织私有的定义结构。在**参数后台**（`/parameter-admin`）中，**参数定义管理**（`/parameter-admin/specs`）是治理入口。提出提案或上传 DTS 都不等于发布了定义；这一独立治理流程以[Catalog 编制与发布参考](../design-docs/catalog-authoring-and-publication-control-plane.md)为准。

## 初始化或导入项目参数

管理员从**参数后台**（`/parameter-admin`）进入**项目清单**（`/parameter-admin/projects`），启动项目初始化向导。填写项目身份和负责人，选择来源项目；使用多个来源时指定主来源，再选择候选参数，提交快照审阅。向导也支持明确从空库开始。提交后项目处于待审阅状态，并未完成初始化。管理员在**变更审阅**（`/parameter-review`）批准或打回初始化：批准后生成所选绑定，打回后由创建人修改。初始化通过前，普通参数提交保持锁定。

在**参数后台**（`/parameter-admin`）的组织配置区域打开**批量参数导入**，选择目标项目，上传或粘贴 JSON、CSV、DTS 内容。确认前先检查解析报告、逐行决定和批次预览。完整 DTS 由服务端解析，不在本地猜测。规范参数导入只暂存草稿，提交并批准前不会改变当前值或源文件。应阅读确认界面和返回状态，不能把预览当成已生效。

管理项目 DTS/JSON 源文件时，进入**参数后台**的**配置工作台**（`/parameter-admin/projects/:projectId/configuration`，`:projectId` 替换为选中的项目）。核对工作源、上传候选、差异和历史。上传文件或候选不会自动激活工作配置；需要明确把文件编入配置集，并按界面提供的审阅或应用动作处理。JSON 源变更同样保留精确来源上下文，不是对全局 Catalog 的任意编辑。

## 区分工作配置与发布结果

在**配置工作台**（`/parameter-admin/projects/:projectId/configuration`）中：

- **配置集**：按角色和顺序组织的一组成员文件。Working 工作配置来自成员的现行版本；未编入集合的文件不属于该集合的 Working 和 Release 视图。
- **发布基线**：固定成员版本的快照。创建草稿基线不等于发布。先看服务端发布就绪摘要，解决阻塞项，并在需要时确认警告，才能发布。本地未保存的编辑、不可用或过期的就绪结果都可能阻止操作。
- **恢复**：先预览受影响的成员，再将 Working 恢复到基线。恢复可能创建来源标记为回滚的新版本，不会悄悄替换已发布基线指针。
- **冲突**：文件内容和界面草稿对同一变更给出不同结果。在冲突任务中检查两边来源，选择采用文件值还是草稿值。选择会保留在待审请求里；批准时发现来源偏离该决定会拒绝继续。
- **回写**：批准或合入将审阅过的修改写到精确的项目源，并保留版本和历史证据。它不是设备写入，也不代表发布了基线。固定的来源已经变化时，应解决冲突，或刷新后重新提交，不要假定文件已更新。

旧项目的 `/files`、`/config-sets`、`/structure`、`/conflicts` 链接会转入这个集成工作台。底层模型见[配置工作台参考](../design-docs/2026-08-06-project-configuration-workbench-design.md)，其它操作可回到[用户指南](README.md)。
