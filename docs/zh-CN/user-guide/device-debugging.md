# 调试设备

> English: [English](../../user-guide/device-debugging.md)

## 谁可以使用

硬件开发（`hardware-user`）和软件开发（`software-user`）可以进入节点调试（`/node-debugging`），具备 `debugging:view`、`debugging:read` 时可查看和读取节点。写入需要 `debugging:write`，回滚需要 `debugging:rollback`。默认的硬件MDE、软件MDE、管理员（`admin`）和平台超级管理员（`platform-admin`）拥有这些写权限；普通硬件开发、软件开发没有。访客不能使用此工作流。

参数调试（`/dts-reload`）页面仅向 MDE 及以上角色开放。启动、部署或恢复 DTS 重载，还需要所选项目范围内的 `debugging:dts-reload` 权限，默认由上述 MDE 和管理员角色持有。服务端支持凭 `debugging:view` 只读查询历史；页面访问和设备写入仍需各自的授权。敏感参数可能另需专项权限和明确确认。即使角色符合要求，也必须有权访问当前组织、项目、会话和设备。

在「调试平台」导航分组中选择：

- 节点调试（`/node-debugging`）：读取或写入单个运行时节点路径。
- 参数调试（`/dts-reload`）：通过平台生成的设备树 Overlay 和内核重载，测试一组项目参数值。

旧的参数调试工作区（`/debugging`）已下线，请使用 `/dts-reload`。调试后台（`/debugging-admin`，节点库位于 `/debugging-admin/nodes`）供管理员维护节点和协议绑定，设备写入仍受写权限限制。

## 连接本机并选择设备

1. 打开节点调试（`/node-debugging`）或参数调试（`/dts-reload`），按设备选择 HDC 或 ADB。
2. 打开「安装指南」，核对平台、架构和包版本后下载对应安装包。默认显示图形安装包，需要便携版时再展开「便携压缩包（zip / tar.gz）」。浏览器无法可靠识别 Mac 芯片，请在「关于本机」核对 Apple Silicon 或 Intel。图形安装包落后于新版便携包时，指南会分别标明版本。Windows 要求以管理员身份运行安装程序，以便浏览器唤起 Bridge；其余步骤也请遵循面板提示。
3. 点击「连接本机」，允许浏览器打开已安装的 Bridge。指南保持打开，并提供重试和手动终端补救。临时配对码到期会刷新，也可使用重新生成操作取得新码，不要沿用旧码。
4. 将目标设备连接到运行 Bridge 的电脑，完成设备端调试授权，再在页面检测设备。出现多个目标时，先选定本次要操作的设备，再写入或部署。
5. 分别核对 Bridge 是否已连接，以及 HDC/ADB 是否已检测到目标设备。检测失败时，检查线缆、设备授权、所选协议以及面板中的工具状态，然后重新检测。

连接栏显示 Bridge 当前状态和下一步操作。已有登记电脑时，点击「管理设备代理」打开管理弹窗，可修改电脑名称或申请撤销配对授权；撤销仍需确认。关闭弹窗或按 Escape 后，工作台保持原来的位置。

组织管理员和平台超级管理员可在「组织管理 → 设备代理」盘点本组织所有成员的 Bridge，查看所有者、机器标识、版本、在线／最后活动和撤销状态。选择「撤销配对」，核对成员与机器并填写原因；失败后保留原因以便重试，刷新目录可读回处理结果。撤销使原凭据失效并断开连接，重新使用需由成员重新配对。盘点和撤销不会授予管理员借用他人 Bridge 执行设备操作的权限；普通成员仍从调试工作台管理本人的配对。

安装、配对或 HDC/ADB 工具持续不可用时，请部署运维人员参考[本地 Device Bridge 运维手册](../runbooks/local-device-bridge.md)。确认目标设备后再写入。真实设备验证需要现场硬件和工具；模拟结果不能证明目标设备已就绪。

## 找到节点并读取当前值

在节点调试（`/node-debugging`）选择模块或子树，按名称、Key、描述、模块或路径搜索。准备目标值前，查看节点详情、当前协议的路径、访问模式、当前值和状态。

- **RO**：只读，用于观测。
- **RW**：只有协议绑定可用且安全检查通过时才能写入。
- **WO**：无法取得写前快照，因此不提供安全写入。
- HDC/ADB 绑定缺失或被禁用时，节点在该协议下不可用。请管理员在调试后台（`/debugging-admin/nodes`）检查绑定，不要自行猜测替代路径。

当前显示值只反映一次观测，设备状态可能随后发生变化。注意旧值提示；需要确认当前状态时重新读取。

## 写入节点并判断结果

1. 打开可写节点编辑器，核对设备、节点路径、单位和风险后输入目标值。输入先保留在编辑器中，明确暂存或写入后才进入操作流程；关闭未保存内容时，可继续编辑或放弃。复杂值可展开格式与规范化提示。配置了数值上下界时，服务端会校验范围；复杂值按其值元数据校验。
2. 选择「写入并回读」，或暂存目标值后使用批量下发栏。批量只发送待写入且可写的节点；勾选行后，只发送选中行中的待写入项。包含高风险节点的批量操作会先请求确认，确认前不会下发。
3. 物理写入前，服务端检查授权和设备租约，读取原值并记录写前快照。写前读取失败时，不会执行写入。高风险写入需要人工明确确认。
4. 分别查看「写入结果」和「写后回读」。「写入已执行」只说明写命令已执行，设备返回值仍可能与目标值不同。节点调试保留实际返回内容，不做相等性判定；设备使用不同表示方式时，也不会仅凭文本差异认定失败。

写入已执行但回读失败或未知时，当前显示值可能已过时。使用「重新回读（不会再次写入）」重新读取。「写入结果未知」时，先检查连接、Bridge 提示和节点当前值，避免盲目重发。

需要恢复节点时，在节点调试（`/node-debugging`）点击「回滚快照」并核对确认内容。系统检查回滚授权后，写回快照保存的写前值，再回读结果。能否执行取决于快照是否有效，以及所属会话和设备是否符合条件。确认后检查实际结果，才能判断回滚是否成功。节点快照与 DTS 重载证据快照用途不同。

## 预检并部署 DTS 重载

在参数调试（`/dts-reload`）中：

1. 选择项目和候选参数，对照库基线与调试值，明确加入本轮后保存编辑。候选表上方可展开本轮摘要，核对或修改已选值；关闭未保存编辑时，可继续编辑或放弃。Overlay 由平台生成，不需要手工编写。调试值只属于本次运行，不会修改参数库、草稿或发布基线。
2. 点击「启动预检」检查本轮。平台编译基线和 Overlay、试合并，再检查合并后的属性和值。逐项查看步骤和诊断。「预检通过（未部署）」表示预检已完成，尚未部署到设备；阻断或失败的检查需先处理。工具链或项目源文件有问题时，请运维人员或项目管理员协助。
3. 完成 Bridge 连接和设备检测后，选择部署，在确认窗口核对设备目标、参数变更和生成的 Overlay。敏感值和设备部署需要分别确认。预检可以在设备连接前准备，部署则必须先连接设备。
4. 确认后，平台挂载并传输编译产物，核验设备端摘要，触发重载，再采集可用的内核日志和调试节点证据。根据运行终态和快照判断驱动行为是否得到验证，不能只看传输结果。

| 运行结果 | 如何理解 |
| --- | --- |
| 预检通过（`validated`） | 预检完成，部署到设备是另一项操作。 |
| 失败／已阻断 | 查看失败步骤或拒绝原因。设备侧写入后的失败仍可能留下调试残留。 |
| 不可验证（`unverifiable`） | 部署命令和完整性检查通过，但没有可读绑定参数，或部分回读缺失且没有矛盾，无法确认驱动行为。 |
| 行为已验证（`verified`） | 本次所选参数中，所有具备可读调试节点绑定的参数均按声明的值形状与调试值匹配。没有绑定的参数仍是证据缺口。 |
| 矛盾（`contradicted`） | 至少一项绑定参数的回读与调试值不符，不能报告为已验证。 |

DTS 重载会比较绑定节点的观测值与调试值，普通节点调试不做这项比较。内核日志保留为未判定证据，不能单独证明重载成功或失败。

## 重载后恢复基线

参数调试（`/dts-reload`）可能显示所选设备的「重载残留」。这个提示来自平台对历史运行的记录，并非实时探测结果。重启、重新刷机或在 WiseEff 之外修改设备，都可能使该提示失效。

点击「恢复基线（补偿性重载）」并核对确认内容。平台使用产生残留的那次运行所记录的库基线值，为同一组参数启动新的运行。这次运行仍须通过预检、敏感参数检查和独立部署确认。缺少基线或配置变化可能阻断恢复。

恢复基线会再部署一层使用基线值的 Overlay，已应用的 Overlay 仍保留，无法通过此操作撤销或卸载。补偿性部署进入行为已验证、不可验证或矛盾终态后，平台会清除残留记录；恢复失败时保留记录。提示消失后，仍需查看新运行的证据和剩余警告，核对驱动行为是否符合基线值。重载快照保存证据，不提供可用于撤销的设备树副本。边界说明见[重载快照决策](../../adr/0021-reload-snapshot-satisfies-device-write-snapshot-non-negotiable.md)。

## 查看历史并分享证据

- 在节点调试（`/node-debugging`）展开「节点操作记录」，查看当前会话的检测、读取、写入／回读和回滚事件。展开「查看完整结果」可核对完整输出、错误、节点路径、返回码和时间，并结合节点详情中的写入与回读结果判断。
- 在参数调试（`/dts-reload`）展开「运行历史」。历史按项目列出，包括已阻断和失败的运行；恢复基线运行会单独标注，也可以筛选「仅当前设备」。打开一次运行，查看预检步骤、基线与调试值、终态和重载快照。快照包含记录的库基线、产物摘要及完整性结果、可用内核日志证据和每个参数的行为验证结果。编译产物可用时可以下载，过期产物会标记为不可下载。
- 分享报告时保留运行 ID、项目和设备信息。通过参数调试（`/dts-reload?runId=<run-id>`）可以重新打开对应运行。没有绑定、读取失败、内容截断和不可验证状态都应如实说明，不能写成验证成功。
- 管理员可在审计中心（`/audit`）交叉核对保留的操作。[用户操作覆盖矩阵](../developer/user-operation-coverage-matrix.md)区分自动化／模拟检查与有条件的真实 HDC/ADB 证据；目标硬件是否通过验收，需要结合真实设备证据判断。
