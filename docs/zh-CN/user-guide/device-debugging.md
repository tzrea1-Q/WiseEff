# 调试设备

> English: [English](../../user-guide/device-debugging.md)

## 谁可以使用

硬件开发（`hardware-user`）和软件开发（`software-user`）可以进入节点调试（`/node-debugging`），具备 `debugging:view`、`debugging:read` 时可查看和读取节点。写入需要 `debugging:write`，回滚需要 `debugging:rollback`。默认的硬件MDE、软件MDE、管理员（`admin`）和平台超级管理员（`platform-admin`）拥有这些写权限；普通硬件开发、软件开发没有。访客不能使用此工作流。

参数调试（`/dts-reload`）的页面入口要求 MDE 及以上角色。启动、部署或恢复 DTS 重载，还需要所选项目范围内的 `debugging:dts-reload` 权限，默认由上述 MDE 和管理员角色持有。服务端另支持凭 `debugging:view` 只读查询历史，但这不代表可以绕过页面入口限制或写入设备。敏感参数可能另需专项权限和明确确认。角色不能替代对当前组织、项目、会话和设备的访问授权。

在「调试平台」导航分组中选择：

- **节点调试（`/node-debugging`）**：读取或写入单个运行时节点路径。
- **参数调试（`/dts-reload`）**：通过平台生成的设备树 Overlay 和内核重载，测试一组项目参数值。

旧的参数调试工作区（`/debugging`）已下线，请使用 `/dts-reload`。调试后台（`/debugging-admin`，节点库位于 `/debugging-admin/nodes`）供管理员维护节点和协议绑定，不是绕过写权限的入口。

## 连接本机并选择设备

1. 打开节点调试（`/node-debugging`）或参数调试（`/dts-reload`），按设备选择 **HDC** 或 **ADB**。
2. 在本地 Device Bridge 面板中按「安装 Bridge」的指引，下载标记为「本机推荐」的安装包。遵循面板提示；Windows 安装提示要求以管理员身份运行安装程序，以便浏览器能唤起 Bridge。
3. 点击「连接本机」，允许浏览器打开已安装的 Bridge。面板会提供临时配对码。配对过期或连接中断后，使用当前面板重新连接，不要沿用旧配对码。
4. 将目标设备连接到运行 Bridge 的电脑，完成设备端调试授权，再在页面检测设备。出现多个目标时，先选定本次要操作的设备，再写入或部署。
5. 同时核对 Bridge 连接状态和 HDC/ADB 设备目标。Bridge 已连接不等于已检测到设备。检测失败时，检查线缆、设备授权、所选协议以及面板中的工具状态，然后重新检测。

安装、配对或 HDC/ADB 工具持续不可用时，请部署运维人员参考[本地 Device Bridge 运维手册](../runbooks/local-device-bridge.md)。目标不明确时不要写入。真实设备验证取决于现场硬件和工具条件，模拟结果不能证明目标设备已就绪。

## 找到节点并读取当前值

在节点调试（`/node-debugging`）选择模块或子树，按名称、Key、描述、模块或路径搜索。准备目标值前，查看节点详情、当前协议的路径、访问模式、当前值和状态。

- **RO**：只读，用于观测。
- **RW**：只有协议绑定可用且安全检查通过时才能写入。
- **WO**：无法取得写前快照，因此不提供安全写入。
- HDC/ADB 绑定缺失或被禁用时，节点在该协议下不可用。请管理员在调试后台（`/debugging-admin/nodes`）检查绑定，不要自行猜测替代路径。

当前值是一次观测，不保证一直反映设备现状。注意旧值提示；需要新证据时重新读取。

## 写入节点并判断结果

1. 打开可写节点的编辑器，输入目标值。复杂值按页面显示的格式和规范化提示填写。配置了数值上下界时，服务端会校验范围；复杂值按其值元数据校验。
2. 选择「写入并回读（仅展示）」，或暂存目标值后使用批量下发栏。批量只发送待写入且可写的节点；勾选行后，只发送选中行中的待写入项。包含高风险节点的批量操作会先请求确认，确认前不会下发。
3. 物理写入前，服务端检查授权和设备租约，读取原值并记录写前快照。写前读取失败时，不会执行写入。高风险写入需要人工明确确认。
4. 分开查看「写入结果」和「写后回读」。「写入已执行」表示写命令已执行，不表示设备返回值一定等于目标值。节点调试保留实际返回内容，**不做相等性判定**；设备使用不同表示方式时也不会仅凭文本差异认定失败。

写入已执行但回读失败或未知时，当前显示值可能已过时。使用「重新回读（不会再次写入）」取得新观测。「写入结果未知」不能作为盲目重发的理由；先检查连接、Bridge 提示和节点当前值。

需要恢复节点时，在节点调试（`/node-debugging`）点击「回滚快照」并核对确认内容。系统在回滚授权下写回快照保存的写前值，再回读结果。能否执行取决于快照是否有效，以及所属会话和设备是否符合条件。确认操作后仍要检查结果，不能把点击确认当作回滚成功。节点快照与 DTS 重载证据快照不是同一回事。

## 预检并部署 DTS 重载

在参数调试（`/dts-reload`）中：

1. 选择项目和候选参数，对照库基线与调试值，编辑本次要测试的值。Overlay 由平台生成，不需要手工编写。调试值只属于本次运行，不会修改参数库、草稿或发布基线。
2. 点击「下发参数」启动预检。平台编译基线和 Overlay、试合并，再检查合并后的属性和值。逐项查看步骤和诊断。「预检通过（未部署）」**不是已经部署到设备**；阻断或失败的检查需先处理。工具链或项目源文件问题，请运维人员或项目管理员协助。
3. 完成 Bridge 连接和设备检测后，选择部署，在确认窗口核对设备目标、参数变更和生成的 Overlay。敏感值确认与设备部署确认是两道独立关口。预检可以在设备连接前准备，部署则必须先连接设备。
4. 确认后，平台挂载并传输编译产物，核验设备端摘要，触发重载，再采集可用的内核日志和调试节点证据。查看运行终态和快照；传输成功不等于驱动行为已得到验证。

| 运行结果 | 如何理解 |
| --- | --- |
| 预检通过（`validated`） | 预检完成，部署到设备仍是另一项操作。 |
| 失败／已阻断 | 查看失败步骤或拒绝原因。设备侧写入后的失败仍可能留下调试残留。 |
| 不可验证（`unverifiable`） | 部署命令和完整性检查通过，但没有可读绑定参数，或部分回读缺失且没有矛盾，无法确认驱动行为。 |
| 行为已验证（`verified`） | 本次所选参数中，所有具备可读调试节点绑定的参数均按声明的值形状与调试值匹配。没有绑定的参数仍是证据缺口。 |
| 矛盾（`contradicted`） | 至少一项绑定参数的回读与调试值不符，不能报告为已验证。 |

与普通节点调试不同，DTS 重载会比较绑定节点的观测值与调试值。内核日志作为**未判定证据**保留，不能单独证明重载成功或失败。

## 重载后恢复基线

参数调试（`/dts-reload`）可能显示所选设备的「重载残留」。这是平台依据历史运行做的记账，不是设备实时状态探测。重启、重新刷机或在 WiseEff 之外修改设备，都可能使该提示失效。

点击「恢复基线（补偿性重载）」并核对确认内容。平台以产生残留的那次运行所记录的库基线值，为同一组参数启动一次**新的运行**，仍须通过预检、敏感参数检查和独立部署确认。缺少基线或配置变化可能阻断恢复。

这不是撤销，也不会卸载已应用的 Overlay，而是再部署一层使用基线值的 Overlay。补偿性部署进入行为已验证、不可验证或矛盾终态后，平台会清除残留记账；恢复失败不会清除。因此，提示消失不代表驱动已观测到基线值，仍需查看新运行的证据和剩余警告。重载快照保存的是证据，不是可以撤销的设备树副本。边界说明见[重载快照决策](../../adr/0021-reload-snapshot-satisfies-device-write-snapshot-non-negotiable.md)。

## 查看历史并分享证据

- 在**节点调试（`/node-debugging`）**展开「节点操作记录」，查看当前会话的检测、读取、写入／回读和回滚事件。结合节点详情中的写入与回读结果，核对状态、返回码、输出／错误摘要和时间。
- 在**参数调试（`/dts-reload`）**展开「运行历史」。历史按项目列出，包括已阻断、失败运行；恢复基线运行会单独标注，也可以筛选「仅当前设备」。打开一次运行，查看预检步骤、基线到调试值、终态和重载快照。快照包含记录的库基线、产物摘要及完整性结果、可用内核日志证据和逐参数行为验证结果。编译产物可用时可以下载，过期产物会标记为不可下载。
- 分享报告时保留运行 ID、项目和设备信息。通过参数调试（`/dts-reload?runId=<run-id>`）可以重新打开对应运行。没有绑定、读取失败、内容截断和不可验证状态都应如实说明，不能写成验证成功。
- 管理员可在**审计中心（`/audit`）**交叉核对保留的操作。[用户操作覆盖矩阵](../developer/user-operation-coverage-matrix.md)区分自动化／模拟检查与有条件的真实 HDC/ADB 证据；有历史记录不代表已完成目标硬件验收。
