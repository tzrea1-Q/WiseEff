# 查找与维护工程知识

> English: [English](../../user-guide/knowledge.md)

## 谁可以操作

- 当前组织中已启用的成员，具备 `knowledge:view` 即可在**知识库（`/knowledge`）**浏览和检索。默认角色中的访客、硬件开发、软件开发、硬件MDE、软件MDE、管理员（`admin`）和平台超级管理员（`platform-admin`）都有这项权限。
- 硬件开发、软件开发以及硬件MDE、软件MDE具有 `knowledge:edit`，可以创建条目，并编辑、发布、归档或恢复自己创建的条目；不能因此维护他人的条目。
- 管理员和平台超级管理员还具有 `knowledge:manage`，可以维护他人的条目，并使用**知识后台（`/knowledge-admin`）**处理索引健康、Agent 草稿和已归档条目。这些操作仍限定在当前组织内。

草稿只有创建者和知识管理员可以查看。具备查看权限的成员可以阅读已发布和已归档条目，但**只有已发布条目参与检索和小泽的知识检索**。账号与角色设置见[账号与访问](account-and-access.md)。

## 查找已发布的答案

1. 打开**知识库（`/knowledge`）**。未进行检索时，可以按状态、标签筛选有权阅读的条目。标签用于标注项目或主题，知识库没有文件夹层级。
2. 在“检索知识库”中输入问题或关键词，点击**检索**。全文检索支持中文和英文，只返回已发布条目，不包括自己的草稿或已归档资料。
3. 打开结果，阅读正文、标签、来源与当前修订。文件条目还应检查正文提取状态；需要时下载原文件核对。
4. 查看页面报告的检索模式，不要默认已经启用语义检索。实际模式可能是“语义 + 全文混合检索”或“仅全文检索(FTS-only)”。点击**清除检索**可回到条目列表及其筛选条件。

连接真实 API 的部署中，**知识库（`/knowledge`）**的**问知识库(小泽)**会打开小泽对话面板。请在面板中提出问题；按钮不会自动发送检索框里的文字。小泽可以通过工具查找已发布知识，并给出回到条目的引用链接。使用答案前，应打开来源核对适用条件。mock 模式不提供这个入口；小泽创建的草稿也不会自动进入检索。

## 创建条目或上传文件

在**知识库（`/knowledge`）**中，根据资料选择内容形式：

- **新建 Markdown 条目**：填写标题、逗号分隔的标签和正文，可用项目标签标明适用背景。检查预览后，点击**创建草稿**。
- **上传文件条目**：填写标题与标签，选择文件，点击**上传并创建草稿**。这会创建独立的文件条目，不是给 Markdown 条目添加附件。

PDF、Word `.docx`、纯文本和 Markdown 文件可以提取正文用于检索。文件选择器也接受旧版 `.doc`，但提取器不支持这种二进制格式；提取失败时，应转换为 `.docx` 后替换文件。检查条目上显示的提取状态和原因：上传成功不等于正文已可检索。文件原件只能替换，不能在 Markdown 编辑器里修改。

新条目都从草稿开始。发布前核对正文、适用条件和来源证据；仅创建草稿，不会让资料进入检索或供小泽检索。

小泽创建的草稿如果引用了降级的来源日志分析，平台会在正文顶部自动加入与沉淀草稿相同的来源提示，标明「降级分析 · 规则回退」或「降级分析 · 提前收敛」、说明原因，并提醒依赖结论前复核证据。正文开头已有完全相同的提示时不会重复添加；未降级、未记录分析来源的旧分析，以及没有来源日志的草稿保持原样。提示是可编辑的草稿正文，不会阻止发布，也不代表质量保证。

## 发布并修订条目

1. 在**知识库（`/knowledge`）**打开自己创建的草稿，或作为知识管理员打开有权维护的草稿，点击**发布**。发布是进入检索的门槛，并会将索引更新加入队列；索引不一定立即完成。
2. 修改 Markdown 条目时，点击**编辑**，完成修改后选择**保存为新修订**。文件条目则点击**替换文件**，选择新文件，再点击**替换并生成新修订**。旧文件会保留在修订历史中。
3. 每次保存内容都会追加一条不可变修订。**已发布条目直接修订，保存后仍为已发布**，没有“待审批修改”状态。保存前应核对内容，因为这会更新已发布正文，并触发索引更新。
4. 打开**修订历史**查看旧版本。对于未归档的条目，有编辑权限的创建者或知识管理员可以点击**恢复此版本**，再确认**恢复为新修订**。恢复会追加修订，不改写历史，也不改变条目的发布状态。

若提示当前修订已被他人更新，先保留自己的改动，再刷新条目、核对差异，并基于最新修订重试。不要把冲突提示当作保存成功。

## 归档过时资料或恢复发布

在**知识库（`/knowledge`）**打开有权维护的已发布条目，点击**归档**。归档使条目退出检索，但保留正文和历史。以后可用“已归档”状态筛选找到它；点击**恢复为已发布**可重新发布。修改归档条目的正文前，需要先恢复发布。

知识管理员也可在**知识后台（`/knowledge-admin`）**的已归档列表中恢复条目。**彻底删除**与归档不同：确认时需要勾选声明，会永久删除条目及全部修订，无法恢复。仅让过时资料退出使用时，不要选彻底删除。

知识管理员还可以在**知识后台（`/knowledge-admin`）**的 Agent 草稿队列核对创建者、可用的会话或来源链接，审阅后发布，或者拒绝并归档。“草稿直接拒绝归档”只适用于 Agent 草稿；普通草稿须先发布，才能使用常规归档操作。

## 查看索引健康并发起重建

知识管理员打开**知识后台（`/knowledge-admin`）**，进入**检索索引健康**区：

1. 检查检索模式提示。“仅全文检索(FTS-only)”表示语义检索降级或不可用，不表示全文检索已停用。页面还报告 pgvector 是否可用、嵌入端点是否已配置；部署问题应交给运维处理。
2. 查看各条目的发布状态、已索引修订号、索引状态、分块数量及失败原因。索引状态包括**排队中、索引中、已索引、失败**。将已索引修订号与条目当前修订核对后，再判断最新内容是否已经处理。
3. 对有问题的条目，先阅读失败原因并处理根因，例如替换正文提取失败的文件，再点击**重试**。反复重试不能解决格式不支持或服务不可用的问题。
4. 已发布条目集合需要重新处理时，点击**全量重建索引**。提示中的数量是重新入队的已发布条目数；这是后台任务入队结果，不是重建完成证明。点击**刷新**查看处理结果与剩余失败。

索引失败可能涉及正文提取或嵌入生成，不能仅凭一个失败标记断言全文检索全部不可用。应结合失败原因和实际检索模式判断。
