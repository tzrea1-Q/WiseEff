# 向小泽提问并确认操作

> English: [English](../../user-guide/xiaoze.md)

## 谁可以使用

- 已登录用户（包括访客，`guest`）可以在权限范围内提问。查询参数和知识分别需要 `parameter:view`、`knowledge:view`；读取节点快照需要 `debugging:view`，查看近期日志结论需要 `logs:view`。
- 硬件开发、软件开发、硬件MDE、软件MDE、管理员（`admin`）和平台超级管理员（`platform-admin`）只有具备 `parameter:edit` 和目标项目访问权限，才能批准参数变更建议。创建知识草稿需要 `knowledge:edit`。
- 管理员和平台超级管理员可以访问**审计中心**（`/audit`）和**知识后台**（`/knowledge-admin`）。能打开页面不代表能执行所有操作，服务端仍会逐项检查权限。

小泽只在连接后端的 API 模式中提供，不在模拟体验中提供。它是浮层助手，没有单独的导航页面。角色申请方式见[账号与访问](account-and-access.md)。

## 围绕当前工作提问

1. 打开**参数修改**（`/parameters`），选择项目，再点击**打开小泽**。也可以从**知识库**（`/knowledge`）提问；其中的**问知识库(小泽)**入口会打开小泽并填入固定的预设提示，不会带入你的检索问题。发送前请替换或补充为实际问题。
2. 说明想了解什么，并写清参数或业务对象。页面会提供路由、页面标识、你的角色、适用时的项目标识，以及简短的页面上下文摘要。这不是完整的屏幕读取：不要假定小泽能看到每一行表格、当前选中项或未保存的编辑内容，请在问题中明确对象。
3. 要求小泽给出依据，而不只是答案。它可以通过只读工具查询项目参数数量和待处理请求，搜索已配置的参数并解释定义和值，也可以检索、阅读已发布知识。它还可以获取**节点调试**（`/node-debugging`）相关的已存储节点快照，以及**智能分析**（`/logs`）中的近期日志结论。
4. 使用结论前核对来源。只读查询不需要审批卡片，但仍受服务端权限检查约束。项目工具要求项目访问权限，知识检索限定在本组织内。当前节点快照和近期日志结论返回的是组织范围内的记录，不能假定结果只属于当前所选项目。

小泽读取已有日志结论，不会代替日志分析工作流运行分析。已存储的节点快照也不能证明刚刚读取过设备。当前注册的写入工具只用于提交参数变更和创建知识草稿，不会写入设备节点。设备操作和日志处理分别见[设备调试](device-debugging.md)与[日志分析](log-analysis.md)。

## 核对参数建议，再决定是否批准

在**参数修改**（`/parameters`）中，请小泽为明确的参数准备变更。建议不等于已生效：修改业务数据的工具会先暂停，等待人工明确批准。对话里的一句话不能代替审批。

出现**确认参数变更**卡片后：

1. 核对**项目**和**参数**标识，确认是你要修改的对象。
2. 检查**目标值**、提供时显示的**变更理由**，以及引用链接。对象不对或理由不清楚时，不要批准。
3. 如需调整，编辑**目标值**。系统会将修改后的值连同建议的其余内容提交，服务端按参数的源码格式校验，并重新检查授权。卡片不支持编辑项目、参数或变更理由；这些内容有误时，应拒绝并要求小泽重新准备。
4. 点击**批准**执行建议，或点击**拒绝**阻止这次建议写入。可以填写可选的**拒绝理由**，告诉小泽需要修正什么。
5. 查看执行结果。批准不等于执行成功，权限、校验或执行过程仍可能失败。成功的参数操作会创建变更请求，不会立即写设备或合入。具备相应权限时，可在**变更审阅**（`/parameter-review`）中追踪；完整提交与审阅路径见[参数管理指南](parameter-management.md)。

## 将有用的回答整理成知识草稿

请小泽根据会话准备一篇新知识草稿。在**确认创建知识草稿**卡片中，检查**草稿标题**、**标签**、提供时显示的**来源分析**和**内容预览**。预览可能被截短，不一定包含完整正文。当前卡片只支持编辑标题；正文、标签或来源有误时，应拒绝并要求重新准备。

核对后再点击**批准**。批准只会新建草稿，不会改写已有知识条目，也不会自动发布。到**知识库**（`/knowledge`）检查生成的条目。草稿和归档条目不会被小泽的知识检索读取，草稿须经人工发布后才能进入检索。具备权限的管理员还可以在**知识后台**（`/knowledge-admin`）的**Agent 草稿发布队列**中审阅。发布是另一次独立的人工决定。

小泽读取的近期日志结论包含分析来源和降级原因，主要结论的摘要也会提示降级。如果批准创建的草稿引用了降级的来源日志分析，平台会在正文顶部自动加入来源提示，标明「降级分析 · 规则回退」或「降级分析 · 提前收敛」及其限制。正文开头已有完全相同的提示时不会重复添加。发布前请在生成的草稿中核对提示与来源证据；提示仍可编辑，批准创建和发布仍是两次独立的人工决定。

## 区分 AI 内容和引用依据

- 助手回答标为**小泽**，聊天界面提示「AI 可能会出错，重要决策请自行核实」。生成的解释不是权威工程结论。
- 回答带有引用时，下方会显示**来源**。依据来自工具返回的参数记录、节点快照、日志结论或已发布知识等。有链接的来源可以打开原始对象，没有链接的来源只显示标签。没有来源的回答，即使语气肯定，也不能直接当作有证据支持的结论。
- 知识条目详情会显示修订版本及**来源**，区分**人工**与 **Agent**。管理员的 Agent 草稿队列还显示创建人、会话来源，以及存在时的关联分析。发布前应结合正文核对这些信息；Agent 标记说明内容来源，不保证质量。

## 了解谁批准、谁执行

审批链记录人工决定，并关联会话、工具调用和审批记录。你批准后，小泽执行的操作仍以 Agent 发起的操作记入审计，不会被改标为用户直接操作。具备权限的管理员可到**审计中心**（`/audit`）调查。

审批和来源追溯的维护文档见[Agent 审批状态持久化决策](../../adr/0024-agent-approval-state-is-db-backed.md)。其他工作流见[用户指南首页](README.md)。
