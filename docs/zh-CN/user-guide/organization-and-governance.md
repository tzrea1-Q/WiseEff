# 组织管理与业务治理

> English: [English](../../user-guide/organization-and-governance.md)

## 谁可以操作

管理员（`admin`）和平台超级管理员（`platform-admin`）按自身权限维护所属组织并使用业务后台。成员与组织名称的修改需要 `users:manage`；审计中心和反馈管理需要 `admin:access`。各业务后台还会校验本业务的权限与资源范围；平台控制台仅限平台超级管理员。已启用并登录的用户，包括访客，都可以提交产品反馈并查看自己的反馈。

其它角色包括访客、硬件开发、软件开发、硬件MDE 和软件MDE。注册和密码操作请参阅[账号与访问](account-and-access.md)，不要把管理后台当作申请访问权限的入口。

组织代表一家公司或一个部署客户，不是硬件部、软件部等部门。组织管理维护你所属的组织，不提供创建、列举或切换组织的功能；成为组织成员也不等于获得项目权限。平台超级管理员不能因此任意访问其它组织的业务数据。注册申请队列是一个明确的例外：平台超级管理员可以处理跨组织的待审批申请。

## 维护组织档案与成员

1. 打开「组织管理」（`/organization`），核对组织编号与显示名称。需要改名时，编辑「显示名称」并选择「保存名称」。改变的是名称，不是组织身份或你的所属关系。
2. 进入「人员管理」（`/organization/members`）的「账号库」。搜索或筛选成员，先确认角色与启用、停用状态，再执行修改。旧的 `/user-permissions` 书签也会进入人员管理区域。
3. 创建本地账号时，选择「添加用户」，填写姓名、用户名、职位、初始密码与确认密码，并选择合适的角色。按照表单提示完成校验，确认创建成功后再交付账号。
4. 调整角色或启用状态时，使用成员行内的控件，核对确认信息后提交。停用后账号不能登录；重新启用恢复的是现有角色对应的访问能力，不会额外授予权限。

管理员不能授予或撤销平台超级管理员角色，也不能通过受保护的行内控件管理平台超级管理员账号。这类操作只能由平台超级管理员执行。你不能停用或注销当前登录账号，也不能移除自己最后的管理员能力。

只需要停止访问时，优先考虑停用，而不是注销。注销用户不可撤销：账号的角色、凭据、会话和临时数据会清除；保留的业务与审计历史仍在，相关位置会显示已删除用户的归属信息。操作前务必阅读确认说明。重置密码请参阅[重置成员的本地密码](account-and-access.md#重置成员的本地密码)。

## 审批 MDE 注册申请

在「人员管理」（`/organization/members`）中切换到「注册申请」。核对申请人的账号标识、当前角色以及申请的硬件MDE 或软件MDE 角色，再选择「通过」或「拒绝」。

- 通过后，系统授予申请的 MDE 角色并启用账号。申请人可以使用原有凭据登录。
- 拒绝会记录审批结果，但不会启用账号或授予申请角色。待审批的 MDE 账号被拒绝后仍处于停用状态。
- 管理员处理本组织的申请。平台超级管理员的队列可能包含其它组织的申请。当前队列显示账号与角色信息，不显示组织名称；处理跨组织申请前，应另行核实申请人的所属组织。

该队列处理的是自助注册申请；已有成员的角色调整在「账号库」中完成。申请已被处理或操作失败时，刷新并检查实际结果，不要把点击「通过」当作审批成功。

## 查清谁在何时改了什么、为什么改

打开「审计中心」（`/audit`），查询本组织的参数、日志、调试、Agent 和用户管理事件。这里不是跨组织审计浏览器。

1. 按操作、操作人或事件类型搜索，再结合模块、项目、时间范围和严重度缩小范围。项目筛选在有项目列表时显示。
2. 选中事件，核对操作人、发生时间、操作及对象。事件提供了变更前后值或原因时，再查看这些信息；并不是每条事件都有原因或值差异。
3. 需要对象编号或 Trace ID 时展开技术详情。事件带有 Trace 时，可以查看关联事件，或按该 Trace 筛选，沿同一次关联操作核对记录。
4. 用「加载更多」继续查看匹配项。在 API 模式下，「导出 CSV」导出匹配记录，最多 2,000 条；较大的调查应进一步缩小筛选范围。CSV 包含事件标识与摘要字段，并不包含详情弹窗中的所有信息或原因。

没有查到记录，并不证明操作从未发生；先检查筛选、加载错误及可用历史范围。保留策略请参阅[审计保留](../security/audit-retention.md)。

## 选对后台，维护业务模块

组织管理与组织范围内的参数资产治理是两回事。先进入资产所属的业务后台，再通过「审计中心」（`/audit`）核对各后台已记录的变更。

| 要做的事 | 导航名称与路由 | 由这里负责的内容 |
| --- | --- | --- |
| 维护参数资产 | 「参数后台」（`/parameter-admin`）；「参数定义管理」（`/parameter-admin/specs`）；「模块管理」（`/parameter-admin/modules`）；「项目运营」（`/parameter-admin/projects`） | 治理定义、整理参数模块树、管理项目。导入与项目工作流参阅[参数管理](parameter-management.md)。 |
| 维护调试资产 | 「调试后台」（`/debugging-admin`）；其中的「节点调试」（`/debugging-admin/nodes`） | 默认区域维护重载配置；节点区域维护逻辑节点、协议绑定及调试模块树。参阅[设备调试](device-debugging.md)。 |
| 治理日志分析 | 「日志后台」（`/log-admin`） | 检查分析记录和质量，维护业务域。业务域治理需要 `logs:admin-domains`。参阅[日志分析](log-analysis.md)。 |
| 治理知识内容 | 「知识后台」（`/knowledge-admin`） | 审阅 Agent 草稿，管理归档条目，检查索引健康。管理操作需要知识管理能力。参阅[知识库](knowledge.md)。 |
| 操作平台所有的资产 | 「平台控制台」（`/platform-console`） | 平台超级管理员使用的独立页面，不是组织切换器，也不替代上述业务后台。 |

维护参数模块时，打开「模块管理」（`/parameter-admin/modules`），展开树并确认父模块，再新增根模块或子模块。通过可用的编辑、重命名与移动控件调整层级；已注册的规范目录主体应通过其归属控件检查，不要把分类调整当作创建新定义。删除不是通用清理手段：普通模块只要还有子模块、参数引用或规范目录归属，就不能删除。遇到「解散驱动组」时，应单独阅读警告；它与删除空分类不是同一种操作。

维护调试模块时，进入「调试后台」的「节点调试」（`/debugging-admin/nodes`），打开「模块管理」，新增根模块或子模块、重命名，或移动到允许的父模块。只有没有子模块、也没有节点引用的模块才能删除。参数与调试各自维护模块树，修改一棵树不会同步整理另一棵树。

## 附上截图，提交产品反馈

「问题反馈」是在当前路由打开的弹窗，不是独立页面。可以从导航中的「问题反馈」打开；带页脚的页面也提供这个入口。请先进入发生问题的页面，使反馈记录的页面标题与路径对应实际场景。

1. 选择「体验问题」「数据问题」「导出/提交异常」或「功能建议」，填写操作步骤、预期结果及实际表现。问题描述不能为空。
2. 如有需要，把剪贴板中的截图粘贴到表单，检查预览并移除无关图片。服务接受 PNG、JPEG 和 WebP，最多五张，单张不超过 5 MiB，总计不超过 15 MiB。粘贴前先去掉密钥及无关个人信息。
3. 选择「提交反馈」并等待成功提示。「保存草稿」保留尚未完成的报告，不等于提交；有未提交修改时关闭弹窗，会询问是否放弃这些修改。
4. 在同一弹窗打开「我的反馈」，继续编辑草稿，或查看已提交记录、附件、状态及公开处理进展。管理员的内部备注不会出现在提交人的视图中。

管理员在「反馈管理」（`/feedback-admin`）按状态、类型筛选或搜索，检查描述与截图并记录进展。可以开始处理、填写解决结论与公开说明后标记已解决，或确认关闭；已解决的反馈可以填写原因重新打开，已关闭的反馈则只读。更新时注意区分公开进展与内部备注。产品反馈与日志分析结果的质量评价不是同一个工作流。
