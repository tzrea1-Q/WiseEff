# Controlled original DTS preprocessing

> Chinese: [受控原始 DTS 预处理](../zh-CN/developer/dts-preprocessing.md)

`dts-cpp/v1` retains original UTF-8 members, paths, BOM/line endings and source versions. It runs real GNU CPP for literal `#include`, supplied headers, object/function value macros and conditional compilation. Native `/include/` remains supported; when CPP is enabled it must occupy its own line. Relative paths may traverse to another directory inside the manifest. Header members are build inputs, never independent device-tree declarations.

The fixed contract uses the official GCC 14.2.0 Linux/amd64 image pinned in `tools/dts-toolchain/versions.json`, C17, UTF-8 input/output, `C` locale, `-nostdinc`, `-undef` and `__DTS__=1`. Search paths and external `NAME=value` macros come only from strict declared build inputs; source-defined macros remain in original members. Request bodies cannot select executables, images or compiler arguments. The server adapts standalone native includes and DTS hash-prefixed property lines for C preprocessing; these transformations are part of this versioned contract, not changes to stored source.

Preflight checks every supplied member, including inactive branches. Computed includes, token-pasting, external files, `#line`/numeric line controls, `include_next`, pragmas/embedding, environment probes and volatile time/path macros are rejected. There are no host include directories or network inputs. Unsupported declarations retain a repairable draft and block publication/application.

The shared draft editor exposes collapsed build settings for relative include directories and at most 32 external `NAME=value` macros. These settings participate in draft CAS, publication digests, frozen versions, history and exports. Resource manifests retain their own declarations. Dependency directories are mapped under each fixed resource mount; differing values for one macro and ambiguous literal include bindings are refused. `ConfigRevision.declaredBuildInputs` retains the private project declaration separately from effective global search paths and the preprocessing receipt; composition never infers local ownership from merged macros. Older revisions have no external defines, and migration preserves their recorded local include paths. Malformed or inconsistent historical declarations block with a repairable diagnostic.

Preflight also returns the literal dependency closure reachable from the actual entry and overlays, including inactive conditional branches. Fixed snapshots must match this declared closure and exact upstream bytes. Active semantic source files remain separate: inactive files create no occurrences or effects. Removing the project entry include still refuses the write.

Each operation uses an owned private temporary manifest mounted read-only into a container with no network, persistent logs, capabilities or privilege escalation, eight PIDs, 512 MiB memory including swap allowance, a five-second CPU hard limit and a five-second native wall deadline. Each asynchronous client has at most ten seconds and bounded stdout/stderr capture; the complete operation has a thirty-second deadline. Source limits are 128 files, 2 MiB per member and 16 MiB total; include nesting is 16; each full original/semantic expansion is at most 32 MiB and 100,000 statements. Failure reaps only the operation's unique container. One active CPP operation per API process keeps native work bounded; another operation receives a retryable busy conflict while health and unrelated API requests remain responsive. Additional API processes remain an operator-controlled capacity choice.

The adapter compares directives-only active original declarations with expanded declarations and verifies original lines and exact UTF-16 CST ranges against authorized frozen members. Compiler line markers alone do not prove a writable span. Declaration-generating macros and one original occurrence expanding differently in several contexts are blocked. Supported value macros use explicit `expanded-v1` provenance: exact original invocation text remains in occurrences, while semantic AST and a `dts-cpp/v1` input/output/tool receipt are derived evidence. Exact source proof reruns the frozen contract. The browser and server share the same bounded pure DTS value parser, including integer expressions and native path references; original literal layouts remain lossless. Legacy plain-DTS proof is unchanged. Structured writes through the legacy affine writer are refused for CPP configurations with an original-source editor/local-override correction; whole-source review uses the complete manifest.

Shared publication, project resolution/ingest, source review, Catalog value synchronization, native compilation, original-source export/reimport and project-copy initialization consume this contract. Resource publication does not publish Catalog definitions or change any project. Original sources are authoritative exports; generated output is never their replacement.

For local or CI setup, start a Docker Engine that enforces memory, swap and PID limits, then run `npm run dts:toolchain:bootstrap` and `npm run dts:toolchain:check -- --required`. Only bootstrap pulls the pinned image; requests use `--pull=never`. The API must have an explicitly provisioned usable sandbox. A deployed container without that capability reports CPP unavailable and continues supporting plain DTS. This feature does not authorize mounting a Docker socket into an existing deployment or changing production infrastructure.

Native syntax/provenance checks live in `server/modules/dts/cppSources.test.ts`; actual API-role publication and whole-source review, PostgreSQL exact proof, and native DTB equivalence have their existing owner tests. Browser verification extends `shared-dtsi-publication.acceptance.spec.ts`. Tool availability or an older run is not current acceptance.
