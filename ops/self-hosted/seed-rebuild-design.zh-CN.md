# 示例参数受审重建操作入口

> English: [English](seed-rebuild-design.md)

状态：已实现，供本地评审；目标服务器执行及浏览器验收仍待完成。用户已授权 Atlas、Aurora、Nebula 的旧参数归档及新版 DTS/JSON 种子重建；保留其他项目、用户、角色、后台节点和非参数对象。不新增 schema，不绕过发布策略，不回退旧安装器，不启用尚不可用的 P11–P16。

现场已经接管 `crel_acme_1`，旧语义绑定有数据，新版绑定为空。应用升级按设计不执行 seed。本入口组合现有发布、归档、来源物化及处置 owner，不直接写 Catalog 指针或绑定。

## 入口及职责

- `scripts/seed-rebuild.ts`：计划、状态、目录准备/发布、重建和验证。计划固定数据库、组织、代码/种子摘要、三项目身份、Catalog 和原始库存；读取真实用户权限，不构造测试身份，不默认授权或轮换密码。
- `scripts/lib/seedCatalogPublication.ts`：先准备受审厂商后继，再准备 ConfigurationSchema 后继；复用候选授权及 manager 队列，保留不可变摘要确认与独立审核规则，以实际激活回执确认完成。
- `ops/self-hosted/scripts/seed-rebuild.sh`：复用 Compose、升级存储和操作锁，完成实际静默、新恢复点验证、仅 manager 的受控发布、完成及恢复。部分失败保持停止写入，记录原始服务/队列/冻结状态。
- 重建复用归档、物化和处置 owner。先记录阶段再写入；可能发生部分写入且不具备幂等保证的阶段进入整套恢复，不盲目重试。完成态重放必须验证实时结果。
- 已封存计划保留原始运行中清单。切换期间使用另一份不可变保留基线，仅在隔离及备份验证完成后、任何 Catalog 候选创建前采集；其摘要绑定 run ID、计划及恢复清单。这样保留计划到停服之间的正常会话和 Bridge 更新，同时不排除后续校验中的任何字段。缺少或篡改证据会阻断发布和重建；已存在的基线只能验证，不能静默替换。
- 私有运行目录仅保存脱敏计划、日志和受保护备份引用；普通状态不输出 DSN、凭据、源码内容或归档对象引用。

## 威胁与验收矩阵

| 场景 | 预期及验证责任 |
| --- | --- |
| 只读计划 | 无数据库/对象写入，无权限授予，输出范围和阻断项；CLI/PG 测试。 |
| 用户、组织、项目或编码不符 | 在发布/归档/来源写入前拒绝；真实数据库权限测试。 |
| 数据库、代码、种子、Catalog 或计划摘要漂移 | 在依赖写入前拒绝；计划及 PG 测试。 |
| 同作者高风险审核、缺少能力 | 原发布策略拒绝，无绕过参数或自动授权；发布测试。 |
| 候选重试、manager 排队、回执不符 | 复用精确身份或拒绝差异，实际激活前不 seed；发布测试。 |
| 写者仍运行、队列未排空、冻结失败、锁冲突 | 不报告恢复点成功、不重建；部分进入维护后保持停止；包装器测试及隔离栈彩排。 |
| 计划到停服之间的更新 / 维护后的更新 | 采集并保留停服时的完整记录，不修改已确认计划。后续数据漂移、维护证据缺失或不匹配均在依赖写入前拒绝；真实 PG 回归及包装器顺序测试。 |
| 备份缺失、篡改或实例不符 | 拒绝重建/恢复，沿用存储身份及校验和验证；包装器测试及彩排。 |
| 归档截断、对象缺失或摘要不符 | 处置旧数据前拒绝；现有 owner 及真实对象/PG 测试。 |
| 已接管且有旧数据的成功路径 | 经 manager 发布、归档保留、受审 DTS/JSON 身份集合正确、其他项目及非参数指纹不变；集成彩排。 |
| 阶段中断 | 精确幂等续跑或明确 recovery-required，无重复事实；测试及恢复彩排。 |
| 物化后处置 | 只移除捕获的旧残留，保留后继；不 DROP、不跨项目；owner 及集成测试。 |
| 完成及重复执行 | 验证实际绑定、来源 pin、归档及非参数保留后才恢复流量；不能仅凭日志宣称成功。 |
| 目标执行 | 本地候选通过评审后由用户在原生 amd64 服务器执行；逐步给出命令及检查点；本地结果不替代目标证据。 |

交付前要求独立实现及 Spec 评审。既有封印程序单独验收，本入口不把 #853 或 S1/S2 标为完成。

## 证据边界

定向 PostgreSQL 测试使用专用本地测试数据库下的临时数据库，覆盖已有数据的接管基线、真实非超级用户 publication-manager LOGIN、原生作者/审核权限和激活回执、全部 372 个受审身份、当前源文件字节、旧参数归档/处置、后台节点及共享对象保留，并拒绝中断阶段或被改动的日志。纯脚本及模拟包装器测试单独计为本地证据。

独立本地 Compose 运行 `seed-final-v5-20260921` 已通过计划、新恢复点验证与维护、两次原生 manager 发布、精确 372 绑定重建、重复验证及整套恢复。恢复后 Catalog 回到 `crel_acme_1`，规范绑定和新增种子/归档记录均为零，服务恢复健康、队列恢复运行、发布恢复未冻结状态。另一轮存储 owner 彩排验证了修改后的 PostgreSQL、MinIO 卷及 Redis AOF 哨兵值恢复。最后一处仅涉及摘要记录的队列状态修正由聚焦包装器测试覆盖；原生彩排使用其前一版控制脚本。

彩排镜像在已有本地镜像上覆盖经过审核的运行源码，并使用合成 provider 配置，不能作为全新原生发布镜像构建、真实 LLM 调用或部署服务器证据。本轮选择恢复而非 `finish`；正常完成路径由聚焦包装器检查覆盖，并复用已验证的服务恢复函数。[人工操作指引](seed-rebuild.zh-CN.md)保留真实服务器与浏览器验收步骤。
