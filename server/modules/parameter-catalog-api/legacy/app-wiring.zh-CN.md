# 应用组合根中的 Catalog 退役路由

英文：[English](app-wiring.md)

候选代码原本就无条件注册 #677 的退役适配器。冻结的
`parameterCatalogLegacyWriteRouteIds` 包含结构变更和已退役的管理 GET
操作。这些路径应返回 410，不执行旧服务，携带 release 或重放请求头也不例外。

原先 `buildWiseEffRouter` 先注册旧参数模块，再注册退役适配器。HTTP
路由器在 method/path 完全相同时选择先注册的处理器，因此适配器自身测试
返回 410，不代表真实应用不会继续调用旧处理器。

组合根现在在注册旧参数模块时过滤这些精确 method/path，让既有 Catalog
适配器成为它们唯一的路由所有者。全局路由优先级、非退役业务操作和有界
旧读路径保持原状。过滤依据来自既有冻结清单，没有新增第二套退役名单。

## 范围与威胁用例

| 场景 | 必需观察 |
| --- | --- |
| 旧模块再次注册退役路径 | 只有一个处理器；HTTP 410；不执行旧服务或数据库操作 |
| 退役管理 GET 或变更请求 | 返回既有类型化 410 和后继路径请求头 |
| 重放／release 请求头或请求体自报管理员 | 两次请求均为 410，不执行变更 |
| 非退役业务路径或有界旧读 | 保留原注册与行为 |
| 候选缺少适用启动批准 | 路由过滤不产生启动权限；仍由独立运行准入负责 |

`server/app.catalogRetirement.test.ts` 通过本机真实 HTTP 调用
`createWiseEffServer`，遍历冻结退役路径。数据库边界使用拒绝访问的合成
实现；最初反例经过真实旧服务调用链检测旧源访问。这证明应用路由组合，
不证明真实数据库权限、启动、P13 撤权或完整 controller。旧源部署的
checkout 和镜像不受本变更影响。

父协调者负责 startup/controller 集成及独立 Standards/Spec 审查。
本变更没有新增迁移、grant、环境开关或批准。

## 文档影响
